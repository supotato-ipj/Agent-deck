# 桌面分区通过 Win32 直接操控真实桌面图标，而非壁纸内自绘 UI

需求原本包含"用户自行添加常用应用到桌面固定栏位"，直觉做法是在壁纸里画出可点击的分区和应用格。但实测确认 **Wallpaper Engine 的网页壁纸在桌面上收不到点击**：图标层 `SHELLDLL_DefView` 覆盖整个屏幕并吃掉点击，WE 官方文档也没有任何桌面鼠标输入设置；TERMINAL 02 里那个"点时间框"只在 WE 编辑器预览中生效，落到桌面就失效。因此分区改为由数据服务通过 explorer 的 `SysListView32` 发送 `LVM_SETITEMPOSITION` 来重排**真实**图标——分区的存在只体现为图标坐标的约定，壁纸侧仅保留一行极小的方位标签。

## Considered Options

- **壁纸内自绘可点击分区** — 平台硬限制，不可行（非取舍，是被否决的事实）。
- **独立置顶 GUI 窗口承载交互** — 需要多养一个常驻进程，与"能力全放数据服务、与壁纸共存亡"的部署决策相悖。
- **把文档移动到桌面下的归档子文件夹** — 会打断硬编码的绝对路径、网盘同步与用户肌肉记忆，且不可逆；被明确否决，分区只动坐标、绝不动磁盘文件。

## Consequences

- **不需要任何 HTTP 写端点**，因此不会在本地引入无鉴权的写操作通道（数据服务目前是 GET-only 且带 `Access-Control-Allow-Origin: *`）。这一条是本决策最大的附带收益。
- 依赖 explorer 内部控件结构与消息协议，属于未文档化接口，Windows 更新可能使其失效；因此布局快照与一键还原是必备兜底，而非可选功能。
- 图标位置按显示名存储、不区分来源，因此对公共桌面（`C:\Users\Public\Desktop`）的 .lnk 做重排会在本机全用户范围生效。
- 壁纸层几乎不改动，QODER DECK 于 2026-09-23 定稿的形态不受威胁。
