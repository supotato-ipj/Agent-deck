# 控制面的本地安全边界与凭证：协作性边界、通道绑定身份、会话与持久凭证

控制面第一次引入“谁在调”，但不能把回环监听、ACL 或本地加密夸大为对同用户恶意进程的强制隔离。拍板：安全目标是可靠区分合法调用方、减少误调用并让受控路径可审计；身份只由主进程从通道绑定推导，后端使用会话凭证，外部客户端使用命名持久凭证，敏感用户操作使用一次性手势授权。写操作的完成、超时、吊销与崩溃恢复统一遵循不重放原则。

## 本地安全边界与启用策略

- **护栏是协作性的，不是强制性的。** 控制面防误调用、防客户端间混用凭证并提供审计；不承诺抵抗已控制同一 Windows 用户会话的恶意进程。该进程可以直接改 `userData`、插件根或审计文件，也可能读取本地 bearer token。ACL 与本地加密至多减少事故，不能把这种情况变成可靠隔离。
- 这不取消对**投放档**的防范。插件包是面板主动装载的不可信代码，仍须受身份裁剪与闸门约束；“同用户进程出局”不能被用来合理化插件包自称内核档。
- **外部档默认关闭。** 创建外部凭证不自动启用；用户在内核 UI 显式打开外部档开关后才接受外部连接。
- **按需监听。** 只有外部档已启用，或至少一个管理型后端会话存活时，才绑定 ADR-0016 选定的固定回环 URL；两者都不存在时 MCP 宿主可存活但不监听。外部档后来启用仍用同一 URL，不引入动态端口或第二监听面。

## 身份与凭证

### 身份只能来自通道绑定

主进程必须从自己登记的通道绑定推导信任档与调用方身份，绝不采信参数里的 `trust`、`pluginId` 或其他自报身份。

- MCP 侧由 bearer 绑定到一个后端会话或一个外部客户端。
- 插件侧采用**每包独立、由主进程登记的执行上下文**，绑定插件 id 与来源根；内置根与投放根分别得到内核档与投放档。frame 或独立 webContents 是可选实现形态，同 JS 环境里的自报身份不是有效替代。
- 内核 UI 保持不执行插件的可信上下文。仅以 `senderFrame`、模块 URL 或渲染层 facade 名称判断身份都不够，主进程必须持有绑定关系。

### 后端会话凭证

“后端会话凭证”取代容易误解的“一次性凭证”：它在会话内可多次调用，不是单请求凭证。每个管理型后端会话独立签发高熵随机 bearer，只存内存，随会话存亡。

显式结束会话、后端进程退出、面板重启或 MCP 宿主重拉均使其失效；对话窗收起不失效，不另设空闲超时。宿主重拉后原会话只能聊天，必须新建管理型会话才能取得新凭证。会话内不轮换，新会话一律发新凭证。

这里的“后端会话”不是 ADR-0016 排除的 MCP 协议会话：MCP 请求仍无状态，bearer 只是把每次请求关联回面板已有的后端会话。

### 外部客户端凭证

外部档按客户端签发**命名凭证**，不共用一把全局钥匙。用户在内核 UI 创建，完整 token 只显示一次；面板只保存哈希、客户端名与生命周期元数据。凭证跨面板重启有效，客户端静态 MCP 配置无需随面板重启改写。

轮换与吊销由用户手动执行，旧凭证立即失效；不做自动轮换。创建、启用、轮换和吊销是彼此独立的用户动作，其中创建凭证不隐含打开外部档。

## 用户操作与会话级授权

- **用户手势授权**：`proposals/approve`、`rollback/restore`、信任根配置写与外部档开关等敏感操作，必须由可信内核 UI 的真实输入触发。主进程据输入签发短时、一次性、内存态 grant，绑定调用上下文、方法与目标对象，消费时原子作废。MCP 与其他执行上下文没有这条路径。
- 不强制在这些已明确点击的操作之后再弹原生确认框。手势授权表达“这次受信 UI 操作附带输入”，不被包装成对同用户恶意进程的证明。
- **会话级授权**只给后端档，粒度为“后端会话 × 档×客体格”。它只免除该格后续写的逐次确认，不扩张开放级、不覆盖其他客体或方法级例外；随后端会话凭证失效，用户可提前撤销，绝不落盘。请求、获批与撤销均进审计。

## 存储、审计与恢复

- 外部凭证元数据、护栏配置、审计、提案与回滚点集中放入 `userData` 下的专用控制面存储；ADR-0016 已决定的端口仍留在 `app/config.json`。目录 ACL 限当前用户只是基础卫生，不增加签名链、DPAPI 或“防篡改存储”等越出威胁模型的承诺。
- 审计采用追加式 JSONL、按日滚动、保留 90 天。写操作先记带操作 id 的意图，再追加成功、失败或补偿结果；重启发现只有意图没有结局时标为**结果未知**，绝不补记成功。只读仍按 ADR-0010 的档×方法×段集×时间窗聚合。
- 未过期提案及其状态持久化，重启后继续可见。批准采用**至多一次**语义：先原子标记一次性授权已消费，再执行写；执行中崩溃留下结果未知，重启不自动重放。用户依据审计与现状重新发起，不由面板猜测补偿。
- **凭证与授权不属于回滚点客体。** 还原历史护栏配置不能复活旧外部凭证、后端会话凭证、会话级授权或已消费提案。吊销只能前进，用户需要新钥匙时重新创建，而不是还原旧钥匙。

## 写完成、超时与失效

- 写成功必须表示应持久化的数据已落盘，且该次调用承诺的副作用已落地；任一步失败按原子性契约补偿并返回失败。不得以“内存状态已翻转”冒充成功。
- 每次写带操作 id。客户端超时只结束本次等待，不自动取消已开始的写，也不允许自动重试；最终结局进入审计，调用方可查询自己档位的记录。内部无法确认结局时明确记为结果未知。
- 凭证轮换、吊销或后端会话结束只阻止新调用，不粗暴中断已认证的在途写。在途操作仍执行到成功或补偿完成并记审计，结果未知时不重放。

## Considered Options

- **把 ACL、DPAPI 或命名管道包装成同用户强制隔离**——同一用户的进程仍可使用该用户身份读取或改写，承诺强于机制本身。
- **外部档常开、所有客户端共享长期 token**——开机自启会无声打开入口，共享凭证无法单独吊销，审计也无法区分客户端。
- **由调用方传信任档或插件 id**——现状同文档执行的任意投放包都能自称内核档，参数不是凭证。
- **只给同 renderer 加 nonce 或 renderer 自绘确认**——同页插件能读取或抢用 nonce，也能直接绕过浮层调用 bridge；它证明不了用户意图。
- **后端凭证持久化或真的一次调用即作废**——前者把后端档漏成长期外部档，后者让正常会话无法连续读写。
- **外部凭证自动轮换**——客户端使用静态 URL 与 header，自动轮换只会制造断连；手动轮换配合命名凭证更可审计。
- **敏感用户操作一律再弹原生确认框**——在执行上下文已隔离后，它把一次明确点击重复成两次确认，增加噪声而不补足既定威胁模型。
- **客户端超时即失败并重试、重启重放在途写或未执行完的提案**——都可能把同一变更执行两遍；审计中的结果未知比伪造成功或猜测补偿更安全。
- **回滚点连凭证一起恢复**——会复活用户已经明确吊销的钥匙，破坏吊销语义。

## Consequences

- 《agent 写入插件包的契约与 capability 授予》必须继承“身份来自主进程通道绑定”的前提，并据此收紧 `plugin-config` 命名空间。只扩张 manifest capability、保留同文档自报 id，不能兑现投放档裁剪。
- 《对话窗驱动后端 agent 的接入协议》必须把会话结束与进程退出通知给凭证登记处；宿主重拉后的既有会话降级为只能聊天，不偷偷续用旧凭证。
- ADR-0010 的“仅内核档且必须由用户交互触发”由可信 UI 与用户手势授权共同兑现；回滚点不再被理解为覆盖全部安全状态的全量备份。
- ADR-0016 的宿主仍随面板生命周期托管，但监听是按需的；无可用身份时宿主存活不等于端口必须打开。
- 结果未知是控制面的一等结局，不是成功或失败的别名。任何自动恢复都不得把它转成隐式重试。

## 补记（票 #74 决完后，2026-10-24）

Consequences 中《对话窗驱动后端 agent 的接入协议》的两项要求已由 ADR-0018 履行：会话结束与进程退出通知凭证登记处；宿主重拉后原会话只能聊天，恢复管理必须新建管理型会话。

## 补记（票 #73 决完后，2026-10-25）

Consequences 中《agent 写入插件包的契约与 capability 授予》的要求已由 ADR-0019 履行：

- 插件包进入**每包独立、由主进程登记的执行上下文**；`tier` 与 `pluginId` 只从通道绑定推导，`host.view`（快照段）、`host.config`（私有状态）与 invoke 窄面都在这个绑定上裁剪，manifest 与调用参数不能自报。
- 投放型插件包拿**投放窄面**（4 段 + `taskbar/get-state` + 自身 `host.config`）；内核档插件包拿**受信内部桥**（母集减 `app/quit`）。`plugin-config` 的命名空间隔离由约定式收成强制式。
- 写完成语义按本 ADR 兑现：install/update 的「成功」是有界激活成功；失败回滚，`result_unknown` 不重放；每次写带 `opId`，闸门/提案/审计沿用本 ADR。
