# 验收提示条由电池控制器自绘，驻留顶部安全带

真机验收电池全程驱动真机键鼠与桌面断言，用户并行操作会污染结果，而 accept-guard 的占用 toast 瞬时即逝，撑不起「全程提醒」的诉求（工单86）。四块电池的控制器（与面板同仓库的 Electron 进程，`src/main/index.ts` 的 `--accept*` 分发点）统一自绘一条**验收提示条**：琥珀药丸驻留屏幕上中部 y<48 DIP 的安全带——面板全部内容与电池断言取样区均自 y≥48 起，条又全程在场，任何前后帧像素差分在条所占区域恒定相消；条随控制器进程生灭自清，app.exit、崩溃、强杀全路径零残留，无需清理逻辑。

## Considered Options

- **面板自呈现**（面板读「测试中」标记自绘）— 面板是被测物，且被电池反复杀重启（`stopPanel` → 重拉），条会随之闪烁消失；条画在面板自己的窗里还会闯进面板自身的断言。
- **guard 侧系统 toast 增强** — toast 瞬时自动消失，达不到「驻留直到结束」；guard 在仓库外（`.accept-guard`），改动跨仓。
- **独立进程承载提示条** — 电池暴毙时条会残留桌面，需额外的回收/超时兜底；控制器自绘的窗口随进程一起死，天然自清。

## Consequences

- 条是纯提示（advisory）：点击穿透、不抢焦点、**不锁输入**——锁输入会拦死电池自己的 SendInput 合成键鼠。用户不守提示导致的个别断言失败属固有风险，不作防护。
- 三条不干扰硬约束（点击穿透、不抢焦点、顶部安全带内静态无动画）落在 `accept/lib/hint-bar.js` 头注，改动提示条前必读。
- 条会出现在验收存证截图顶部，可兼作该轮电池运行时段的旁证。
- `GLOSSARY.md` 入库「验收电池 / 验收提示条」两词条（补上「电池」一词久未立词条的缺口）。
