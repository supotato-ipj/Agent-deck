# 任务栏策略开关的开放级与闸门：内核插件层拆出策略子行、策略写免串行、外部逐次确认

ADR-0010 的「内核插件层」一行把任务栏的接管程度建模成「禁用 / 启用」两个动作，并在补记「缺口一」里登记了 `taskbar/set-maximize-retract` 与同族三个开关：它担心逐次确认会把自动收栏的高频态打成噪声，把这一格怎么开留给后续。本 ADR 收口这一格。开工先校正那条噪声前提：**`taskbar/set-maximize-retract` 是持久策略开关，不是收栏态写**——真正的 `BarMode` 由前台窗口状态自动裁决、自动施加，控制面里没有任何写态方法，所以自动收栏/还原根本不经过确认闸门。真正的决策点不是「怎样给高频态降噪」，而是「这条策略写属于哪一格、开给哪些档、要不要串行与会话级授权」。拍板：四条持久策略开关（收栏、系统按钮显隐、硬件摘要勾选、托盘溢出档位）并案，从「内核插件层」拆出**独立的「内核插件·策略」子行**；内核 `W`、后端 `W✓` 逐次确认（可请求本格会话级授权）、外部 `W✓` 逐次确认（无会话级）、投放 `—`、自主管理只能提案；四条都是同步配置写，**不挂串行化**。`set-enabled` 与 `system-action` 留在「内核插件·生命周期」行，格位、串行与原子性不变。

## 前提校正

- **`taskbar/set-maximize-retract` 是策略写，不是态写。** 契约形状是 `{ enabled: boolean }` → `TaskbarState`；内核把布尔值写进 `config.json` 的 `taskbar.maximizeRetract`（同段其他字段一并持久化），同值幂等空转，变化时 `persist()` → 提交内存态 → 回推 `taskbar/changed`。真正的 `BarMode`（`visible` / `maximize-retract` / `fullscreen-yield`）由 `resolveBarMode` 按前台窗口状态裁决、`planBarTransition` 判动作、`applyBarMode` 施加；`window.ts` 只向任务栏渲染窗发 `taskbar/bar-mode` 内核事件，桥接方法表里没有写态方法。
- **`taskbar/get-state` 只给策略字段。** 它的响应是 `TaskbarState`，含 `enabled` / `hiddenButtons` / `metrics` / `trayOverflowLimit` / `maximizeRetract` 等策略与运行态字段，**没有**当前 `BarMode`；`taskbar/bar-mode` 不是控制面事件。
- **收栏策略同时管最大化收栏与分屏收栏。** 两者共用 `taskbar.maximizeRetract`（工单269；GLOSSARY「分屏收栏」）。关掉它不是只关最大化一种，而是把两种自动收栏一起关掉；它仍是可逆、可审计、可回滚的持久偏好，不是一次性系统动作。
- **同族三条与 `set-enabled` 不同类。** `set-button-hidden` / `set-metrics` / `set-tray-overflow-limit` 与收栏一样，都是同步落盘 config 任务栏段的持久偏好，无在途异步副作用；`set-enabled` 则有任务栏窗建/销、托盘宿主交还、串行化与原子性契约（ADR-0010）。四法并案的是**策略开关**，不是接管生命周期。
- **ADR-0010 缺口一的噪声担心是范畴错误。** 自动收栏每拍都可能发生，但它不经过控制面；进入闸门的只有用户/agent 显式发出的策略切换。策略切换是低频动作，不会因为收栏频繁而变多。真正需要避免的是「把 `set-enabled` 与四条策略写放在同一格，再给后端会话级授权」——一次批准会覆盖关任务栏；本 ADR 用子行拆开这一风险。

## 决策

### 1. 可管理对象只到策略，不到收栏态

控制面只暴露四条持久策略的读写（写侧见下），**不新增写态方法**，`taskbar/get-state` 继续只给 `TaskbarState` 的策略字段，不给当前 `BarMode`。

理由：收栏态是前台窗口事实的派生视图，不是可独立持有的状态。写态会与 `resolveBarMode` / `applyBarMode` 争夺同一状态，制造第二个事实源；要支持「强制收栏」就必须另定策略与态谁优先、窗口事实变化时谁覆盖谁，那是一张新票，不在本 map。管理只需要策略，态是自动效果。

读侧边界：策略字段随 `taskbar/get-state` 对已有该读面的档可读；当前 `BarMode` 不进控制面。非内核档 `taskbar/get-state` 的 `title` / `tooltip` / `exe` / `path` 脱敏仍归 #282，本 ADR 不顺手改读面。ADR-0020 的 `taskbar/autonomy-state` 已含 `maximizeRetract` 等策略字段、不含 `mode`，与本决策一致。

### 2. 四法并案，`set-enabled` 单列

并案的四条策略开关：

- `taskbar/set-maximize-retract`（收栏策略）
- `taskbar/set-button-hidden`（开始组系统按钮显隐）
- `taskbar/set-metrics`（硬件摘要勾选）
- `taskbar/set-tray-overflow-limit`（托盘溢出档位）

`taskbar/set-enabled` 与 `taskbar/system-action` 留在「内核插件·生命周期」行。并案不等于同格：四法共享一个**策略子行**，`set-enabled` 不进入该子行。

### 3. 新增「内核插件·策略」子行

宽严矩阵修订如下（只增子行，不改原生命周期行的格位）：

| 客体 | 内核 | 后端 | 外部 | 投放 | 自主管理 |
| --- | --- | --- | --- | --- | --- |
| **内核插件·策略（四开关）** | W | W✓ 确（可请求本格会话级授权） | W✓ 确（无会话级） | — | 提案 |
| **内核插件·生命周期（`set-enabled` / `system-action`）** | W（`set-enabled` 串 + 原子性；`system-action` 仅内核） | W✓ 确 + 串（`system-action` —） | W✓ 确 + 串（`system-action` —） | — | 提案 |

- 记号沿用 ADR-0010：`W` = 可写免闸门，`W✓` = 可写带确认闸门，`确` = 确认闸门，`串` = 在途串行化；回滚点与审计对所有档所有写默认生效，不逐格标。本表只列写；投放档的 `taskbar/get-state` 读面按 ADR-0019 另计。
- **策略子行是「内核插件层」的一个面，不是第五类客体。** 它把原行的生命周期写与策略写分开，目的是让「档 × 客体」的会话级授权有独立的作用域；矩阵的宽严顺序与单调性不变。
- 投放档 `—`：四法不在 ADR-0019 的投放窄面内（投放包只有 `taskbar/get-state`、`host.view` 四段与自身 `host.config`）。自主管理只能提案（ADR-0010 / ADR-0020）；提案批准是用户手势，落地写记自主管理档并引用提案 id。

### 4. 闸门形态：逐次确认是默认，后端可请求本格会话级

- 内核档：`W`，免确认；回滚点与审计照常。
- 后端档：`W✓`，逐次确认；后端**可以请求本格的会话级授权**（ADR-0010 的既有机制）。请求本身是一次带闸门的写、进审计、可被用户的收紧设置关掉；授权随会话存亡、绝不落盘。授权只覆盖请求时该子行的现有四法，**未来新增到策略子行的方法不自动继承**，需要重新请求。用户收紧该格即失效。
- 外部档：`W✓`，逐次确认；**不给会话级授权**（ADR-0010：外部是常驻端点、凭证长期有效，「会话」概念不成立）。
- 确认闸门超时即拒绝，并按 ADR-0010 / ADR-0017 转入提案队列。
- **同值幂等写不触发确认闸门**：值未变化时是空转，不写盘、不建回滚点；控制面在进入闸门前比较当前策略值。闸门打开期间值被别的调用方改到目标值，最终写仍空转，不建回滚点。
- 本族不引入新的闸门类型；噪声问题由「自动态不入闸门 + 策略写低频 + 后端可会话级」三条共同解决，不需要「只对策略写挂闸门」的额外规则——默认就只有策略写会到闸门。

### 5. 策略写免串行，生命周期写照旧串行

四条策略写都是同步配置写：`persist()` 写盘、提交内存态、回推事件在同一调用栈完成，没有在途异步副作用；ADR-0010 的串行化是为「关窗 → 开窗」这类有完成信号的异步副作用准备的，对策略写是空转。故策略子行**不挂串行化**。

并发的确认闸门不改变这一判断：闸门是异步的，但批准后的写本身同步、由主进程顺序执行；控制面按 ADR-0010 的「读-改-写」纪律取当前 config 再落盘，不会用陈旧快照覆盖别的字段。生命周期行的 `set-enabled` 仍按 ADR-0010 保留串行化与原子性契约。

### 6. 审计与回滚点

策略子行的每条实际写都进审计（谁 / 何时 / 方法 / 参数摘要 / 闸门结果 / 成功失败），并在写前建回滚点；内核档也不例外（ADR-0010：回滚点与审计不因「调用者知情」而免除）。只有用户能触发回滚点的还原，调用方不能自己回滚。同值空转不建回滚点。四条写都必须遵守 ADR-0010 的「不得整份回写」：读当前 config、只改本字段、再写回。

### 7. 生命周期行不动

`set-enabled` 保持 ADR-0010 的 `W` / `W✓ 确 + 串` 格位与原子性契约；`system-action` 保持仅内核档。本 ADR 不重开 #72 对 `set-enabled` 的档位判断，也不重开该行的会话级授权规则；本 ADR 只保证策略写不再与它共用一个会话级授权作用域。

## 为什么这样切

- **为什么不把四法全归 `config·观感与检索`。** 四条虽然都落 config，但收栏与系统按钮显隐改的是任务栏作为系统 UI 的接管行为，不只是面板观感；若归入观感列，后端档会拿到免确认写。把系统 UI 行为当观感配置，是这一刀最危险的地方。硬件摘要与托盘溢出单独看更接近观感，但四法同族、写入形状相同、频率极低，先同格能让矩阵保持一族一格；若将来证据表明这两法需要更松，只能按「方法级例外只往严」的规则另开票，不在本 ADR 预支。
- **为什么不再留在原「内核插件层」一行。** 原行同时含 `set-enabled`。ADR-0010 的会话级授权按「档 × 客体」格生效；若四法与 `set-enabled` 同格，后端一次会话级批准就会覆盖关任务栏——这正是本票要避免的放大。拆子行把策略写与生命周期写的作用域分开；顺带把「串行化」从策略行拿掉，因为对同步配置写是空转。
- **为什么不只开内核档。** charting 时 Q3 已把可管理边界定到最宽，ADR-0010 也已把内核插件层对后端/外部开成 `W✓`。只开内核会悄悄收窄已定的边界；策略写可逆、可审计、可回滚，后端会话又是用户发起的，保留 `W✓` 是既能管又有闸门的形态。
- **为什么不新增写态方法。** 见决策 1：态是自动驱动的派生视图，写态会制造第二个事实源。若未来确有「强制收栏」需求，应另开票定义它与前台窗口事实的优先级、失败与恢复语义，不能搭本票的便车。
- **为什么不把 `BarMode` 加进 `taskbar/get-state`。** 读态会暴露「当前前台是否最大化/全屏」这一窗口事实，并给 1 Hz 轮询增加一个高频变化字段；管理策略不需要它。ADR-0020 的自主管理读面也只到策略字段。若未来某个只读场景确实需要，另开票按 #282 的脱敏口径设计。
- **为什么不给外部会话级授权。** ADR-0010 已定：外部是常驻端点、凭证长期有效，没有「会话」边界；给会话级等于永久授权。外部仍可逐次确认，策略写频率低，不会成为噪声源。

## Considered Options

- **四法全归 `config·观感与检索`**：后端 `W`、外部 `W✓`，最开放；但把系统 UI 接管行为降成观感，且与 Q3 的「内核插件面」语义冲突。否决。
- **四法留在原「内核插件层」一行**：不新增子行；后端/外部 `W✓ + 串`。最接近 ADR-0010 原文，但会话级授权会覆盖 `set-enabled`，且串行对同步配置写空转。否决。
- **只给内核档**：把 `set-maximize-retract` 收成内核专属。违背 charting 的最宽边界，且策略写本身可逆可审计；否决。
- **新增强制收栏/还原的写态方法**：把 `BarMode` 变成可写对象。会与自动裁决争同一状态，需要另定优先级与恢复语义；不在本 map，需另开票。否决。
- **把 `BarMode` 作为只读字段加进 `taskbar/get-state`**：便于 agent 验证效果，但暴露前台窗口事实并增加高频读面；管理策略不需要。否决。
- **按影响再拆两格（收栏/按钮显隐 vs 摘要/溢出）**：更精确，但把同族写入切成两条矩阵行，增加维护与授权作用域；本票先同格，保留将来按证据收紧的余地。否决。
- **让策略子行的会话级授权覆盖生命周期行**：等于一次批准后后端可在本会话内反复关任务栏；正是拆子行要避免的放大。否决。

## Consequences

- **ADR-0010**：新增补记（2026-10-25 #276 决完后）登记策略子行与格位；缺口一的噪声前提就地更正为「策略写 vs 自动态」。原矩阵表不改写，保留历史决策。
- **GLOSSARY**：新增**任务栏策略开关**与**收栏策略**两词条；**内核插件**词条补一句「控制面把写入面拆成生命周期与策略两个子行」，明确策略写不改接管生命周期。
- **#277（14 个 `taskbar/*` 方法）**：本 ADR 给它的不是「策略写 vs 视图态」二分，而是「策略写 vs 自动驱动的态（非控制面对象）」这一更窄的结论。那 14 个方法不是策略开关，不能借本子行开口；它们应按 ADR-0010 的「面板外的世界」判据单独裁。
- **#282**：本 ADR 只动写侧归类，不动 `taskbar/get-state` 的非内核档脱敏；`title` / `tooltip` / `exe` / `path` 仍由 #282 收口。
- **实施输入**（控制面尚未落代码）：新增策略子行的投影与格位、四条策略写的确认闸门/会话级授权/回滚点/审计、同值空转短路、读-改-写配置；这些是后续实施票的输入，本 ADR 不产代码。`set-enabled` 的生命周期实现、串行与原子性仍按 ADR-0010 既有口径。
- **验证**：纯决策与词汇变更，无运行时代码；`git diff --check` 与 PR CI 通过即可，不跑真机验收电池（没有运行时行为可验）。

## 补记（2026-10-25，#282 决完后）

ADR-0023 定非内核档 `taskbar/get-state` 的读形状，策略字段全保留：

- `TaskbarStateManaged` 与 `TaskbarStateDisplay` 均保留 `enabled` / `hiddenButtons` / `metrics` / `trayOverflowLimit` / `maximizeRetract`；`BarMode` 仍不进任何形状。
- 四条策略写的响应也按调用方档位的形状返回，不再返回完整 `TaskbarState`。
- 策略子行的写侧格位、闸门与审计不变；本补记不重开 #276。
