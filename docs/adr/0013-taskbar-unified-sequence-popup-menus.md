# 任务栏交互模型定案：应用组统一序列与鼠标位竖排弹窗（逆转 z 序排序、空带居中、条带内横排三项既有设计）

背景：spec154 落地的任务栏有三处刻意设计，经用户真机使用反馈（2026-10-14 grill 定案）判负：

1. **仅运行段按 z-order 快照排序**——编排 1Hz 一拍，运行图标按当拍 GetTopWindow 链首见序落位（apps-plan.ts），切一次窗口焦点图标就重排，用户位次预期完全不稳定；
2. **应用组在「开始组右缘 ~ 右组左缘」空带内居中**（appsPillLeft 以空带中点减半宽），随两侧内容浮动、非屏幕绝对中心，用户感知为「没有居中」；
3. **全部右键菜单横排渲染进 `#pill-start`**——条带窗仅 64px 高、竖排浮层出不了窗矩形，属几何受限的折衷（taskbar.html 有注释在案），但「右键应用组图标、功能项出现在屏幕左端开始组里」违反桌面右键菜单心智，用户判为不可用。

另有第四项：拖拽换位代码已接线但仅覆盖手钉↔手钉等四条路径，用户真机实测「拖动后弹回」（根因另行取证修复，不属本 ADR 决策面）。

## 决策（2026-10-14，用户确认）

1. **应用组改为一条统一图标序列**（词汇表「应用组序列」）：默认规则——手钉按钉入先后居前（老左新右；存储继续用有序清单，无时间戳字段，存量零迁移）；未钉运行应用按应用合一图标（多窗并入单图标），新面孔追加序列最右，有窗即在位不动、全部窗口关闭即消失；钉入＝运行图标原地转正 / 推荐组来源落最后一个手钉之后（精确化注记，2026-10-14 评审轮补：两段模型下手钉段恒在运行段左，「运行图标原地转正」对运行段非首位图标不可达——实作口径为**钉入一律落手钉段末位**，安静栏面即视觉原地、其余条目相对序保持；此即 US9「落最后一个手钉之后」在两段模型下的可达语义，49 电池 P18 臂C 断言同口径）；**拖拽自由覆盖全序列**（手钉拖位持久于栏布局存储，运行图标拖位随面板会话）。
2. **应用组中心对齐屏幕水平中心线**，不随开始组/推荐组/右组宽度漂移；超宽夹取与溢出「⋯」兜底维持。
3. **任务栏全部右键菜单与多窗选窗迁入「任务栏弹窗菜单」**：独立浮层窗承载（沿用托盘溢出菜单 DECK-TRAY-OVERFLOW 的浮层窗通路），锚鼠标位置弹出、工作区夹取、点外即收；条目集维持现状；pill 内横排菜单整体退役——菜单不住在条带窗里，64px 条带高从此不约束菜单形态。
4. **推荐组独立容器化**（独立漂浮 pill，居开始组与应用组之间）与**托盘自带菜单被条带遮挡的修复**（回放右键期间条带让位方向，机理取证中）随本批工单落地。

**备选否决**：

- **按窗口逐窗图标**——用户初选后经边界场景压测自纠为按应用合并：同应用多任务挤占格位、与 Win11 心智不符；
- **顺序纯时间推导、禁用拖拽**——顺序完全可预期，但牺牲用户手工编排自由；用户实测拖拽缺失后明确要求 Win11 式全量自由拖拽，「固定」的敌人是 z 序漂移，不是人手；
- **菜单留在条带窗内竖排**——出窗矩形，几何不可行；**维持横排**——即用户判负的现状。

## Consequences

- 栏布局存储：pinned 有序清单语义不变；新增统一序列落位规则与运行位会话态（不落盘）。
- **跨段拖拽为段边界钳取**（2026-10-14 评审轮补记的裁决，防后人当 bug 修）：手钉源条目落运行图标上 → 钳取至手钉段末位；未钉运行源条目落手钉图标身份上 → 钳取至运行段首位；段内拖拽全自由（手钉拖位落盘、运行拖位会话态）。钳取与决策 1 的两段模型（US2「运行恒在钉右」序不变式）自洽——落点越段时向本段邻接边界收敛正是该不变式的落点保护，不作废拖拽、不静默吞掉；dragDrop 契约已在 `app/src/shared/contract.ts`（TaskbarDragDrop 注）书面化。
- 验收电池按章法（ADR-0011、docs/agents/battery-governance.md）动断言：49-taskbar P15（推荐位界内断言随推荐组独立 pill 重定界）、P16③⑥/P17①②③（菜单 DOM 锚点从 `#pill-start .tb-menu-item` 迁至浮层窗）、55-right-group P7 臂6/7（档位菜单行迁浮层窗）；事件面 notify 名与 `taskbar-geometry` 字段保持则事件断言可存活；renderer 单测钉的推荐菜单三行中文 label 不变（条目集维持现状）。
- 工单拆分另走 to-tickets；本 ADR 只锁模型。
