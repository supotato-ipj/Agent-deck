# 性能与响应性重整：维持 Electron，建立性能预算与韧性基线

2026-11-14 用户以三症状发起性能 grill（空闲 CPU 长期 6%+、开机进桌面后超 10 分钟面板才出现、点任务栏图标 5-6 分钟无反馈），并提议换语言全量重写。经三路只读调研（现场采样、代码消耗源盘点、启动/点击链路与日志取证）定谳：**三症状全部是我方代码写法问题，不是 Electron 框架固有开销**，重写不解决问题。本 ADR 记录维持技术栈的复议结论、性能预算（SLO）制度、韧性基线与重写重议门槛；不改变 ADR-0004 与 ADR-0029 的任何决定。

## 决策

- **维持 Electron + cordis + koffi 技术栈**，就性能与响应性抱怨复议维持 ADR-0029。定谳证据：
  1. 空闲 CPU 实测 7.38%（16 核整机口径、仅面板进程组，2026-11-14 采样），大头是周期轮询与子进程 spawn——虚拟桌面对账每秒 spawn 2 个注册表读取子进程、GPU 采样每 5 秒一次外部命令、桌面遮罩守望每 150ms 全窗 z 序走查、任务栏三态裁决每 250ms 全窗枚举（仓库审计实测外推约 1.6% 整机）、数据面每秒全量五工具扫描（含每秒重开 SQLite）——全部可改事件驱动或降频；
  2. 开机慢实测（日志取证：登录→面板出现 3 分 21 秒与 7 分 34 秒两轮、热机重启约 7 秒；同机其它自启程序登录同拍即就绪）：面板页面加载排在启动装配链最尾，链上存在无界等待（桌面工作区启动无超时）与每次启动必跑的同步 PowerShell（上界 20 秒）；
  3. 点击无反馈：开机窗口期内二次拉起处理是空占位、托盘图标未建，任何点击被静默吞掉；面板崩溃无自动重拉、冻结在生产无取证无恢复路径，且原生任务栏处于接管隐藏态——面板瘫痪即整个任务栏壳瘫痪、无退路。
  换任何语言照此写法同样患病；结构性地板（全屏透明窗合成 + 多进程引擎基线，估算 1.5~3%）换 Tauri/Avalonia 同样要付，只有纯原生可能更低，而全量重写已被 ADR-0029 三因素否决。
- **建立性能预算（SLO）三线**：① CPU——任务管理器进程页面板进程组、整机百分比、空闲态长期均值：≤1% 目标、≤2% 可接受（余量须实测归因到结构性成本）；② 开机——进桌面到面板出现 ≤60 秒；③ 点击——≤1 秒图标视觉反馈且启动命令已发出，普通应用 ≤3 秒出窗；重型工具（VS Code 系 / CLI agent）自身启动耗时不在面板账上。
- **事件驱动优先于轮询**：能订阅系统通知的不轮询；必须轮询的按用户拍板的新鲜度降级（硬件摘要 30 秒、会话扫描 3~5 秒、时钟去秒）；交互热区轮询暂不动，待实测归因后再裁。
- **韧性基线三件套**：**拉回**（外层守卫对面板异常退出按退避自动重拉、重拉次数有界；冻结只记账并告警一次，自动杀拉暂缓——待常驻事件日志跑出冻结真实形态后再立决策）；**逃生口**（冻结失能档与崩溃路径触发原生任务栏自动还原，面板恢复后重新接管；另设手动热键作保险丝）；**常驻事件日志**（生产默认开启，关键事件滚动落盘、轮转有界、不含敏感内容——修复「冻结在生产不可观测」的取证盲区，此盲区同时卡住 2026-11-14 并行的 Win 开始菜单双 bug 诊断线）。
- **启动重排为骨架屏形态**：面板窗与任务栏条带尽早创建、尽早可交互，桌面组件以轻量占位先行、数据到达后原位填充；启动链上一切外部等待（shell/COM/注册表/外部命令）必须有显式上界；自启项维护不得同步阻塞启动链。
- **重写重议门槛**：仅当「原地优化压不进 ≤2% 可接受线」且「实测归因证明余下瓶颈为框架固有开销」两条同时成立，才重启 ADR-0029 的迁移讨论；性能痛点本身不构成 ADR-0029 既定再评估门槛（跨平台需求 / 四 spike）的触发条件。

## Considered Options

- **换语言全量重写（Rust/Tauri、C#/Avalonia 等）**——否决：三症状归因于我方代码而非框架；重写 = 插件平台与验收体系重造（ADR-0029 三因素维持成立），工期以月计；结构性地板在新框架同样存在。
- **只做 CPU 优化、不动韧性与启动排序**——否决：点击被吞与开机等待是韧性与排序问题，光降 CPU 治不了；不修取证盲区则复发无从诊断。
- **先跑 ADR-0029 四 spike 再议**——不触发：无跨平台需求，性能痛点不在再评估门槛内；spike 结论与本 ADR 的 SLO 实测归因是两套证据，不互相代位。

## Consequences

- 词汇入册：骨架屏、拉回、逃生口、常驻事件日志（GLOSSARY）；「看门狗」为已退役词条不复用，拉回/逃生口行文勿再称看门狗、守卫、守护。
- 立法路径：性能与响应性重整 spec（骨架屏 / 拉回 / 逃生口 / 常驻事件日志 / 轮询事件化 / 图标修复拆票执行）；诊断轮先实锤开机链「卡在哪一秒」、explorer 图标回归点与工具图标慢启动归因（面板侧 vs 工具自身）。
- 若优化终局停在 1%~2% 且归因为结构性成本：按门槛记账为达标（可接受线），不自动触发重写；连 2% 都压不进才重议。
- 冻结自动杀拉为暂缓项：待常驻事件日志积累冻结形态数据后另立决策，本 ADR 不预设结论。
