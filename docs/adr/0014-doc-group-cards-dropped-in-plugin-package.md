# 桌面文档的呈现交给投放型插件包，内核侧只增一处插件私有状态存储

背景：桌面文档文件由内核文档区承载，按**类别**（folders/office/pdf/image/archive/other 六类）聚成几列图标——3 个 .docx 与 2 个 .xlsx 同挤一列，组粒度与用户的直觉（「Word 的」「Excel 的」）对不上；分区几何只由 config.json 决定、不可拖，形式是一列而不是一个框。而要让桌面出现一张「每类一卡、框内图标网格、顺次居中」的**组卡**，桌面组件这条路上没有用户可用的扩展位：内置卡片的几何写死在面板样式表里按 DOM id 匹配，无布局表、无 per-card 配置 schema，用户既不能新增也不能删除（工单166）。

## 决策

**(a) 交付为投放型插件包**，而非内置卡片包。插件装载时隐藏内核文档区、卸载时还原；插件源码作为仓库内可安装单元维护（另有一道拷进用户插件根的安装步骤），运行态仍是投放型——删目录即完全撤回。

**(b) 全程只改归属，不动磁盘。** 组卡是归属概念不是目录；「解散一张卡」等于删掉卡定义、让卡内文件按扩展名回落固有分组，文件本身原地不动。

**(c) 内核只新增一对桥接方法** `plugin-config/get|set`，按插件 id 命名空间落盘，沿用项目既有的合并校验与原子写。内核的 `docGroupOf`、`GROUP_ORDER`、`DesktopLayout`、选区状态机、文档区渲染一律不动。

## 备选否决

- **做成内置插件包**（进 `app/src/renderer/cards/`）——几何能进面板样式表、图标链路能直调内核，但它随面板发版、不能单独删，用户改一次就得等一次发布。投放型把「要不要这个卡片」完全绑在目录在不在。
- **插件配置存 `localStorage`**（`deck-plugin` 协议注册带 standard+secure，本就跑在一个正规 origin 上，技术上可行）——零内核改动，但它不是配置文件：随 userData 被清就一起丢，无备份无原子写，与 `config.json`/`layout.json` 那套持久化惯例不是一个量级。选了内核那对契约正是为了拿到与项目同级的持久化强度。
- **顺手立住控制面**（按 GLOSSARY 里已有的信任档/开放级/护栏三词条实现最小判定）——那套设计覆盖四类客体与两维矩阵，为一个 KV 搭半套骨架只会留下「只有最窄一档有实现」的残缺结构，正是 ADR-0010 自陈的困境。「投放档只能写自己命名空间」写成该契约的固有约束即可，不需要信任档机制来表达。
- **粘贴时真的把文件搬进组卡对应的文件夹**——与 Q2 的「不动磁盘」冲突，且一旦卡变成真实目录，「解散」就变成一次不可逆的批量移动。
- **右键菜单复用上下文菜单插件**——该插件在本机当前处于停用状态（内置六包停用其五），依赖它等于交付一个开箱即坏的功能，且它可被用户随时关掉。改为插件自绘菜单外壳，开层期间铺一张全屏 `.card` 让面板在该范围内不穿透，菜单外点击收起与 Esc 由插件自己接管。

## Consequences

- **框选、内核选区、跨分区选区存续、桌面项拖拽摆位、经内核的批量启动全部失去。** 这些在内核里是 `main.ts` 的模块私有状态，既不 export 也不挂 window，桥接契约表里也没有对应方法——插件无接口可接，只能自建等价物（双击启动、单击高亮、卡内框选）。内核的 `desktop-selected/-toggled/-cleared` 存证族对插件不可见。
- **`plugin-config` 的命名空间隔离是约定式、不是强制式。** `invoke` 是全表透传的单一 handler，主进程无从分辨调用方，`id` 由调用方自证。这与面板现有的零护栏状态一致（同 ADR-0010 所述，控制面在代码里尚不存在），不得让人误以为有强制力。
- **插件的「不写磁盘」靠自律，无机制强制。** 同一张透传表里还有删除、重命名、粘贴、退出等写操作。
- 隐藏文档区后，窗口左上角残留一块 **24×24 的文档区热区**。**成因（工单187 真机轮订正，原记录有误）**：不是「热区计算对零尺寸矩形仍返回带状结果」——零尺寸矩形在 `main.ts:1575` 被 `filter((r) => r.w > 0 && r.h > 0)` 明确滤掉了；真正的成因是 `main.ts:1564` 走 `zoneHotzoneRectOf(docZone)` 时，**零尺寸矩形先被 `ZONE_HOTZONE_PAD_PX=24` 四向外扩撑成 24×24 的带**，再由 hasItems 判据（`zone.querySelector('.ditem') !== null`，看的是 DOM 子节点而非可见性）放行，于是这条带非零、躲过那道 filter，一直活到插件卸载。真机实测：插件装载期间最新热区申报里 `doc-zone` 恰为 `(0,0,24,24)`，同时文档区 `display:none`、矩形 0×0、`.ditem` 子节点 21 个（子节点个数随桌面夹具在场面数浮动，要紧的是它**非零**；工单187 验收段 P179 存证）。
- **对该残留的处置：记录并接受，不消除**（工单187 定案）。理由：① 消除它必须改内核共享几何——`zone-hotzone.ts` 的同一份 `zoneHotzoneRect` 同时供 `declareHotZones` 与 body 级 `zoneAtPoint` 使用，改「分区非空」判据会连带改掉**所有**分区的框选起笔带与穿透让渡带宽，回归面远超本决策；② 本决策 (c) 已把内核改动圈定为「只增一对 plugin-config 方法」，为一个 24×24 的角做越界改动与该边界自相矛盾；③ 代价有界且只在插件在装期间存在——删插件目录即完全撤回，内核文档区原样还原、该带随之退场（工单187 验收段 P179B 存证）。该行为由工单187 的真机段钉死：带的位置与尺寸随 `ZONE_HOTZONE_PAD_PX` 走，常量一改即红。
- 自绘菜单外壳重复实现了内核已有的菜单外点击收起与 Esc 处置；换来的是不依赖任何其他插件的启停状态。
- **「空组不占卡」这条纪律自工单187 起只对固有扩展组卡成立；空的自定义卡留在屏上（0 格）。** 原来的口径是两层同一条纪律，而那条纪律本是为**规则生成**的组设的：桌面上此刻没有文件的类型不出卡，免得糊屏（spec166 用户故事 #7）。自定义卡不在其列——它是用户亲手建的持久对象，定义存在插件私有状态里、面板重启后原样回来，可它一旦空掉就退场的话，屏上就再没有 `EDIT TYPES`（把类型勾回来）与 `DISSOLVE`（解散这张卡）这两条出路：造一张什么类型都没勾的卡、或在 `EDIT TYPES` 里把勾全取消，皆可走到这一步，而**用户界面上不可恢复**（definition 还在盘上，卡却不见了）。这条不变量的落点是 `ownership.js buildCards` 的自定义层一处条件（`if (bucket)` 而非 `if (bucket && bucket.length)`），连带后果：一张 0 格卡也占一个卡 id，故唯一化兜底对它同样生效；卡面如实写「卡名 · 0」，`+N` 徽标在 0 格卡上不渲染（`remainingCountOf(0) === 0`，无「+0」）；卡内多选、卡内框选、ENTER 那几处读几何的交互在 0 格卡上有几何可读，不抛。**临时卡维持原样**（空则不出卡）——临时卡是粘贴的产物，不属于本次裁决的范围。
- **`NEW GROUP` 自工单187 起在固有扩展组卡上也可见（恒可见），而 `EDIT TYPES` / `DISSOLVE` 仍只在手改得动的卡上。** 工单185 当初给 `NEW GROUP` 挂 `visibleWhen`（归宿自定义卡或临时卡）的理由是「规则生成的卡不该被手改」，但 `NEW GROUP` 建的是**另一张新卡**、压根不动脚下那张，那条理由管不着它；而那一挂的直接后果是**用户建不出第一张自定义卡**：全新安装时屏上一张自定义卡都没有、全是固有卡，唯一那条路只剩「先粘贴一张临时卡，再从它上面 `NEW GROUP`」。反过来看，`EDIT TYPES` 与 `DISSOLVE` 在固有卡上依旧没有意义（固有卡由扩展名规则算出，没有定义可勾、没有定义可删），故这两行的 `visibleWhen` 一个字没动——**本裁决只放开一行，不放宽另两行**。
- 若日后 `plugin-config` 需要备份、更高等级的原子性或跨插件共享，升级为完整的控制面客体——那应是四类客体都有落点之后的一次整体动作，不是本决策的延续。
- 关联词条：**扩展组**、**组卡**（新增），**文档组**、**归类**（修正与代码不符的「按扩展名」表述）。spec 见工单 #166。

## 补记（2026-10-25，#73 决完后）

ADR-0019 改变了本决策的两处落点，决策 (b)「不动磁盘」不变：

- **决策 (a) 的「投放型插件包」不再适用于本包，由 ADR-0019 取代**：`doc-group-cards` 迁到随面板发布的第一方包根，成为**内核档插件包**；用户可停用、不能运行期卸载。「删目录即完全撤回」对它不再成立，换来的是 `desktop` 段与 10 个面板外方法可以在内核档宿主面内合法使用。用户根里若还留着旧副本，内核/第一方根先到先得，`plugins/list` 会把它以 `shadowed` 列出、可卸载；它的 `<id>.json` 与迁移后的包共享同一 id，组卡定义随迁不丢。
- **决策 (c) 的 `plugin-config` 访问路径改为 `host.config`**：桥方法 `plugin-config/get|set` 保留为内核档（内核 UI/验收电池），插件包（含迁移后的 `doc-group-cards`）经主进程绑定 id 的 `host.config` 访问自身命名空间；命名空间隔离由约定式收成强制式（ADR-0017 的每包执行上下文）。持久化强度、合并校验、原子写不变；卸载保留 `<id>.json`，组卡定义不随包目录消失。
- **「升级为完整控制面客体」的那次整体动作就是 #73**：结论是 **不升级**——`plugin-config` 不是第五类控制面客体，而是插件私有状态；ADR-0010 的四类客体不变。跨插件共享/备份若将来需要，另开票。
