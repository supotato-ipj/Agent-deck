# 桌面文档的呈现交给投放型插件包，内核侧只增一处插件私有状态存储

背景：桌面文档文件由内核文档区承载，按**类别**（folders/office/pdf/image/archive/other 六类）聚成几列图标——3 个 .docx 与 2 个 .xlsx 同挤一列，组粒度与用户的直觉（「Word 的」「Excel 的」）对不上；分区几何只由 config.json 决定、不可拖，形式是一列而不是一个框。而要让桌面出现一张「每类一卡、框内图标网格、顺次居中」的**组卡**，桌面组件这条路上没有用户可用的扩展位：内置卡片的几何写死在面板样式表里按 DOM id 匹配，无布局表、无 per-card 配置 schema，用户既不能新增也不能删除（工单166）。

## 决策

**(a) 交付为投放型插件包**，而非内置卡片包。插件装载时隐藏内核文档区、卸载时还原；插件源码作为仓库内可安装单元维护（另有一道拷进用户插件根的安装步骤），运行态仍是投放型——删目录即完全撤回。

**(b) 全程只改归属，不动磁盘。** 组卡是归属概念不是目录；「解散一张卡」等于删掉卡定义、让卡内文件按扩展名回落固有分组，文件本身原地不动。

**(c) 内核只新增一对桥接方法** `plugin-config/get|set`，按插件 id 命名空间落盘，沿用项目既有的合并校验与原子写。内核的 `docGroupOf`、`GROUP_ORDER`、`DesktopLayout`、选区状态机、文档区渲染一律不动。

## 备选否决

- **做成内置插件包**（进 `app/src/renderer/cards/`）——几何能进面板样式表、图标链路能直调内核，但它随面板发版、不能单独删，用户改一次就得等一次发布。投放型把「要不要这个卡片」完全绑在目录在不在。
- **插件配置存 `localStorage`**（`deck-plugin` 协议注册带 standard+secure，本就跑在一个正规 origin 上，技术上可行）——零内核改动，但它不是配置文件：随 userData 被清就一起丢，无备份无原子写，与 `config.json`/`layout.json` 那套持久化惯例不是一个量级。选了内核那对契约正是为了拿到与项目同级的持久化强度。
- **顺手立住控制面**（按 GLOSSARY 里已有的信任档/开放级/护栏三词条实现最小判定）——那套设计覆盖四类客体与两维矩阵，为一个 KV 搭半套骨架只会留下「只有最窄一档有实现」的残缺结构，正是 ADR-0010 自陈的困境。「投放档只能写自己命名空间」写成该契约的固有约束即可，不需要信任档机制来表达。
- **粘贴时真的把文件搬进组卡对应的文件夹**——与 Q2 的「不动磁盘」冲突，且一旦卡变成真实目录，「解散」就变成一次不可逆的批量移动。
- **右键菜单复用上下文菜单插件**——该插件在本机当前处于停用状态（内置六包停用其五），依赖它等于交付一个开箱即坏的功能，且它可被用户随时关掉。改为插件自绘菜单外壳，开层期间铺一张全屏 `.card` 让面板在该范围内不穿透，菜单外点击收起与 Esc 由插件自己接管。

## Consequences

- **框选、内核选区、跨分区选区存续、桌面项拖拽摆位、经内核的批量启动全部失去。** 这些在内核里是 `main.ts` 的模块私有状态，既不 export 也不挂 window，桥接契约表里也没有对应方法——插件无接口可接，只能自建等价物（双击启动、单击高亮、卡内框选）。内核的 `desktop-selected/-toggled/-cleared` 存证族对插件不可见。
- **`plugin-config` 的命名空间隔离是约定式、不是强制式。** `invoke` 是全表透传的单一 handler，主进程无从分辨调用方，`id` 由调用方自证。这与面板现有的零护栏状态一致（同 ADR-0010 所述，控制面在代码里尚不存在），不得让人误以为有强制力。
- **插件的「不写磁盘」靠自律，无机制强制。** 同一张透传表里还有删除、重命名、粘贴、退出等写操作。
- 隐藏文档区后，窗口左上角残留一块 **24×24 的文档区热区**（热区计算对零尺寸矩形仍返回带状结果，因其「分区非空」判据看的是 DOM 子节点而非可见性）。位置在所有桌面组件之外，肉眼无感，但该角点击不会落到系统桌面。消除方案（移出屏外 vs 清空子节点）未验，留待真机验收。
- 自绘菜单外壳重复实现了内核已有的菜单外点击收起与 Esc 处置；换来的是不依赖任何其他插件的启停状态。
- 若日后 `plugin-config` 需要备份、更高等级的原子性或跨插件共享，升级为完整的控制面客体——那应是四类客体都有落点之后的一次整体动作，不是本决策的延续。
- 关联词条：**扩展组**、**组卡**（新增），**文档组**、**归类**（修正与代码不符的「按扩展名」表述）。spec 见工单 #166。
