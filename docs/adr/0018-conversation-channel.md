# 对话通道：仅长驻 ACP、会话级管理授权、每会话一进程

对话窗驱动后端 agent 只走一条协议：**ACP v1**。后端候选只有能提供 ACP server 的 kimi（`kimi acp`）、hermes（`hermes-acp`）与 dsh（`dsh --profile acp`）；zcode 的 `app-server` 是私有 ZCode Protocol，Qoder 无无头 agent，Kimi Work 只有 GUI，三者都不进后端选择器——zcode 与 Qoder 仍可作为外部 MCP 客户端连面板（外部档），Kimi Work 两者都不行。只支持长驻 ACP，不提供一次性模式；v1 不开放五工具之外的自定义后端。适配面是**一个 ACP 客户端 + 每后端一份启动描述符**，协议差异由 `initialize` 的能力协商吸收，不在适配器里按工具名分叉。

对话窗建会话默认是**聊天型**：不注入管理通道、不签发**后端会话凭证**。用户显式勾选「允许管理本面板」才建**管理型会话**：面板按需启动 MCP 监听、签发仅内存的会话凭证，经 ACP `session/new` 的 `mcpServers` 把回环 Streamable HTTP 端点与 bearer 交给 agent，再把会话 id 与凭证登记绑定。管理型创建是**全有或全无**：监听绑定失败、后端未声明 HTTP MCP 能力或 `session/new` 失败时不创建，明确报错并提供「以聊天型创建」的显式选择，绝不静默降级。

## 会话形态与选择器

- **长驻 only**：一次性模式下各家没有统一的 MCP 注入、流式、取消与权限路径；#69 已定一次性后端一律按外部档。对话窗只服务能拿后端档的长驻 ACP，不为一次性模式维护第二套事件解析。
- **后端候选**只有 kimi / hermes / dsh。dsh 未安装时在选择器里置灰标「未安装」；zcode、Qoder、Kimi Work 不进后端选择器，它们作为外部客户端的角色写在设置/帮助里。
- **可用性**按可执行文件解析判断；真正的门槛是 ACP `initialize` 握手。握手失败或认证未完成时给出明确错误与补救命令，不把失败伪装成可用。
- **v1 不开放自定义 agent**。描述符表按可扩展写，将来要接五工具之外的 ACP 后端时另开票；不把未经验证的协议变体与认证边界拉进首版。
- **不暴露模型/模式/工具集选择**：使用后端自身配置的默认值；`set_config_option`、`set_mode`、`set_model` 与 kimi 的 `unstable_*` 模型切换不在首版实现。

## 管理授权与凭证

- **默认聊天型，逐会话显式授权**：管理型会话由用户在建会话时勾选；授权不持久化，新会话重新选择。外部档默认关闭的同一信任原则适用于这里。
- **管理型会话 = MCP 注入 + 后端会话凭证**：凭证仅内存、绑定会话，随会话结束、后端进程退出、面板重启或 MCP 宿主重拉失效；对话窗收起不失效（沿用 ADR-0017）。
- **全有或全无**：管理型创建失败时不自动退化成聊天型；「以聊天型创建」必须是用户看到的显式选择。
- **降级语义**：MCP 宿主重拉或后端进程退出后，原会话仍可聊天，但管理通道与凭证已失效；恢复管理必须新建管理型会话并取得新凭证，不自动续用旧凭证。
- **结束会话**：显式结束时先发 `cancel`，给一个短宽限让在途 turn 落定，再终止进程；会话结束与进程退出都通知凭证登记处。面板退出前若有在途 turn，弹一次确认，确认后终止全部会话进程，不留后台孤儿。

## 工作目录与进程

- **工作目录**：每个会话默认在面板 `userData` 下建专用空目录，用户可改成别的项目目录；绝不默认面板安装目录或仓库。ACP `session/new` 的 `cwd` 使用该目录，窗内显示当前工作目录。
- **进程模型**：主进程直接 `spawn` 外部 agent，可执行文件与参数来自后端描述符（不经 shell）；每会话一个进程。Windows 上用 Job Object 设 kill-on-close，面板异常退出也不留孤儿。
- **不自动重启**：会话有状态，崩溃后无法安全重放；进程崩溃时把会话标为中断，由用户决定新建或续接。
- **多会话并发**：允许多个会话同时存在，每个会话独立进程、凭证与工作目录；只要还有一个管理型会话存活，MCP 监听就保持。UI 首版可以只开一个窗口，但架构不设单会话锁。
- **窗口可见性不等于生命周期**：关闭对话窗只是收起；只有显式「结束会话」或面板退出才终止会话。

## ACP 客户端能力面

- **不声明 fs/terminal**：agent 用自己的文件/终端工具在工作目录里干活；面板不替它读写文件、不执行 terminal 命令，避免多一条不受控制面约束的执行路径。若某后端在 `initialize` 后表明必须依赖客户端 fs/terminal 才能工作，则标为不兼容。
- **工具审批必须呈现**：`session/request_permission` 原样展示 agent 给的选项（允许一次 / 始终允许 / 拒绝），绝不自动批准，也不设超时自动拒绝；用户可回应或取消本 turn。它与控制面的**确认闸门**是两条路径，不可互相替代。
- **不注入合成引导 prompt**：连接信息放在 `mcpServers`，能力说明放在 MCP server 的 `instructions` 与工具描述里；对话窗只向用户显示「已连接控制面」提示，不替用户或 agent 起额外 turn。
- **认证不归面板管**：`initialize` 要求认证时，显示后端给出的认证方式与可复制的 CLI 命令（如 `kimi acp --login`、`hermes-acp --setup`）；用户在自己的终端完成后重试。面板不代跑登录、不保存 provider 凭证。

## 记录与续接

- **只存会话元数据**：后端 id、会话 id、工作目录、创建/结束时间、是否管理型、用户命名。消息正文不落盘；后端是会话内容的权威来源。元数据保留期与删除入口留待实施细化，本 ADR 只定不存正文。
- **只续接面板自己创建的会话**：不调 `session/list` 导入或浏览后端历史里的其他会话。
- **续接能力按后端协商**：后端声明 `session/load` 或 `session/resume` 时，面板用同一工作目录重新拉进程并续接；两者都没有时明确显示「内容不可回放」，不伪造历史。续接得到的会话一律是聊天型；要恢复管理必须新建管理型会话。

## Considered Options

- **ACP + zcode 私有适配**——zcode 的 `app-server` 是自有 `hello/clientHello` 握手与约 55 个方法、多种反向请求的私有协议，且对第三方 HTTP MCP 的 origin 信任门控未明；为单个工具再养一套事件/取消/权限模型，收益不抵维护面。zcode 作为外部 MCP 客户端仍可用。
- **保留一次性模式**——一次性模式拿不到后端档（#69），各家输出契约又不同，且 zcode 的一次性模式本机当前跑不通；对话窗会退化成两套语义。若将来只需聊天，另开功能，不混进后端会话。
- **默认管理型**——等于让一次普通对话在用户没看见授权动作时持有快照读与受护栏写；与外部档默认关闭的原则不一致。
- **后端默认 cwd / 面板目录**——agent 的文件工具本来就能绕过控制面；把 cwd 放在面板安装目录只会把误伤面扩大到面板自身。
- **`utilityProcess` 对话宿主 / 每后端一个进程**——前者多一层宿主与孙进程 Job Object 管理，后者把多个会话的故障绑在一起；主进程每会话直接 spawn 更贴合「会话有状态、凭证随会话」的边界。若真机出现主进程解析卡顿，再迁到专用宿主。
- **持久化完整对话 / 浏览后端历史会话**——把敏感正文复制进面板，并把别的工具/项目上下文混进对话窗；后端已是会话内容的权威来源。
- **五工具全列 / 置灰所有不可用项**——选择器是承诺；永远不会成为后端的工具列进去只会制造噪声与重试。
- **自定义 agent**——首版会把未经验证的协议变体、认证与工作目录边界一起拉进来，且一旦显式授权就是后端档；描述符表留扩展位即可。
- **声明 fs/terminal / 自动批准工具权限**——等于给 agent 多一条不受控制面约束的执行路径，或让用户看不见它自己的工具动作；控制面护栏只覆盖经控制面的写，补不了这个洞。
- **合成引导 prompt**——多花一个 turn，并可能被用户误当成自己说的话；MCP 工具描述本身就是契约。
- **单会话锁**——与每会话凭证、续接和多后端切换相冲；资源竞争交给用户控制。
- **退出不确认 / 后台保留 agent**——前者让在途任务静默消失，后者与「面板即宿主、退出即终止」及凭证失效语义冲突。
- **管理创建失败时自动降级 / 照常创建**——会让窗内的「可管理」标识变成谎话。
- **每后端自定义模型/模式控件**——没有统一 ACP 面时，会把各家方言写进 UI；首版用后端自身默认。
- **关闭对话窗即结束会话**——与 ADR-0017 的「对话窗收起不失效」冲突；窗口可见性不是会话生命周期。
- **面板代管认证 / 内嵌 terminal-auth**——本 ADR 已定不声明 terminal 能力；认证属于后端工具自己的状态。
- **导入后端历史会话**——需要为每家不同的 list/load 能力做兼容，并把无关上下文带进对话窗。

## Consequences

- 对话窗是内核 UI，继续只做呈现与输入；管理调用由后端 agent 自己经控制面发起（禁止**代发**）。
- agent 自己的文件/终端工具仍在控制面之外；**工具审批**是用户看见这些动作的唯一位置，ADR-0010 的「护栏是协作性的、不是强制性的」在这里同样成立。
- MCP 监听随管理型会话按需存在；最后一个管理型会话结束且外部档未启用时停止监听（ADR-0017）。管理型会话创建前必须先起监听并铸凭证，`session/new` 失败则回收凭证。
- 对话正文不落盘，面板只保留会话元数据；续接能力取决于后端是否声明 `load/resume`，没有该能力的后端会明确显示内容不可回放。
- 每会话一进程与 Job Object 让面板异常退出也不留孤儿；代价是每会话一份进程启动成本，这是用隔离换来的。
- 后端描述符表是唯一的启动配方来源；将来开放自定义 ACP 后端时不需要改协议适配层，也不需要改信任档模型。
- ACP SDK 的具体选择与版本封闭在适配器内，不改变本 ADR 的协议面；`initialize` 的能力协商是唯一的降级依据。
- zcode、Qoder、Kimi Work 的后端选择器缺席必须在设置/帮助里有角色说明，避免用户把「不能当后端」误读成「面板不支持该工具」。
