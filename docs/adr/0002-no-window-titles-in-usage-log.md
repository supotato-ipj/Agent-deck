# 使用日志只记录进程路径与时间戳，绝不记录窗口标题

自动推荐需要"使用频次"，而本机的现成数据源不够用：`C:\Windows\Prefetch` 是空目录（预取被禁用），UserAssist 只有约 4 条记录。所以数据服务要自建一份使用日志。前台窗口能采集到的最丰富信息是窗口标题，但用户的日常工作是法律案件调研，窗口标题里经常直接带着案号、当事人名称、项目名。我们决定**只落盘进程可执行路径 + 时间戳，不记录窗口标题**。

## Considered Options

- **记录标题但仅本地保存、不外传** — 否决：日志文件本身就是明文，"不外传"不构成边界；且一旦落盘就无法收回。
- **记录标题并做脱敏** — 否决：脱敏规则无法穷举案号与当事人名的形态，漏一条就是泄露；而它换来的信息对"哪个应用常用"这个判断毫无贡献。

## Consequences

- 无法区分同一应用的不同用途（例如说不出哪个 Excel 文档被打开得最多），因此**文档区的排序只能用文件修改时间**，不能复用同一套频次分数。
- 进程路径 → 桌面图标的映射要靠解析 .lnk 的目标路径完成；映射不上的进程仍记录，但不参与推荐排名。
- "使用频次"因此定义为**真启动次数**（进程从无到有）× 时间衰减，而不是前台时长——后者需要标题级别的粒度才有意义。
