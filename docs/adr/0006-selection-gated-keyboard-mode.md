# 桌面项选区以键盘模式门控取得键盘路径：点击桌面项可夺前台焦点

桌面级交互（选区/框选/上下文菜单/批量动作，见对应 spec）要求 Del/Enter/Ctrl+A/Ctrl+C/X/V 在选区存在期间可用。工单02 确立的「面板永不激活」默认不动摇（穿透与不打扰前台仍是立身之本），但键盘路径无处可来：面板默认不可聚焦，热区点击不激活窗口，渲染层收不到任何按键。拍板：**选区门控**——渲染层选区由空变非空时经既有键盘模式通道（setFocusable(true) + focus() + 立即重钉 HWND_BOTTOM，见 panel-ipc）临时取得键盘，选区清空即还原。键盘模式开启会把前台焦点从当前应用手里拿走（前台窗口标题栏变灰）——这正是真实 Windows 桌面的原生行为（点桌面图标焦点即归桌面），肌肉记忆对齐优先于「点击桌面项绝不打扰前台」的洁癖，用户知情拍板。约束：与搜索/设置浮层的键盘模式同一把开关、后开优先，浮层激活期间选区快捷键不接管（按键落在浮层聚焦元素上）；keyboard-mode-on/off 全程存证，验收电池断言其与选区生灭同相。

## Considered Options

- **键盘零接入（复制/剪切只走上下文菜单）** —— 菜单可达但键盘肌肉记忆断裂（Ctrl+C 后直接去资源管理器 Ctrl+V 的连贯动作做不成）；用户点名要键盘路径。
- **全局快捷键（globalShortcut）** —— 选区存在期间注册 Ctrl+C 等全局热键，会劫持用户在前台应用里的同款按键（编辑器里复制文本被抢），不可接受。
- **低级键盘钩子（WH_KEYBOARD_LL）** —— 违反 ADR-0005 红线：窗口宿主线程不得持有任何系统级输入钩子。
- **点击桌面项即常驻激活面板** —— 选区不存在时也无谓夺焦点，破坏「面板是背景层」的日常手感；门控把夺焦点限制在有选区（可能有键盘意图）的窗口期内。

## Consequences

- 选区非空期间面板为前台焦点窗口（聚焦但钉底不抢 z 序）；选区清空（单击空白、Esc、条目删尽、浮层接管）即还原不可聚焦，键盘焦点悬空不回给之前窗口（工单02 spec 同款语义）。
- Del/Enter/Ctrl+A/Ctrl+C/Ctrl+X/Ctrl+V 随门控几乎白送，随二期与剪贴板动作同批落地。
- 点击桌面项（选中动作）会改变前台焦点窗口——已知情接受的行为变化，验收电池需覆盖。
- Esc 语义定序：上下文菜单开→关菜单；否则选区非空→清空选区（并还原键盘模式）。
- 验收电池新增断言组：选区生灭与 keyboard-mode-on/off 存证严格同相。
