# DSH ACP 运行时：浮动最新、专属数据目录、失败不重置

DSH 是 agent-deck 默认且首个完整验收的后端 agent，但“充分融合”不意味着共享 Cordis Context 或把 DSH 嵌进 Electron 主进程。拍板：保持 ADR-0018 的 ACP v1、每会话一进程与按会话 MCP 注入，使用面板专属、稳定的 `DSH_HOME` 和 `acp` profile；运行时使用用户机器上的最新 DSH，未知版本乐观接入并显式标记。用户明确接受持续版本漂移及升级前不备份数据，失败仍不得自动清空、降级或重放。实施与验收范围见 spec #326。

## 运行时与版本

- DSH 承载普通对话／编码与交互管理，第一阶段不承载自主管理。其他 ACP 后端抽象保留，不采用 DSH 私有 SDK、in-process 嵌入或共享 Cordis Context，首版也不开放第三方 DSH 插件安装。
- 运行时不锁定精确版本，也不随面板交付固定 sidecar。未知版本经 ACP `initialize` 与最小只读 MCP 冒烟通过后即可使用，界面标记“未验收版本”并记录实际版本与协商能力；版本号本身不作为拒绝理由。
- 握手或冒烟失败按真实故障处理：管理型创建仍全有或全无，聊天型降级必须由用户显式选择。不自动降级 DSH，不重放在途写，不把协议失败伪装成可用。
- ACP 能力协商、会话凭证、工具审批、取消、工作目录、Job Object 回收、不自动重启与禁止代发等 ADR-0018 决策不变。真实验收记录当时实际 DSH 版本，不把一次绿色结果写成永久兼容承诺。

## 数据与故障

- 面板使用专属、稳定的 `DSH_HOME` 和 `acp profile`，运行时代码与数据分离；provider 由用户显式配置或导入，不声称自动复用其他 profile 的模型配置或其他客户端的会话。
- 面板在 DSH 升级前不自动备份 `DSH_HOME`。用户接受新版本迁移会话格式后可能无法回读旧数据，也接受没有运行时与数据一体回滚。
- 升级或运行失败后，旧数据保持原样；面板不自动清空、重置、降级或改写会话。用户可继续使用新版本、自行恢复自己的备份，或显式创建全新数据目录；任何新目录都不自动继承旧会话。

## Considered Options

- **随面板交付固定 DSH sidecar／首次下载受管归档**——可复现性最强，但引入 Node、原生依赖、包体和升级链工程；用户明确选择浮动最新，不把“锁版本”继续写成目标。
- **用户自备安装但只接受精确白名单版本**——比浮动稳定，却会让 DSH 升级后管理后端不可用，与用户选择相反。
- **共享默认 `~/.dsh`**——便于复用部分凭证，却让其他客户端和不同版本共同读写会话与 profile；选择专属数据目录。
- **升级前自动备份／失败自动回滚**——能降低迁移风险，但引入会话正文复制、恢复与重放语义；用户选择不备份，失败处置仍必须非破坏。
- **DSH 私有 SDK 或共享 Cordis Context**——能获得更深内部能力，却把预览版漂移、进程故障和插件版本矩阵带入面板；ACP 进程边界足够承载当前闭环。

## Consequences

- 本 ADR 修订 ADR-0018 的 DSH 可用性与数据策略：DSH 从候选之一提升为默认且首个完整验收后端，但 ACP 协议面与多后端边界不变；浮动版本与专属 `DSH_HOME` 成为明确产品选择。
- 合并回归以确定性 ACP fake 和面板契约为主，真实最新 DSH 做记录版本的握手、MCP、取消、权限、退出与升级冒烟；不能让浮动第三方进程成为伪装成固定的合并门。
- 失败诊断必须展示实际 DSH 版本、ACP 能力和 MCP 结果。恢复不自动销毁数据，用户选择全新数据目录时须明确旧会话不会随带过去。
