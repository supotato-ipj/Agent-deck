# 独立面板以 Electron + cordis 为底座，取代 Wallpaper Engine 宿主

项目从「WE 壁纸 + Python 数据服务」迁为独立常驻应用：面板浮于用户自选壁纸（背景层）之上，默认鼠标穿透、仅在交互热区接收点击；隐藏原生桌面图标、由面板自绘承载桌面项；终局目标是可热插拔的用户自定义桌面组件。为此选定 Electron 作窗口宿主（透明窗口、穿透 + 事件转发、托盘均为原生能力），cordis 3.x 作主进程插件内核（插件生命周期与热插拔是其本职，经 Koishi 生态长期实战验证）；数据服务的会话扫描、使用日志、Listary 客户端移植为 TS 服务/插件，Python 侧冻结退役。层叠模型定为：背景层 < 独立面板 < 普通窗口；Explorer 与任务栏不动，只接管桌面图标的承载职责。

## Considered Options

- **Python + pywebview（原选型）** — 无插件内核，「用户自定义组件」的生命周期与热插拔要全部手搓，被 cordis 终局推翻。
- **cordis 只用于前端** — 插件拿不到文件与进程能力，承载不了桌面项，不成立。
- **双运行时混合（Python 数据面 + cordis 编排面）** — 两套进程两份状态，违背单常驻进程哲学。
- **托管原生图标（面板下透出真图标、点击穿透直达）** — 保留系统重排、Explorer 打乱布局的全部顽疾，做不到「替代承载」。
- **面板挂 WorkerW 图标层之后** — 图标层盖满屏幕吃掉一切点击，与「面板可交互」互斥。

## Consequences

- ADR-0001 的「壁纸层收不到点击」前提与 ADR-0003 的「搜索面板必须是服务自有 Tk 窗」结论随之失效：面板热区内可收点击与键盘，搜索面板并入面板内 HTML 浮层，Tk 窗退役；桌面分区按 ADR-0001 当年被平台限制否决的「自绘」路线落地。
- 分区语义平移（应用区/文档区/栏位/手钉/推荐位/使用频次/归类/编排）；漂移纠正与布局快照退役，仅保留「恢复出厂布局」动作。
- Win+D 会把面板与普通窗口一并最小化（壁纸不受影响），由守护逻辑防抖自动恢复；应用崩溃时须还原原生桌面图标显示，避免留下空桌面。
- 窗口底部钉扎（HWND_BOTTOM）在 Electron 无原生档位，经 FFI/SetWindowPos 实现。
- cordis 锁 3.x 稳定线（4.0 尚在 beta、官方声明 API 未稳定），只圈定使用其插件生命周期与依赖注入子集。
- 透明背景依赖 WebView2 透明合成，验证失败时降级为窗口级整体 alpha（文字随之变虚）——已接受的降级路径。
- Electron 包体与内存基线高于 pywebview，为插件生态支付的代价。
