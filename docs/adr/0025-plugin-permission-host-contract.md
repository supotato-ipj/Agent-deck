# 插件权限与宿主契约：逐包逐代次授权、独立执行上下文、封闭领域目录

面板要让 DSH 用源码自由创建和改造投放型插件包，但既有投放窄面不足以表达媒体播放器等正当需求，现有同渲染上下文与自由网络也不能支撑逐包授权。拍板：保留**控制面 / 插件宿主面 / DSH 扩展面**三边界，以机器可读的**插件契约目录**描述源码插件能力；敏感数据与动作改由封闭的**权限目录**按包、按代码代次授予，所有投放包进入每包独立 `webContents` 与 origin。首版领域只收媒体与受控 HTTP(S) 网络，实施与验收范围见 spec #326。

## 契约与授权

- 插件仍是 manifest + JS 源码，不引入声明式 UI 运行时。manifest 声明 `hostApiVersion` 主版本与全部权限；首版只接受当前主版本，同主版本只做向后兼容新增，删除权限或改变语义须升主版本。
- **插件能力（capability）**仍只是快照读段白名单；**插件权限（permission）**表达敏感数据与动作。权限由面板按领域实现并登记，插件不能靠新字符串创造权限，也不能获得原始 invoke、系统调用或通用 IPC。
- 插件契约目录向 agent 提供 manifest、宿主 API、权限 DTO／动作／事件／错误与资源上限的只读发现面；MCP 与用户批准 UI 从同一来源投影。MCP 只做确定性的管理操作，DSH 负责写源码，多步流程由 DSH skill 组合。
- 授权绑定插件 id、权限集合、代码哈希与可选凭证绑定，跨重启保存；每次代码更新都重新批准，撤销只向前生效。批准只属于该包，不扩给创建它的 agent、其他插件或控制面。
- manifest 一次声明全部权限，运行中不追加申请。必需权限成组批准，任一缺失即不执行；可选权限逐项批准，缺失时由插件降级。权限目录另定义动作能否持续授权，高影响或不可逆动作仍需一次性**用户手势授权**。
- 敏感包不论来自控制面还是手动投放，批准前都不执行；无敏感权限的手动投放保持投放即生效。待批准更新不执行，已激活代次继续运行；批准后原子替换，拒绝不影响旧代次。安装／更新成功仍须经过待装载区与有界激活。
- 批准界面展示来源、代码代次、文件清单、权限变化和哈希，可展开完整 diff。正常更新保留私有配置；卸载保留但脱离配置，同 id 重装只有在用户独立选择**旧数据继承**后才能重新挂载。

## 执行与领域能力

- 每个投放包使用独立 `webContents` 与 origin，主进程从登记的执行上下文推导插件 id、包根与代码代次；不共享 DOM、跨包资产、网络身份或凭证，不采信调用参数自报身份。内核档插件包仍拿受信内部桥。
- 投放包使用分领域、带类型的 `host.view` / `host.config` / `host.media` / `host.network`，事件只含已获权限的脱敏 DTO。单包崩溃不影响其他上下文，不自动重挂；结果未知的在途动作不重放。
- **媒体**：`media.read` 与 `media.control` 分设，覆盖全部 GSMTC 会话，系统当前会话只是默认选择。Broker 以带代次的不透明媒体会话键寻址，控制前重新解析并检查目标当下能力；只向插件提供脱敏快照、受控缩略图和播放／暂停／上一曲／下一曲，不暴露 WinRT 对象或原生流。
- **网络**：默认无出站网络，`network.request` 按精确 scheme／host／port 授予，首版仅 HTTP(S) 请求—响应与有界响应，不含 WebSocket、原始 TCP/UDP 或永久流。origin 内路径与方法同属授权，跨 origin 重定向不自动跟随，凭证只发给精确匹配目标。
- **凭证**：命名凭证由面板用系统加密能力保存并由 Broker 注入，插件不能读回、枚举或继承其他登录态。可显式绑定多个插件，撤销单包绑定互不影响；轮换不触发代码重批，撤销绑定只产生 `credential_unavailable`，不等同撤销权限。凭证本体保留至用户显式删除。
- **限额与审计**：权限目录规定按插件＋权限的速率、并发、超时与大小上限，用户可收紧不可放宽。权限审计与控制面审计分离，读取聚合、副作用逐次，含目标与结果但不含凭证或完整载荷；完整记录仅用户可见，保留 90 天，插件与 agent 不能删除。
- 旧投放包明确断裂迁移，不保留同上下文／全 invoke 兼容层，不自动改写 JS。第一阶段不开放通用文件、Shell、进程、跨插件调用或自主管理。

## Considered Options

- **只维持 ADR-0019 的固定投放窄面**——能守住边界，却让媒体读取／控制等合理插件永远无法实现；本次改为显式逐包授权，而非暗中放开整个桥。
- **把权限并入 capability 或按原始 invoke 逐条授权**——混淆快照读段与敏感动作，也会把实现细节变成用户批准文案；两轴必须分开。
- **声明式 UI／数据／动作运行时**——能限制表达力，但要在已验证需求之前另造一套运行时；源码优先先证明创建、改造、激活和撤回闭环。
- **共享 renderer、沙箱 iframe 或 facade 检查**——资源成本较低，却无法可靠实现逐包 origin、网络、凭证与故障边界；接受每包独立上下文的资源代价，数值由实测预算。
- **网络自由 fetch、按主域名或按 HTTP 方法授权**——前两者扩大数据出口，后者制造 GET 必然安全的错觉；采用精确 origin + Broker + 凭证注入。
- **崩溃自动重挂与结果未知自动重试**——可能重复 mount 或外部副作用；恢复保持显式。

## Consequences

- ADR-0019 中“投放型插件包只能拿固定投放窄面”及“否决逐包权限”的结论由本 ADR 取代；其包根、控制面安装、待装载区、严格校验、有界激活、回收站与错误信封决策继续有效。投放窄面仍是基线，获批权限在其上叠加。
- ADR-0017 的“每包独立执行上下文”从可选实现收窄为每包独立 `webContents` 与 origin；通道绑定身份、协作性安全边界与不重放原则不变。控制面的宽严矩阵和“面板外的世界”排除不因插件获权而开放给 agent。
- 凭证加密、独立 origin 与审计不承诺抵抗同 Windows 用户恶意进程；它们约束经面板发起的调用并提供可靠身份与追责。
- GSMTC 桥接依赖、Broker 进程归属、生产打包身份和资源预算由前置探针决定，不在本 ADR 假装已验证。交付按零权限、媒体、联网三个参考闭环推进，并以手动投放绕过、代次更新、跨包隔离、旧媒体键和重定向泄密等对抗场景验收。
