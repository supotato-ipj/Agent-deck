# Agent 桌面采用真实 Win11 双虚拟桌面、混合平铺与受控拖入

为在普通桌面完全保留既有窗口行为的前提下增加 Agent 工作区，选定一对真实 Win11 虚拟桌面承载普通 / Agent 桌面，而不是用最小化或隐藏窗口模拟。Agent 桌面采用“屏内平衡二叉平铺＋容量外屏外滚动带”的混合模型，并支持普通桌面窗口经标题栏拖入；两个桌面共享面板内容，其他既有虚拟桌面不受托管。

## 决策

- **桌面边界**：普通桌面是首次启用时所在桌面，既有窗口不迁移；Agent 桌面首次为空，新窗口归属其打开时所在的桌面。TaskView 与标题栏拖入都负责窗口搬家，移入者作为最新成员；第三桌面不创建第三种产品模式。独立面板、自绘任务栏和胶囊跟随当前虚拟桌面并共享状态，自身不参与平铺。
- **混合平铺**：仅管理 Agent 桌面主屏合格应用窗口。容量内保留平衡二叉分裂：初始队列 B、A，子窗格依次排到队尾，分裂轴随深度交替；继续裂变会低于约 `320×240` 逻辑像素时，新窗转入受管的屏外滚动带，不再无限缩小，也不保留原矩形遮挡屏内窗格。平铺区下方避开任务栏，顶部不留胶囊专用条带。
- **屏外滚动带**：新列依次向右排列，每列约为平铺区半宽并占满平铺高度；半宽低于 `320` 时取 `320`，但不超过整个平铺区宽度。右侧屏外列露左缘、左侧屏外列露右缘，露边约 `32` 逻辑像素。首版不支持逐列调宽、自由平移、触摸板或滚轮滑动与手工列排序。
- **激活与视口**：露边点击、任务栏等普通激活采用 `fit`，整组最小滑动到目标窗刚好完整可见，不强制居中；前台新窗按 `fit` 滑入，后台新窗只追加到右端且不移动视口。视口以最近前台受管窗为锚，离开再进入、重启、分辨率或 DPI 变化后重算并 `fit`，不持久化旧像素偏移；无有效锚才回屏内起点。
- **生命周期**：最小化保留窗格、队列与屏外顺序，前台还原执行 `fit`，后台还原不移动视口。关闭屏内窗先由兄弟吸收，再由最早进入屏外的窗口按序补入；关闭屏外窗只收拢滚动带。关闭非当前列保持视口；关闭当前屏外列以右邻优先、否则左邻为锚；关闭屏内当前窗跟随系统新前台，不得留下空白视口。
- **几何状态与收敛**：锁定平铺、已授权但仍平铺、手动浮动三态分离；首次用户改几何仍先询问，切出撤销授权。布局自身导致的目标矩形变化不得冒充用户手势、消费授权或误转浮动；写窗失败必须有界自动收敛。所有受管平铺窗不得因状态错误残留旧大矩形；用户确认后的浮动窗与固定尺寸、拒绝改窗、权限不足造成的异常未平铺仍是明确的覆盖例外。
- **恢复与聚焦**：恢复平铺收回手动浮动并清除授权，异常窗口跳过且报告；屏外滚动带成员已经受管，无需另行补入。恢复后以当前前台受管窗为锚。窗口预览选择目标后直接真正最大化，即使目标原在屏外也不先播放中间滑动；退出聚焦后恢复混合布局并 `fit` 刚退出聚焦的窗口。后台新窗不退出聚焦、抢前台则退出。
- **标题栏拖入**：首版只接受普通桌面主屏合格窗口，一次一窗，从标题栏拖到 Agent 入口；副屏、固定尺寸、面板自身及其他不合格窗口拒绝移入并保持原桌面与原几何。拖悬时只显示落点高亮并暂停 Agent 会话预览，松手才迁移；落放后不切换视图，确认迁移后登记最新成员，实际几何平铺延迟到下次进入 Agent 桌面。
- **拖入取消与失败**：拖走、Esc 或栏外松手只取消跨桌面迁移，保留普通桌面内已完成的正常拖窗位置；落在 Agent 入口但源不合格则恢复拖拽前几何并提示。迁移以桌面 ID 回读确认，未确认不得登记成员；有界重试后仍失败则回滚原桌面与原几何并提示，不留半完成状态。
- **任务栏**：模式切换组固定在开始组右侧；推荐组固定紧贴应用组右侧，两者按可见总宽度整体居中，无推荐位时应用组单独居中；托盘组不变。组间关系不可拖拽破坏，组内图标排序保持可编辑。运行图标按当前桌面过滤，手钉与推荐共享。
- **预览与数据**：Agent 会话预览采用五工具相对顺序的逐会话动态卡片流，空工具不占位，首版只读；标题栏拖拽期间让位于落点反馈。执行、最近活跃、真实等待、疑似等待与未知不得混报。窗口预览优先实时缩略图，最小化使用内存缓存，失败降级为图标与标题；预览图像和新增日志不落窗口标题等敏感内容。
- **恢复与性能**：桌面配对、成员顺序和锚窗可恢复，手动几何授权不持久化，身份不确定即停止自动改窗。目标预算为桌面切换确认不超过 1 秒、窗口事件后平铺稳定不超过 500ms、胶囊预览可交互不超过 200ms；切换串行化并以系统桌面 ID 提交状态。

## Considered Options

- **用 `SW_HIDE` 或最小化模拟双桌面**——会伪造窗口生命周期，破坏 Alt+Tab、TaskView 和新窗口归属语义，拒绝。
- **从第一个窗口起采用 Omarchy 式纯滚动布局**——会改变少量窗口的既有体验；采用容量内二叉、容量外滚动的混合模型。Omarchy 的 `dwindle` 与 `scrolling` 本是两种独立工作区布局，本决策只借鉴其屏外列与焦点适配，不照搬模式切换。
- **窗口继续无限缩小，或容量溢出后保留原矩形堆叠**——前者不可用，后者正是遮挡来源；改为受管屏外滚动带。
- **激活列一律居中，或每次固定滑动一列**——会移动过多并丢失方向感；采用最小位移的 `fit`。
- **拖入后立即切换到 Agent 桌面，或在普通桌面后台改写另一桌面几何**——前者打断连续拖入，后者扩大改窗副作用；采用落放不切视图、进入时再平铺。
- **任意手动矩形继续参与二叉切割**——布局很快成为不可解释的拼图，保留手动浮动与其余窗口重平铺。
- **五工具固定列，或把启发式状态包装成精确事实**——分别采用保留工具相对顺序的动态卡片流，以及显式分态和降级。
- **平台能力缺失时静默退回模拟桌面或缩水发布**——产品语义会被悄然改变，改为原生探针一票否决并返回设计裁决。

## Consequences

- 微软公开 `IVirtualDesktopManager` 只覆盖桌面 ID 查询、当前桌面判断和移动窗口；标题栏拖入还必须取得原生拖动起止、源窗口与松手落点证据，不能把 Chromium 图标拖拽的 `dragSource` 误当窗口句柄。移动以回读为事实，任一路径不稳定都不得冒充完整功能。
- 普通桌面继续维持 ADR-0016 的“托管不改变窗口尺寸”不变量；用户主动标题栏拖动不属于托管改窗，取消拖入不撤销这部分正常系统行为。
- 屏外滚动带仍属 Agent 平铺，计入顶部胶囊与窗口预览；未平铺窗口只包括浮动与异常两类。顶部胶囊不另占平铺区，允许覆盖的浮动与异常不得被误报为本次受管布局缺陷。
- 混合布局、关闭补入、最小化、锚窗重入与露边导航已经一次性单文件状态原型验证；原型不进入生产界面，真实实现仍需原生探针、单元回归与真机验收。
- Agent 会话气泡维持已定的悬浮卡片流：悬停 300ms 展开、离开宽限 400ms、快照刷新 1Hz，支持 Esc 收起与单行横向滚动；标题栏拖拽期间暂停该预览，避免争夺落点。
