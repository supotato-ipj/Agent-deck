# MCP 管理通道：回环 Streamable HTTP、独立 utilityProcess、无状态请求—响应

外部 agent 与后端 agent 经同一份控制面契约管理面板，但 MCP 的进程与故障边界不能反过来绑架常驻面板。拍板：以 `@modelcontextprotocol/sdk` 1.32.1 实现 MCP 2025-11-25，在 `127.0.0.1` 提供固定默认端口的 Streamable HTTP；协议适配器放入独立专用 `utilityProcess`，主进程继续持有 `BridgeService`、信任档与护栏。首版只做无状态请求—响应，不开放异步事件；宿主与面板同生命周期，故障不自动重放写操作。

## Considered Options

- **stdio 直指面板本体**——MCP 客户端要 spawn 服务端，而面板已有单实例锁，二次拉起只会退出。四家可用客户端均支持 URL 与自定义 header，故首版也不提供 stdio bridge；未来确有只吃 stdio 的客户端时再增加薄适配器。旧版 HTTP+SSE、命名管道与描述符文件同样不引入。
- **主进程承载 MCP**——少一次进程间调用，却把网络解析、SDK 依赖与不可信 agent 输入放进整个面板的故障域；一次停顿或崩溃会同时击中桌面接管层。
- **复用 `deck-dataplane`**——技术可行，但会把管理通道与 1Hz 采集、koffi/SQLite、托盘宿主双向耦合：数据面崩溃会切断 agent，agent 输入造成的故障也会打断采集。独立 Node 子进程虽能隔离，却要另建一套已有 `utilityProcess` 范式可覆盖的托管机制。
- **动态端口与描述符文件**——可减少固定端口冲突，却令外部 agent 的静态配置失效，并增加描述符位置、权限与清理问题。固定默认端口选在 1024–49151、写入 `app/config.json`；外部 agent 手工配置同一 URL，后端 agent 仍经对话通道 in-band 获取。
- **面板未运行时按请求自动拉起**——需要额外 launcher 或 stdio bridge，推翻仅 URL 接入并扩大常驻面。保持既有自启项语义：它只负责开机启动面板，不承担 MCP 请求触发的按需启动。
- **保存 MCP 协议会话并推送 BridgeEvents**——2025-11-25 能把异步通知送到客户端，但没有标准机制保证通知进入 agent 会话或模型上下文；日志通知不是领域事件总线，资源订阅只是变化提醒，自定义通知可被客户端忽略。2026-07-28 的 MRTR 也没有补上通用的 BridgeEvent→LLM 推送。首版因此不维护跨请求协议会话，不分配持久 `Mcp-Session-Id`，不提供 GET/SSE 或事件重放。
- **手写 2026-07-28 子集或同时支持两代协议**——会把尚未稳定的协议、兼容与安全实现揽进仓库。先用稳定 SDK，协议细节封闭在适配器内，不以未来规范为由污染 `BridgeService`。

## Consequences

- MCP 宿主只负责协议适配，经 postMessage RPC 进入主进程的单点分派；它不抢单实例锁、不建自启项，也不成为面板退出后仍存活的第二个常驻应用。面板未运行时，外部 agent 看到的就是连接失败，由各自客户端呈现错误。
- 固定端口被占用或落在系统排除段时，不抢端口、不悄悄换端口，也不让面板启动失败；仅管理通道不可用并显式报告，按退避重试原端口，恢复后仍使用原 URL。
- MCP 宿主崩溃或被强杀后，面板按退避重拉专用宿主，主进程与桌面接管层继续运行。既有连接与在途调用失败；结果未知的写操作不自动重试、不补写、不重放，避免一次控制面写执行两遍。
- 首版 agent 需要现状时主动读取 `panel/snapshot`，没有异步事件跨 MCP 边界。将来若另开订阅，仍须遵守 ADR-0010 已定的「事件与快照同口径」段级裁剪，传输不能绕开护栏。
- 宿主重拉不需要恢复客户端协议状态。面板整体退出或重启同样不建立离线队列；面板恢复后仍经同一固定 URL 提供管理通道。
- SDK 升级与 2026-07-28 兼容是适配器内部的后续演进，不改变控制面契约、单监听面或信任档划分。
- 凭证铸造与轮换、默认启用策略和本地安全边界归《控制面的本地安全边界与凭证》；本 ADR 不替该票预设答案。
