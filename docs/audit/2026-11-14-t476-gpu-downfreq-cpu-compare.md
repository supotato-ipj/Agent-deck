## 测量方法（ADR-0032 口径）

- **对象**：面板进程组（electron 主进程整棵子进程树，含 GPU/renderer/utility，约 8~10 pid）
- **指标**：进程组 `TotalProcessorTime` 差分 ÷（墙钟 × 16 逻辑核）×100 = 整机百分比；
  **静置 30s 后采样 300s 长窗**（比 t477 的 30×2s 短窗更长，稳态性更强）
- **驱动**：`audit-round.ps1`（v1）与 `audit-round2.ps1`（v2 = v1 + spawn 归因：每个
  nvidia-smi 现场即时 CIM 查父进程 exe 路径，按工作树分桶 ours / sibling-checkout / other /
  unattributed，把并发外部面板与本票面板分开）——面板由脚本从 t476 工作树 `--panel` 拉起，
  窗口径 300s、settle 30s
- **环境**：本机 zcode 会话并发在跑（非静默夜窗）；面板组读数按自身 CPU 时间差分，背景负载
  不直接污染读数，但调度争用语境如实留痕（与 t484 §一环境标注同口径）
- **形态佐证**：逐轮 spawn 现场数是改前/改后形态的独立证据——旧 5s 档每 300s 应出现 ~60 次
  nvidia-smi（轮询去重后账面 48~53），30s 档每 300s 应 ~10 次（账面 10~11），与代码形态吻合
- **如实注明**：逐轮跑的是「改动前/改动后构建」的二态对比，事后无法对每轮 dist 逐字节复核
  代码态；上表墙钟与提交时刻（a83ef63 12:06、d5eb143 12:56）按 git log 原样记录，形态归属
  以 spawn 频次佐证判读
