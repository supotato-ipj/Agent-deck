# 验收电池章法

验收电池是合并门的证据来源，其可信度取决于测试集本身的纪律：既不能无意义膨胀（运行成本），也不能被单次开发随意增删掏空（审计断层）。本文件立三面规矩与两条流程；段级清单（`app/accept/manifest.json`）是唯一登记处，清单↔代码双向同步与时长预算由 CI 校验器把关（`app/tests/accept/manifest-check.spec.ts`，工单115）——**校验器判红的 PR 不许合并，本文件解释的是「为什么红」和「怎么变绿」**。

## 增段（三条件全满足才可增）

1. **真机行为存证**：仅当新功能需要真机行为存证（像素、输入注入、系统状态等单测无法覆盖的面）才进电池。
2. **单测能覆盖的不进**：纯逻辑、契约、几何、状态机行为一律走 vitest 单测（先例：报告状态机、热区几何、清单校验器）——电池是最后手段，不是顺手保险。
3. **一段绑定一工单**：每段归属唯一工单；同段不得混入无归属的断言。

增段操作：段起笔 `rep.beginSegment('<seg>')` 一行 + 清单登记条目（段号/工单号/失效面五枚举/估计时长），**并附实跑日志佐证估计时长**（guard 托管轮的 `took=` 段账目即可）。增后该电池估计总和不得超时长预算——超了先拆段或等量退役，校验器会替你记住这点。

段号在本电池内唯一（查清单防撞号：主电池曾有两个 P9，后辨析为 P9/P9B）。

## 删段（两类，各有一条硬规矩）

- **特征退役**：功能退役的同一 PR 内删除对应段与清单条目（代码与账本同进同退，不留墓碑断言、不欠账）。退役回归线（断言「某事件不再出现」）按需保留，保留期在 PR 描述里给理由。
- **flaky 禁止静默删除或放宽**：时好时坏的段不许悄悄删掉、注释掉或放松阈值糊弄绿。处置只能走下方 flaky 流程，定责留痕后该删才删、该修才修。

## 改段

- **阈值/等待/取样区改动**：PR 描述必须给理由（为什么旧值错了、新值凭什么对）——断言不许被无形侵蚀。
- **实拍证据更新**：evidence/ 下证据文件随对应改动的 PR 更新，不接受与断言无关的证据漂移。
- 段号改名视同删+增：走两面的全部规矩（含清单同步）。

## flaky 处置流程（禁跳步）

1. **重试**：guard 托管重跑一轮——确认不是单次抖动，记录两轮 verdict。
2. **基线判别**：基线 commit 建一次性 worktree 跑同款电池对照。基线同挂 → 环境扰动，走环境降责定责（结合 preflight 证据与排除窗账目）；基线绿而分支挂 → 真回归，回改代码。
3. **定责留痕**：结论（环境/回归/段自身缺陷）写进 issue 或 PR 描述——静默无痕的「自己好了」不算处置完成。

## 时长预算流程

- 每块电池预算记于清单 `budgetSeconds`（主电池 720s 为 spec 封顶；副电池按实测健康轮校准：估计合计 ×2 向上取整分钟、下限 60s）。
- 新增/改段须附实跑日志佐证 `estSeconds`；健康轮的段账目 `took=` 数据是校准来源，实测与估计偏差过大时在同 PR 校准。
- CI 校验器判「估计总和 > 预算」为红：处置 = 拆段、等量退役或（确有必要的）预算上调——上调预算是章法级改动，PR 描述须给理由并 @ 维护者复核。
- 环境劣化轮的 `took=` 不作校准基准（失败路径耗时混入），以健康轮为准。

## 定向验收轮与轮次纪律（工单207，spec #201 A 链收口）

「哪段验证哪片代码」自工单204 起是**登记**而非部落知识：段级清单为每段登记 `areas` 域标签（14 域封闭词表），配一张声明式 path→area 映射表；选择器（`app/accept/lib/area-selector.js` 纯函数核心 + `app/scripts/select-rounds.js` CLI）把变更文件集映射成运行计划。**选择器只打印计划与拼好的 guard hold 命令行，不拉起、不占验收槽**——多检出并行安全；真正的执行仍走 accept-guard 调度协议。

### 三档轮次

| 轮次 | 何时 | 相位 | 证据地位 |
| --- | --- | --- | --- |
| 定向轮（开发回路） | 改完一处，想分钟级确认 | `selftest` | 自测证据，**不作**合并门证据 |
| 定向轮（合并证据） | PR 合并前 | `accept-sprint` | 合法合并门证据（ADR-0011 范围段语义照旧） |
| 全量校准轮 | 见下方强制触发 | `accept-sprint` | 合法合并门证据；兼作耦合表的体检轮 |

定向轮不降低任何既有门槛：合并门仍按 ADR-0011 的 verdict 三态与 **spec 范围段** 语义判定（声明的范围段须实跑且全绿；范围段被打断须重跑）——定向轮是合法证据形态，不是降级形态。

### 全量校准轮的强制触发

① **影响选段正确性的段级 schema／areas 词表变更的 PR**——改了选段的依据（段级 schema、areas 词表、path→area 映射表），耦合表本身的可信度就得用全量轮体检。口径按 #203 决策 8 收窄：**电池级接线字段豁免**全量校准轮，段级 schema／areas 词表变更**仍触发**。
② **耦合漏报反馈**——全量轮出现红段，且该红段的 `areas` 与本轮 diff 命中的域**无交集**（改了这片代码、跑了全量、红的却是另一片）→ 记 issue 修耦合表，**不判回归**。
③ **按需兜底**——大合并前，或用户点名时。

### 耦合漏报反馈流程（禁跳步）

1. **对照**：全量轮红段 → 查该段在清单的 `areas` → 与本轮 diff 命中的域求交集。
2. **有交集** → 正常按 ADR-0011 判读（未定责失败即 FAIL-CODE，走基线判别流程）。
3. **无交集** → 判为**耦合漏报**（不是回归）：把红段及其 `areas` 写进 issue，指明「该段与本轮改动无登记关系，应登记到哪个域」。
4. **修表**：issue 闭环后按「增段三条件」同款规矩改段级清单的 `areas`（改登记，不改断言）——CI 校验器守住越表与漏映。
5. **留痕**：结论写进 issue 或 PR 描述——静默改表不算处置完成（同 flaky 流程的定责留痕要求）。

**红线**：耦合漏报流程只许改「登记」，不许借机改断言、阈值、等待时长——那是上方「改段」一节的章法红线。
