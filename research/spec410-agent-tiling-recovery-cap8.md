# Agent 平铺异常重启重建与 8 窗屏内上限

## Problem Statement

作为 Agent 桌面用户，我遇到三类相互叠加的问题：

1. 面板异常退出或被强杀后，即使重新启动，Agent 平铺仍可能一直处于崩溃安全态。ZCode、Kimi Code 等合格窗口位于正确的 Agent 桌面，却只以普通浮动窗口的方式打开；必须找到特定的正常退出路径才能恢复。
2. 窗口超过 5 个后，仍可能看到新窗以原矩形悬浮打开或覆盖其他平铺窗，破坏平铺桌面的空间可信度。
3. 上一轮增加的屏外滚动带在日常窗口数量下几乎不可见。当前只按约 `320×240` 的最小窗格判断容量，在 `2560×1392` 平铺区上约需第 33 扇窗才触发，因此用户无法稳定体验屏外滚动带。

我希望异常重启后平铺能自行恢复、6–8 窗稳定分裂，并明确约定屏内最多 8 窗，从第 9 窗开始进入屏外滚动带。

## Solution

Agent 桌面采用明确且有界的混合布局规则：

- 屏内平衡二叉分裂最多容纳 8 个平铺窗格，第 9 个及后续合格窗口按进入顺序进入屏外滚动带。
- 保留最小窗格约束：如果屏幕尺寸或缩放导致不足 8 窗时就无法继续满足约 `320×240` 逻辑像素，则提前进入屏外滚动带；8 是上限，不是对小屏的强制分裂数量。
- 屏外窗口仍是受管平铺成员。前台新窗自动按 `fit` 最小滑动到完整视图；点击露边、任务栏激活等普通激活沿用同一规则。
- 面板发现上次未干净退出时，不再恢复旧的窗口顺序、树形、屏外顺序、锚窗或浮动几何，但也不永久停用平铺；它以当前 Agent 桌面中的合格窗口重建布局。
- 桌面 ID 不符、窗口身份不符或布局模型损坏等其他安全风险仍须停止自动改窗，不因本次恢复调整而放宽。
- 只有用户明确授权后的浮动窗口，以及固定尺寸、拒绝改窗或权限不足造成的异常未平铺窗口可以保留悬浮覆盖。其他窗口必须进入屏内窗格或屏外滚动带，不得以打开时的原矩形覆盖既有窗口。

## User Stories

1. 作为 Agent 桌面用户，我希望 1 扇窗铺满平铺区，以便单窗工作不受新规则影响。
2. 作为 Agent 桌面用户，我希望 2–5 窗继续按既定平衡二叉顺序分裂，以便保留已有空间记忆。
3. 作为 Agent 桌面用户，我希望第 6、7、8 扇窗仍稳定进入屏内窗格，以便常见多窗场景不会悬浮或覆盖。
4. 作为 Agent 桌面用户，我希望屏内同时最多保留 8 个平铺窗格，以便窗口数量与布局行为容易理解。
5. 作为 Agent 桌面用户，我希望第 9 扇合格窗口必进入屏外滚动带，以便无需打开数十扇窗就能使用屏外布局。
6. 作为 Agent 桌面用户，我希望第 10 扇及后续窗口依次进入屏外滚动带右端，以便窗口顺序可预测。
7. 作为小屏或高缩放用户，我希望最小窗格约束优先于强行凑满 8 窗，以便窗口不会缩小到不可用。
8. 作为 Agent 桌面用户，我希望最小化窗口仍保留其屏内窗格或屏外位置，以便窗口计数和恢复语义保持一致。
9. 作为关闭屏内窗的用户，我希望兄弟先吸收空位、再由最早进入屏外的窗口补入，以便 8 窗上限下的关闭行为仍然确定。
10. 作为关闭屏外窗的用户，我希望滚动带按原顺序收拢，以便无关窗口不无端换位。
11. 作为打开前台第 9 窗的用户，我希望新窗自动完整滑入视图，以便立即继续操作。
12. 作为有后台新窗出现的用户，我希望后台窗只追加到屏外滚动带而不移动当前视口，以便当前工作不被打断。
13. 作为点击屏外露边的用户，我希望整组按 `fit` 最小滑动到目标窗，以便导航保持轻量且可预测。
14. 作为经任务栏激活屏外窗的用户，我希望使用与露边点击相同的 `fit` 规则，以便不同入口不产生矛盾的位置。
15. 作为从屏外窗返回屏内窗的用户，我希望反向激活同样最小滑动，以便双向导航对称。
16. 作为 Agent 桌面用户，我希望屏外成员继续计入顶部窗口胶囊与窗口预览，以便不会遗漏正在运行的窗口。
17. 作为面板异常退出后的用户，我希望重启后自动恢复 Agent 平铺，以便不必理解内部崩溃标记或寻找特殊退出方式。
18. 作为面板被强杀后的用户，我希望旧布局被放弃而当前合格窗口重新平铺，以便不可信的历史状态不会永久禁用功能。
19. 作为异常重启后打开新窗的用户，我希望新窗继续正常进入平铺或屏外滚动带，以便恢复不是一次性的。
20. 作为异常重启后的用户，我希望系统不恢复旧的浮动几何或手动几何授权，以便崩溃前的临时操作不会泄漏到新会话。
21. 作为异常重启后的用户，我希望当前窗口按当次可观察事实建立新顺序，以便布局不依赖已经失效的旧句柄或旧几何账。
22. 作为桌面配对无法确认的用户，我希望系统仍停止自动改窗，以便重建规则不会接管未知桌面。
23. 作为布局模型损坏的用户，我希望系统仍进入模型安全态，以免把损坏数据当成有效布局。
24. 作为窗口身份核对失败的用户，我希望既有身份安全边界仍然有效，以免误改其他应用的窗口。
25. 作为 Agent 桌面用户，我希望 6–8 窗新增导致的自动缩放不消耗手动几何授权，以便系统不会误弹提示或误转浮动。
26. 作为 Agent 桌面用户，我希望普通新窗不会以打开时的原矩形覆盖其他受管窗，以便平铺结果可信。
27. 作为明确授权手动浮动的用户，我希望浮动窗仍可覆盖平铺窗，以便既有手动工作流不被破坏。
28. 作为使用固定尺寸或受限应用的用户，我希望异常未平铺被明确记录且不阻塞其他窗口，以便降级行为可理解。
29. 作为普通桌面用户，我希望普通桌面继续保持零自动平铺改窗，以便本次修复不扩大托管范围。
30. 作为非托管虚拟桌面的用户，我希望自己的窗口不受 8 窗规则或崩溃重建影响，以便既有工作区保持独立。
31. 作为重启后面板的使用者，我希望布局恢复状态能区分旧布局恢复与异常后的当前窗口重建，以便诊断结果诚实可读。
32. 作为维护者，我希望同一窗口事件序列产生相同的最终矩形、屏外顺序和视口锚，以便回归可以稳定复现。

## Implementation Decisions

- **在既有平铺规划模型中增加屏内窗格上限**：平衡二叉树新增屏内容量上限 8；当已有 8 个屏内成员时，新成员直接进入有序屏外集合，不再尝试裂变。
- **容量判断采用双约束**：任一裂变仍须满足最小窗格尺寸，同时不得超过 8 个屏内窗格。两个条件任一不允许分裂，都进入屏外滚动带。
- **保持单一布局账**：屏内树、屏外顺序、成员加入序和视口锚继续属于同一个 Agent 平铺状态，不引入第二套窗口成员账。
- **上限适用于所有入口**：普通新窗、TaskView 移入、标题栏拖入、异常重建、干净恢复、显示参数重算和屏外补入都必须遵守同一容量规则。
- **旧布局向新上限归一**：干净启动读到合法但超过 8 个屏内窗格的旧模型时，按持久成员顺序保留前段屏内成员，其余按序转入屏外滚动带；模型损坏不按可恢复模型处理。
- **异常退出只废弃旧布局内容**：布局文档可解析且桌面配对仍可信时，`clean=false` 不再进入永久 `crash` 停写态；旧成员顺序、树形、队列、屏外顺序、锚窗和浮动记录全部不应用。
- **异常后从当前事实重建**：以当前 Agent 桌面主屏合格窗口及当次事件顺序建立新成员序，随后执行正常的屏内/屏外规划与实际几何回读收敛。
- **其他安全闸门保持不变**：文档无法解析或模型不一致仍报 `model`；桌面 ID 不一致仍报 `desktop-id`；需要依赖旧窗口身份而核对失败时仍报 `window-identity`。异常重建既然不采用旧窗口身份，就不因旧句柄已经消失而阻塞当前窗口。
- **恢复结果如实表达**：异常重建完成后不伪称恢复了旧布局；沿用现有恢复投影时，应能明确区分干净恢复与异常重建，事件存证记录重建策略，但不增加窗口标题等敏感内容。
- **正常退出协议保持**：运行中仍写 `clean=false`，正常退出仍写 `clean=true`；该标记继续表达是否允许应用旧布局，而不是决定平铺功能是否可用。
- **复用既有授权与写窗收敛**：布局自身造成的几何变化不得进入手动几何授权；写窗失败继续有界重试并按实际矩形分类异常，不用规划成功代替真实落位。
- **屏外几何和导航规则不变**：列宽、约 32 逻辑像素露边、双向 `fit`、前台/后台新窗、关闭补入、最小化和锚窗恢复沿用 ADR-0028 既有决策。
- **同步领域文档**：更新 GLOSSARY 中 Agent 平铺、容量溢出及异常恢复相关语义，并修订 ADR-0028 的容量与崩溃恢复决策；无需另建平行 ADR。
- **不扩大日志隐私边界**：诊断只使用窗口句柄、低敏计数、恢复策略与结果，不记录窗口标题、缩略图或对话内容。

## Testing Decisions

- **优先使用现有最高行为缝**：纯容量几何由平铺规划函数测试；恢复、授权、成员生命周期和实际写窗由 Agent 平铺服务的假窗口 harness 测试；真实 Win32 与虚拟桌面行为由现有验收电池测试。
- **好测试只断言外部行为**：比较最终实际窗口矩形、屏内/屏外成员数、屏外顺序、视口位置、恢复状态、授权计数和异常分类；不绑定私有缓存、内部调用次数或树节点实现细节。
- **容量规划矩阵**：覆盖 1、2、5、6、7、8、9、10 窗；断言前 8 窗在尺寸允许时全部落格，第 9 窗起按序入带；另覆盖小屏提前入带、关闭补入、旧模型超过 8 窗的归一。
- **异常恢复服务矩阵**：以合法 `clean=false` 文档和当前合格窗口启动，断言旧树/浮动/锚窗不应用、当前窗口全部重建、后续新窗仍受管；另保留模型、桌面身份等安全态零写入反例。
- **多窗稳定性服务矩阵**：逐个打开 6、7、8、9 窗并回读实际矩形，断言非例外成员没有原矩形覆盖、没有误转浮动、没有误消费授权，第 9 窗进入屏外并正确滑入。
- **复用现有真机段而不新增重复段**：修改重启恢复电池的崩溃段，从“崩溃后矩形不变”改为“旧布局不应用、当前合格窗口重建平铺”；保留同一电池的模型和桌面身份安全反例。
- **调整既有屏外滚动带真机段**：把触发夹具从约 33 窗缩到 9 窗，继续验证真实列矩形、露边命中、双向 `fit`、计数与收拢；按电池章法同步段级说明、证据和实测时长，不放宽其他断言。
- **真实回归场景**：在 Agent 桌面验证 ZCode 与 Kimi Code 均参与平铺，并覆盖 6–8 窗稳定分裂及第 9 窗入带；自动夹具仍负责可重复的几何断言。
- **既有先例**：沿用平铺规划纯函数矩阵、平铺服务假窗口 harness、重启恢复电池和 Agent 平铺生命周期电池，不新建平行测试框架。
- **完整验证门**：构建、类型检查、单元测试与受影响真机验收全部通过；真机验收一律经 accept-guard，改段的文本审计链随轮更新。

## Out of Scope

- 不新增滚轮、触摸板横滑、自由平移视口、逐列调宽或手工屏外列排序。
- 不把 8 窗上限解释为小屏也必须强行分裂到 8 窗。
- 不改变普通桌面、非托管桌面或副屏窗口的既有行为。
- 不允许所有异常或浮动窗口都被强制改窗；明确授权浮动与异常未平铺仍是合法例外。
- 不取消桌面 ID、窗口身份、模型有效性等其他安全闸门。
- 不改变 Agent 聚焦、窗口预览选择直接最大化、标题栏拖入事务或会话预览的既有契约。
- 不引入新的布局文档隐私字段，不持久化手动几何授权，不记录窗口标题或预览图像。
- 不通过删除、跳过或放宽既有失败断言来制造绿色验收。

## Further Notes

- 本 spec 的共识来自用户逐项确认：异常后重建、8 窗上限保留最小尺寸兜底、沿用自动 `fit`、仅保留明确浮动与异常例外。
- 现场诊断已确认：ZCode 与 Kimi Code 均可见、可缩放、非工具窗，且桌面 ID 与当前 Agent 桌面一致；它们未被资格过滤，未平铺的直接原因是服务进入 `safe/crash`。
- 隔离双轮对照已确认：真正正常关闭主窗会写入 `clean=true`，随后启动时两窗能立即左右平铺；问题不是平铺算法整体不可用，而是异常标记导致的持续停写。
- 当前屏外滚动带实现已有服务级和真机证据，但其纯尺寸容量阈值在本机约第 33 窗才触发；8 窗上限是对触发规则的明确产品调整，不是另建一套滚动功能。
- 本工单承接并修订 #383 的崩溃恢复语义以及 #403/#405 的容量语义；#404 的布局误授权分流与写窗收敛必须保留。
