# Agent 平铺遮挡修复、屏外滚动带与标题栏拖入 Spec

## Problem Statement

作为 Agent 桌面用户，我在窗口达到 6 个或更多时会看到新窗覆盖既有平铺窗；关闭窗口后，兄弟吸收与容量补入的顺序难以预测，即使只剩 3/4 个窗口，也可能仍有旧的大尺寸窗口压住其他窗口。这使平铺桌面失去最基本的空间可信度。

同时，普通桌面中已经打开的窗口只能经系统 TaskView 等方式迁移。我希望直接拖动窗口标题栏到任务栏的 Agent 入口，把窗口交给 Agent 桌面，并在进入 Agent 桌面时看到它自动参与平铺。

## Solution

保留少量窗口时确定性的平衡二叉平铺；容量不足时，把新增窗口纳入受管的**屏外滚动带**，以固定规则的屏外列和 32px 露边替代原矩形堆叠。点击露边或普通激活窗口时，整组按 `fit` 最小滑动；关闭、最小化、重入和恢复都遵循稳定的成员顺序与锚窗规则。

修复布局状态收敛：布局自身的几何变化不得冒充用户手势，写窗失败必须有界自动恢复，实际窗口矩形必须与受管布局一致。手动浮动与异常未平铺仍是明确、可诊断的例外。

新增标题栏拖入 Agent 桌面的单窗事务：普通桌面主屏合格窗口拖到 Agent 入口，确认虚拟桌面迁移后登记为最新成员，但不切换当前视图；下次进入 Agent 桌面时统一执行实际平铺。取消、无效源与迁移失败均有明确且不伪造成功的行为。

## User Stories

1. 作为 Agent 桌面用户，我希望 6 个及更多窗口仍遵守同一套受管布局，以便新窗不会无故覆盖既有工作。
2. 作为 Agent 桌面用户，我希望相同窗口事件序列产生相同布局，以便我能形成稳定的空间记忆。
3. 作为 Agent 桌面用户，我希望关闭屏内窗时由其兄弟吸收空位，以便无关窗格不会无故换位或缩水。
4. 作为 Agent 桌面用户，我希望屏外窗口按进入顺序补入释放的容量，以便关闭后的布局可以预测。
5. 作为 Agent 桌面用户，我希望逐级关闭到 4 个或 3 个窗口后所有受管窗都恢复到正确矩形，以便旧大窗不会继续遮挡其他窗口。
6. 作为 Agent 桌面用户，我希望新增或关闭兄弟导致的自动缩放不被识别为我的手动操作，以便系统不会突然弹出几何授权提示。
7. 作为已授权手动几何的用户，我希望布局自身的缩放不会消费授权或把窗口误转浮动，以便只有我的真实操作才能改变窗口状态。
8. 作为 Agent 桌面用户，我希望一次瞬时写窗失败能够自动、有界地重试，以便窗口不会永久停留在旧位置。
9. 作为 Agent 桌面用户，我希望平铺状态以实际矩形回读为准，以便“规划已完成”不会掩盖真实的遮挡。
10. 作为 Agent 桌面用户，我希望容量不足时新窗进入屏外滚动带，以便既有窗格不无限缩小，也不被新窗原矩形覆盖。
11. 作为 Agent 桌面用户，我希望屏外窗仍是受管平铺成员，以便它们与屏内窗一样计数、预览和恢复。
12. 作为 Agent 桌面用户，我希望屏外列依次向右排列，以便我能按打开或拖入顺序找到它们。
13. 作为 Agent 桌面用户，我希望屏外列约为半屏宽并占满平铺高度，以便每扇窗都有可用的工作面积。
14. 作为小屏或高缩放用户，我希望屏外列不低于 320 逻辑像素且不超过平铺区宽度，以便最小尺寸规则在所有显示条件下保持一致。
15. 作为 Agent 桌面用户，我希望右侧屏外列露出左缘、左侧屏外列露出右缘，以便我能发现两侧的屏外窗口。
16. 作为 Agent 桌面用户，我希望露边约为 32 逻辑像素，以便点击目标清楚但不过多占用工作区。
17. 作为 Agent 桌面用户，我希望点击露边后整组只滑动到目标窗刚好完整可见，以便不会移动过头或丢失方向感。
18. 作为 Agent 桌面用户，我希望从右侧屏外窗返回左侧窗口也遵循同一最小滑动规则，以便双向导航对称。
19. 作为 Agent 桌面用户，我希望任务栏等普通激活也执行相同的 `fit`，以便不同入口不会呈现互相矛盾的位置。
20. 作为打开前台新窗的用户，我希望新窗自动滑入完整视图，以便立即继续当前操作。
21. 作为有后台新窗出现的用户，我希望后台窗只追加到屏外带右端而不移动视口，以便当前工作不被打断。
22. 作为最小化窗口的用户，我希望原窗格与屏外顺序被保留，以便还原后回到原来的工作上下文。
23. 作为前台还原窗口的用户，我希望该窗自动完整可见，以便无需再手动寻找它。
24. 作为后台还原窗口的用户，我希望视口保持不动，以便后台状态变化不会抢走了当前上下文。
25. 作为关闭非当前屏外列的用户，我希望当前视口保持不变，以便其他窗口的生命周期不影响我正在看的内容。
26. 作为关闭当前屏外列的用户，我希望优先看到右邻、没有右邻时看到左邻，以便连续关闭时位置变化可预测。
27. 作为关闭屏内当前窗的用户，我希望视口跟随系统新的前台窗，以便产品状态与 Windows 焦点事实一致。
28. 作为连续关闭窗口的用户，我希望滚动带收拢后不会出现空白视口，以便屏幕始终展示有效的剩余工作。
29. 作为点击恢复平铺的用户，我希望收回浮动窗但保留当前锚窗，以便修复布局不会无故跳回第一个窗口。
30. 作为离开再进入 Agent 桌面的用户，我希望以最近前台受管窗恢复视口，以便继续之前的工作。
31. 作为重启面板或改变分辨率/DPI 的用户，我希望重算布局并以锚窗恢复，以便旧像素偏移不会把我带到空白位置。
32. 作为使用窗口预览的用户，我希望选择条目仍直接进入 Agent 聚焦并最大化，以便既有聚焦工作流不被改变。
33. 作为退出 Agent 聚焦的用户，我希望恢复混合布局并显示刚退出聚焦的窗口，以便上下文连续。
34. 作为明确授权浮动的用户，我希望浮动窗仍能覆盖平铺窗，以便手动工作流不被本次修复破坏。
35. 作为使用固定尺寸或受限应用的用户，我希望异常未平铺被明确标注而不是反复强改，以便降级行为可理解且不打断其他窗口。
36. 作为普通桌面用户，我希望拖动已打开窗口的标题栏到 Agent 入口即可迁移，以便不必打开系统 TaskView。
37. 作为普通桌面用户，我希望一次标题栏拖拽只迁移当前一个窗口，以便动作边界清楚。
38. 作为普通桌面用户，我希望只有主屏合格窗口可以拖入，以便副屏、固定尺寸和面板自身窗口不会被错误接管。
39. 作为拖窗经过 Agent 入口的用户，我希望看到明确的落点高亮，以便知道松手后的目标。
40. 作为拖窗经过 Agent 入口的用户，我希望 Agent 会话预览在拖拽期间暂停，以便预览不会争夺落点或焦点。
41. 作为完成拖入的用户，我希望该窗成为 Agent 桌面的最新成员，以便连续拖入的顺序可预测。
42. 作为完成拖入的用户，我希望视图仍停留普通桌面，以便可以连续拖入多个窗口而不被反复切换。
43. 作为进入 Agent 桌面的用户，我希望此前拖入的窗口自动完成实际平铺，以便迁移结果立即可用。
44. 作为取消拖拽的用户，我希望拖走、Esc 或栏外松手只取消跨桌面迁移，以便普通桌面内的正常拖窗位置不被面板撤销。
45. 作为把不合格窗口放到 Agent 入口的用户，我希望窗口保持原桌面并恢复拖拽前几何，同时看到简短原因，以便失败动作明确且无副作用。
46. 作为跨桌面迁移的用户，我希望以桌面 ID 回读确认成功，以便界面不会在系统未接受迁移时伪造成功。
47. 作为迁移失败的用户，我希望系统有界重试后回滚原桌面与原几何，以便不出现半迁移、半登记的状态。
48. 作为使用其他 Win11 虚拟桌面的用户，我希望非托管桌面不受新拖入与平铺规则影响，以便现有工作区保持独立。
49. 作为普通桌面用户，我希望既有窗口手工管理行为保持不变，以便新功能不会扩大自动改窗范围。
50. 作为注重隐私的用户，我希望新增日志不记录窗口标题、预览图像或拖入内容，以便平铺诊断不会增加敏感数据暴露。

## Implementation Decisions

- **保留持久二叉树，扩展为单一混合布局账**：现有树继续负责屏内成员、分裂队列和兄弟吸收；新增有序屏外列与视口锚窗属于同一布局状态，不另建互相竞争的成员账。
- **容量溢出改变含义**：它只表示触发屏外滚动带扩展的容量条件；屏外成员不是未平铺窗口。未平铺只剩浮动与异常两类。
- **统一布局坐标与视口**：屏内树和屏外列共享连续逻辑坐标，视口只保存锚窗语义。列宽按半屏、最小 320、最大平铺区宽度计算；32px 露边是导航边界，不是自由浮动状态。
- **单一激活入口执行 `fit`**：露边点击、任务栏激活、前台新增、前台还原和恢复布局都汇入同一最小滑动计算；窗口预览选择仍走 Agent 聚焦，不复制另一套滑动规则。
- **确定性生命周期**：屏内关闭先收缩再按屏外进入序补入；屏外关闭只收拢列；非当前关闭保持视口，当前关闭按已确认的邻接或系统前台规则重新选锚。
- **布局写窗与用户手势分流**：凡由本轮布局目标引起的矩形变化都标记为预期写入，不进入手动几何授权状态机；只有真实用户移动或缩放才允许触发授权流程。
- **以实际几何收敛为准**：写窗后回读实际矩形，失败使用有界重试与退避；没有后续窗口事件也必须能完成收敛。状态投影不能把规划落格数冒充实际达标数。
- **沿用现有状态投影并澄清屏外语义**：顶部胶囊、窗口预览和诊断共享同一投影；优先复用现有计数字段表达屏外成员，只有界面确有需要时才增加低敏状态，不暴露窗口标题或原生对象。
- **持久化布局关系而非旧像素**：现有布局恢复文档扩展屏外顺序与锚窗身份；手动几何授权仍不持久化，桌面身份无法核对时继续失败关闭。
- **新增一个内部工作区拖入命令**：请求只携带源窗口句柄；主进程重新核对配对、当前普通桌面、源桌面、主屏和窗口资格，不能信任渲染端自报资格。复用现有虚拟桌面移动与桌面 ID 回读适配器。
- **拖入是一次事务**：落放前保存原桌面与原几何；移动未确认时有界重试，最终失败则回滚。只有确认后才产生一次性待入列交接，Agent 平铺下次激活时按交接顺序对账并清除，不形成第二份持久成员账。
- **普通桌面不提前改 Agent 几何**：拖入落放不切换视图；实际平铺在下次进入 Agent 时执行，继续遵守普通桌面零自动托管改窗。
- **原生拖动手势先探针后接入**：必须验证系统移动/尺寸起止、源窗口归属、松手与 Agent 热区落点；现有 Chromium 图标拖拽只用于图标排序，不复用其源身份。项目不因该功能默认引入全局低级鼠标钩子。
- **拖拽期间协调会话预览**：原生标题栏拖拽处于活动态时暂停 Agent 会话预览，并把 Agent 热区解释为落点；结束后恢复既有悬停预览行为。
- **露边优先使用真实窗口激活**：不为同一窗口再画一套争抢输入的把手；实际前台变化进入统一 `fit` 路径。
- **沿用 ADR-0028 的性能与安全边界**：窗口事件后 500ms 内稳定、桌面切换确认不超过 1 秒、胶囊预览可交互不超过 200ms；桌面身份或原生能力不确定时停止自动改窗。

## Testing Decisions

- **主测试缝沿用 Agent 平铺服务的现有假窗口 harness**：从窗口事实、前台状态、几何写入与回读驱动服务，断言外部可见的窗口矩形、授权提示、浮动状态、状态投影和事件，不绑定内部类或私有方法。
- **纯几何只保留给既有规划函数**：分裂、兄弟吸收、列宽、露边和 `fit` 可用现有纯函数缝做精确矩阵；生命周期与授权必须上到服务缝，避免只证明规划正确而漏掉真实写窗。
- **拖入以主进程公开工作区命令为最高测试缝**：用既有虚拟桌面适配器的假实现验证资格核对、移动、回读、交接、回滚和事件；渲染层只验证热区状态与契约，不复制主进程业务规则。
- **好测试只断言外部行为**：同一事件序列比较最终实际矩形、屏外顺序、当前锚窗、桌面 ID、前台窗口、提示与回滚结果；不要求测试知道队列节点或私有缓存形状。
- **既有先例如平铺服务 harness、平铺规划几何矩阵、桌面配对回读探针、任务栏输入注入与窗口预览电池**；不为本功能新建平行测试框架。
- **缺陷回归至少覆盖**：6+ 新增；按不同顺序逐级关闭到 4/3；关闭时前台恰好落在待扩张兄弟；locked 与 armed 两种授权相位；一次写失败后完全无后续事件；同拍多窗出现/关闭；2→1→新增及重启后的连续性。
- **屏外行为至少覆盖**：首次溢出、双向露边点击、普通激活、前台/后台新增、最早成员补入、当前/非当前列关闭、最小化与前后台还原、锚窗重入、分辨率和 DPI 变化、极窄屏列宽。
- **聚焦与例外至少覆盖**：预览选择屏外窗直接最大化、退出后 `fit`、恢复保持锚窗、明确浮动与异常未平铺不被误报为受管布局遮挡。
- **拖入至少覆盖**：合格单窗、连续两窗顺序、落放不切桌面、进入后平铺、拖走、Esc、栏外松手、不合格源、未配对、移动失败、回读失败、回滚失败的有界终局，以及拖拽期间会话预览不展开。
- **真机验收只覆盖单测无法证明的面**：真实标题栏输入、原生拖动起止、实际 SetWindowPos/GetWindowRect、露边命中、系统前台、真实虚拟桌面 ID 与面板重启。
- **优先扩展现有 Agent 平铺生命周期与桌面切换验收，不新建电池**：新增或修改验收段必须遵守电池章法，登记工单、失效面、域标签与时长，并经 accept-guard 托管。
- **完整验证门**：构建、类型检查、单元测试、契约测试与受影响真机验收段全部通过；任何尚未取得原生证据的能力不得宣称完成。

## Out of Scope

- 不从第一个窗口起改成 Omarchy 式纯滚动布局，也不以另一套网格替换容量内二叉平铺。
- 不支持副屏窗口拖入、多窗口批量拖入或非托管桌面的自动接管。
- 不支持逐列调宽、手工屏外列排序、自由平移视口、触摸板横滑或滚轮滑动。
- 不在拖入后自动切换到 Agent 桌面，也不在普通桌面后台提前改写 Agent 窗口几何。
- 不改变手动几何授权的持久化边界，不提升权限强改固定尺寸或受限窗口。
- 不把 Agent 平铺变成 Win11 系统 Snap，也不改变既有分屏会话语义。
- 不把一次性 HTML 原型或其视觉外壳作为生产界面交付。
- 不新增记录窗口标题、预览图像或拖入内容的诊断日志。

## Further Notes

- ADR-0028 已按本共识修订；领域词汇以 GLOSSARY 中 Agent 桌面、Agent 平铺、屏外滚动带、容量溢出、未平铺窗口与恢复平铺为准。
- 单文件状态原型已由用户验证通过，覆盖容量、露边、关闭补入、最小化与锚窗恢复；它回答的是状态模型与交互问题，不构成真实 Win32 能力证据。
- Omarchy 的参考点是屏外列与 Hyprland 的 `fit` 焦点适配；Omarchy 自身把 dwindle 与 scrolling 作为独立布局，本方案明确选择混合模型而非照搬模式切换。
- 代码调查已发现布局变化误入授权状态机、写窗重试未闭环等高风险机制，但用户现场根因仍须由真机状态与事件记录定责；不得把假设写成已证实结论。
