# Agent 平铺按真实窗口尺寸约束降级到屏外滚动带

## Problem Statement

作为 Agent 桌面用户，我在打开 5 个及以上真实应用窗口时，仍可能遇到窗口保留旧的大矩形、覆盖其他平铺窗，无法形成可信的自然平铺。现有理想夹具的 5/6 窗与屏外带验收虽然通过，但没有覆盖真实 Electron 应用的最小尺寸、拒改和异步写窗行为，因此不能解释或排除我的现场问题。

同时，我很难触发屏外滑动。现行产品实际只提供容量溢出后的露边点击、普通激活与前台新窗 `fit`，并不提供滚轮、触摸板横滑或自由平移；真实应用一旦因拒绝分裂目标而退出平铺候选，还可能进一步推迟或阻止屏外滚动带出现。

我希望平铺能尊重真实应用的可用尺寸：当前分裂不可行时，新窗进入屏外滚动带，而不是保留旧矩形覆盖其他窗口；只有屏外列也无法安置时才进入异常未平铺。屏外导航继续使用明确、可预测的 `fit`，本次不扩张为自由手势。

## Solution

保留 Agent 桌面的“屏内确定性平衡二叉分裂＋容量外屏外滚动带”混合模型、8 窗屏内上限和约 `320×240` 逻辑像素的基础最小窗格约束，扩展容量溢出的判定：真实应用无法接受分裂后的目标窗格，也是一种容量条件，不再直接等同异常未平铺。

当一次新增导致的分裂对新窗或任一既有相关窗口不可行时，由本次新窗进入屏外滚动带；既有成员保持原窗格、实际几何与顺序。屏外列仍提供约半屏宽、全平铺高度的可用空间。若新窗连屏外列也无法接受，才归为异常未平铺，并保留可诊断、有限重试的终局。

屏外交互维持现有契约：露边点击、任务栏等普通激活、前台新窗与前台还原执行最小位移 `fit`；后台新窗不移动视口。本次不加入滚轮、触摸板横滑、自由平移或纯 scrolling 布局替换。

先用低敏诊断和真实 Electron 应用回归取得故障证据，再实施修复。诊断只记录窗口句柄、低敏计数、恢复状态、目标与实际矩形及写窗结果，不记录窗口标题、缩略图或对话内容。

## User Stories

1. 作为 Agent 桌面用户，我希望 1 扇合格窗口铺满平铺区，以便现有单窗体验保持不变。
2. 作为 Agent 桌面用户，我希望 2–4 窗在尺寸允许时继续按既定顺序分裂，以便保留既有空间记忆。
3. 作为 Agent 桌面用户，我希望 5–8 窗在所有相关应用均接受目标尺寸时继续稳定落格，以便本次修改不制造额外溢出。
4. 作为 Agent 桌面用户，我希望屏内仍最多容纳 8 个窗格，以便既有容量上限不被悄然改变。
5. 作为小屏或高缩放用户，我希望约 `320×240` 逻辑像素的基础最小窗格约束继续优先生效，以便系统不会为了凑满 8 窗而无限缩小。
6. 作为打开新窗的用户，我希望新窗自身无法接受分裂目标时进入屏外滚动带，以便它不会停在打开时的原矩形上遮挡别人。
7. 作为已有窗口的用户，我希望新增窗口导致的缩小落在既有窗口可用尺寸之下时，新窗进入屏外滚动带，以便我的既有窗口不被异常化或留在半分裂状态。
8. 作为 Agent 桌面用户，我希望分裂涉及任一相关窗口不可行时都由本次新窗入带，以便规则简单且结果可预测。
9. 作为 Agent 桌面用户，我希望容量降级后既有成员的窗格和顺序保持不变，以便当前工作上下文不被新窗打断。
10. 作为 Agent 桌面用户，我希望因尺寸约束入带的窗口仍是受管平铺成员，以便它计入胶囊、预览和恢复，而非变成未平铺窗口。
11. 作为 Agent 桌面用户，我希望任何非例外的受管窗口都不保留旧大矩形覆盖其他窗格，以便平铺结果具备空间可信度。
12. 作为 Agent 桌面用户，我希望屏外列继续约为平铺区半宽并占满平铺高度，以便真实应用获得比细小窗格更可用的面积。
13. 作为小屏用户，我希望屏外列宽继续遵守最小 320 逻辑像素且不超过平铺区宽度，以便极窄屏规则保持一致。
14. 作为 Agent 桌面用户，我希望屏外带出现后仍露出约 32 逻辑像素的边缘，以便我能发现屏外成员。
15. 作为点击露边的用户，我希望目标窗按 `fit` 刚好完整可见，以便导航不移动过头。
16. 作为经任务栏激活屏外窗的用户，我希望使用与露边点击相同的 `fit`，以便不同入口不产生矛盾位置。
17. 作为从屏外窗返回屏内窗的用户，我希望反向激活遵循同一最小滑动规则，以便双向导航对称。
18. 作为打开前台新窗的用户，我希望新窗入带后自动完整滑入，以便立即继续操作。
19. 作为有后台新窗出现的用户，我希望后台窗只追加到屏外带右端而不移动视口，以便当前工作不被打断。
20. 作为激活已完整可见窗口的用户，我希望视口保持不动，以便最小位移规则不会制造无谓移动。
21. 作为使用窗口预览的用户，我希望选择屏外成员仍直接进入 Agent 聚焦，以便既有聚焦工作流保持不变。
22. 作为退出 Agent 聚焦的用户，我希望恢复混合布局并 `fit` 刚退出的窗口，以便上下文连续。
23. 作为关闭屏内窗的用户，我希望兄弟吸收与最早屏外成员补入规则继续生效，以便释放容量后的行为可预测。
24. 作为关闭屏外窗的用户，我希望滚动带只收拢列且不留空白视口，以便其他窗口的生命周期不打断当前工作。
25. 作为最小化窗口的用户，我希望原窗格或屏外顺序被保留，以便还原后回到原来的工作上下文。
26. 作为前台还原窗口的用户，我希望该窗自动 `fit` 完整可见，以便无需手动寻找。
27. 作为后台还原窗口的用户，我希望当前视口不动，以便后台状态变化不抢占上下文。
28. 作为点击恢复平铺的用户，我希望收回浮动窗并保留有效锚窗，以便恢复操作不会无故跳回起点。
29. 作为干净重启面板的用户，我希望布局关系与锚窗按既有规则恢复，以便本次容量扩展不引入第二套持久账。
30. 作为异常重启后面板的用户，我希望继续按当前合格窗口重建布局，以便旧模型不会永久停用平铺。
31. 作为改变分辨率或 DPI 的用户，我希望按当前显示条件重新评估容量与几何，以便旧会话的像素经验不会把布局锁死。
32. 作为升级或更换应用的用户，我希望应用尺寸能力证据不跨会话持久化，以便过期约束不会永久影响新窗口。
33. 作为明确授权手动浮动的用户，我希望浮动窗仍可覆盖平铺窗，以便既有手动工作流不被破坏。
34. 作为使用固定尺寸应用的用户，我希望真正无法安置的窗口仍明确标为异常未平铺，以便系统不伪称它已受管落位。
35. 作为使用权限受限应用的用户，我希望系统拒绝写窗仍与尺寸容量问题分开记录，以便诊断不会把所有失败混成一种原因。
36. 作为使用异常应用的用户，我希望连屏外列也无法接受时才进入最终异常态，以便轻量尺寸约束不会过早放弃平铺。
37. 作为 Agent 桌面用户，我希望写窗重试仍然有界，以便异常应用不会造成无限写入或事件风暴。
38. 作为 Agent 桌面用户，我希望状态投影以真实矩形回读为准，以便规划成功不会掩盖实际遮挡。
39. 作为维护者，我希望故障当拍能看到目标矩形、实际矩形和写窗结果，以便区分尺寸夹取、权限拒绝与异步时序。
40. 作为维护者，我希望诊断能呈现 `count/placed/overflow/anomalyDetail/recoveryReason`，以便区分候选退出、屏外形成与恢复安全态。
41. 作为注重隐私的用户，我希望新增诊断不记录窗口标题、缩略图、项目名或对话内容，以便可诊断性不扩大隐私边界。
42. 作为维护者，我希望同一窗口、焦点与几何事件序列产生相同的最终矩形和屏外顺序，以便回归可以稳定复现。
43. 作为真实 Electron 应用用户，我希望 ZCode、Kimi Code 等实际应用纳入回归观察，以便理想 WPF 夹具不再成为唯一真机证据。
44. 作为真实应用用户，我希望自动验收同时保留可控最小尺寸夹具，以便偶发问题能转成确定性回归而不是依赖某台机器上的应用版本。
45. 作为普通桌面用户，我希望普通桌面继续保持零自动平铺改窗，以便修复不扩大托管范围。
46. 作为非托管虚拟桌面用户，我希望自己的窗口不受新容量规则影响，以便现有工作区保持独立。
47. 作为使用副屏的用户，我希望副屏归属与移出主屏语义保持不变，以便屏外滚动带不会吞并真正的副屏窗口。
48. 作为使用顶部胶囊与窗口预览的用户，我希望屏外成员继续被计数和列出，以便导航不会遗漏正在运行的应用。
49. 作为 Agent 桌面用户，我希望窗口事件后仍在既有性能预算内稳定，以便尺寸回退不会变成可感知的持续抖动。
50. 作为维护者，我希望测试只断言外部可见矩形、成员计数、视口、异常分类和事件，以便实现重构不会迫使测试绑定私有结构。

## Implementation Decisions

- **保留单一混合布局账**：屏内树、分裂队列、屏外顺序、成员加入序与视口锚仍属于同一个 Agent 平铺状态；不引入第二种“尺寸溢出窗口”身份，也不另建成员账。
- **扩展容量溢出的含义**：容量条件包含既有 8 窗上限、基础最小窗格，以及真实应用对分裂目标的实际尺寸约束。因该约束入带的窗口仍是受管平铺成员。
- **两级安置降级**：先尝试正常分裂；相关窗口不可接受分裂目标时，由本次新窗转入屏外列；屏外列也不可达标时才进入异常未平铺。不得保留新窗原始矩形冒充布局成功。
- **新窗承担回退**：无论不可行约束来自新窗还是既有相关窗口，本次新窗都进入屏外带；既有成员保持分裂前的目标几何、树形与相对顺序。
- **以真实写窗事实学习约束**：不虚构一个 Windows 并未对外提供的通用“读取任意应用最小尺寸”能力。服务以写入后的实际矩形回读识别目标未达成，并通过屏外安置结果区分可恢复的容量问题与最终异常。
- **失败分类保持分轴**：系统拒绝写窗继续记为权限/系统类异常；受理但矩形不达标先允许屏外容量回退；位置或尺寸仍被钉死、屏外目标也失败时保留最终异常分类。不得把所有 `refused` 都无条件解释为最小尺寸。
- **分裂回退必须收敛**：若既有窗已在尝试中移动，回退到分裂前目标并逐窗回读；回退失败必须进入明确异常并报告，不能只恢复账面树而留下实际半分裂几何。
- **约束证据只在当前会话**：可缓存当前窗口已观察到的可行/不可行几何证据以避免重复撞墙，但不写入布局文档；窗口消失、桌面失活、显示参数变化或异常重建时按既有生命周期清理或重新评估。
- **有界且防抖**：每轮分裂尝试、回退和屏外安置均有有限写入预算；布局自身写入、回退与整组 `fit` 继续与真实用户几何手势分流，不消费手动几何授权。
- **状态投影诚实**：正常激活且非安全态下，成员应清晰分为屏内落格、屏外带、手动浮动与最终异常；屏外带数量不得因尺寸回退被误报为异常，恢复安全态也不得伪装成已经形成屏外带。
- **导航入口不变**：继续由系统前台变化汇入统一 `fit`；新窗入带的前台/后台差异、锚窗恢复、关闭补入、最小化、聚焦退出和恢复平铺沿用 ADR-0028。
- **低敏诊断增强**：在现有事件出口记录有界的写窗/回退结果、窗口句柄、目标与实际矩形、异常类别及恢复状态；不新增窗口标题或图像字段。状态读取继续复用现有平铺投影。
- **持久格式不扩张**：布局仍持久化成员关系、树形、屏外顺序、锚窗与浮动记录，不持久化临时尺寸能力证据或手动几何授权。
- **文档同步而非另起平行决策**：修订 GLOSSARY 中容量溢出与异常未平铺的边界，并修订 ADR-0028 的真实应用容量降级决策；Hyprland 只作参考来源，不成为运行依赖。

## Testing Decisions

- **最高主测试缝沿用 Agent 平铺服务的假窗口 harness**：从窗口事实、前台事件、几何写入与真实回读驱动服务，断言最终实际矩形、屏内/屏外数量、异常分类、授权事件与视口，不绑定私有树节点或内部调用次数。
- **先取得红色回归**：构造宽屏第 5 窗分裂，使新窗或既有窗对约 640 物理像素宽目标的回读被最小尺寸夹取；旧实现应表现为异常化/旧矩形残留，新实现必须让第 5 窗入带、既有四窗逐像素不动且零误授权。
- **覆盖两类约束来源**：分别让新窗自身和既有被分裂窗拒绝目标，验证两条路径都由新窗入带，且最终外部行为一致。
- **覆盖最终异常**：让目标窗连半屏宽屏外列也不接受，断言有限写入后进入异常未平铺；系统直接拒绝写窗与矩形夹取分别断言，不混成同一原因。
- **覆盖回退失败**：若既有窗已移动但回退未达标，断言实际异常与诊断被报告，不能仅凭树形恢复判为成功。
- **保留容量与生命周期矩阵**：覆盖 1、2、4、5、6、8、9、10 窗，小屏提前入带、混合最小尺寸约束、关闭补入、列收拢、最小化/还原、前后台新窗、双向 `fit`、恢复平铺和聚焦退出。
- **覆盖会话边界**：窗口消失与同句柄新身份、桌面切出/返回、干净重启、异常重建、分辨率/DPI 变化后均重新核对实际几何；尺寸能力证据不得泄漏到新身份或跨重启复用。
- **纯几何仍只在既有规划函数缝验证**：8 窗上限、基础最小窗格、列宽、露边和 `fit` 公式不下沉成服务私有断言；真实应用写窗反馈不得只由纯函数测试冒充覆盖。
- **真机只验证单测无法证明的面**：真实 Win32 写入/回读、应用最小尺寸夹取、露边输入、系统前台、虚拟桌面归属与面板重启继续由现有 Agent 平铺生命周期电池承证。
- **真实 Electron 应用与可控夹具分工**：ZCode、Kimi Code 等真实应用用于发现理想夹具之外的兼容性；可控最小尺寸夹具用于确定性复现。真实应用某轮可正常缩放不等于已证明缺陷根因，也不得用它替代红色回归。
- **优先扩展现有电池而不新建框架**：若新增真实最小尺寸真机段，必须满足增段三条件、绑定本工单、登记失效面/域标签/时长并更新文本审计链；真实应用探索性取证可先走既有实验入口，不直接放宽合并门。
- **诊断测试只断言低敏字段**：事件包含目标/实际矩形与结果，不包含窗口标题、缩略图或对话内容；日志关闭时不应为诊断额外常驻采集敏感信息。
- **完整验证门**：构建、类型检查、相关单元测试、全量单元测试与受影响真机验收段全部通过；真机入口一律经 accept-guard，任何 flaky 不得通过删除、跳过或放宽断言处理。

## Out of Scope

- 不新增滚轮、触摸板横滑、自由平移视口或速度投影手势。
- 不从第一个窗口起改成 Hyprland/Omarchy 式纯 scrolling，也不把 dwindle 的焦点/鼠标驱动分裂引入本地确定性模型。
- 不修改 8 窗屏内上限、基础约 `320×240` 逻辑像素约束、半屏列宽或约 32 逻辑像素露边的既有数值。
- 不支持逐列调宽、手工屏外列排序或新的窗口预览选择语义。
- 不持久化应用尺寸能力证据，不改变手动几何授权的持久化边界。
- 不提升权限强改窗口，不隐藏或最小化异常窗口来伪造布局成功。
- 不改变普通桌面、非托管虚拟桌面、副屏窗口、Agent 聚焦或分屏会话的既有契约。
- 不引入 Hyprland 运行依赖，不把 compositor 的渲染、输入或客户端配置能力假设为 Windows 外部面板已有能力。
- 不新增记录窗口标题、项目名、缩略图或对话内容的日志。
- 不通过删除、跳过或放宽既有失败断言制造绿色验收。

## Further Notes

- 本次共识经逐项确认：保留现有 `fit` 交互；真实应用尺寸约束触发屏外安置；先补低敏诊断和真实 Electron 回归；新窗承担分裂回退；屏外也失败才最终异常化。
- 已取得的基线证据：相关纯几何/服务测试 138 项通过；真机 Agent 平铺生命周期轮 14/14 通过，覆盖 5、6 窗精确几何、第 9 窗入带、露边真点击和反向激活。该证据使用的是理想夹具，不能否定真实应用现场。
- 真实面板最后留下的 5 窗布局为干净状态、屏外带为空；仍存活的 4 扇真实应用矩形与目标吻合。因此真实应用的间歇性堆叠尚未在故障当拍复现，实施时必须先用新增诊断定责，不得把“最小尺寸拒改”写成已证实的唯一根因。
- 当前代码事实支持优先排查该机制：写窗两次未达标会异常化，异常窗退出平铺候选并保留当前几何；候选减少也会推迟屏内 8 窗上限的到达。安全态停写与异步改窗时序仍是需要由 `recoveryReason` 和矩形时序排除的备选原因。
- Hyprland 一手源码研究见 `research/hyprland-tiling-scrolling.md`：dwindle 没有本地所需的最小尺寸保障；核心 scrolling 的最小位移 `fit`、有序列账、真实几何目标与当前值分层可借鉴，自由手势则属于显式配置能力。
