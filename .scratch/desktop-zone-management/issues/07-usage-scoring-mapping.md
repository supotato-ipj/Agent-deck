# 07: 频次打分与图标映射

**What to build:** 把 06 积累的日志变成推荐能用的排名。交付打分纯函数：输入启动事件序列与一个固定的"当前时间"，输出每个进程路径的使用频次分数，公式为**真启动次数 × 指数时间衰减，半衰期 14 天**。

同时交付两个数据源的处理：

- **冷启动先验**：读取系统现成的应用启动记录（值名为 ROT13 编码、值为 72 字节二进制），折算成先验分数与自建日志融合。**必须保证自建日志为空的第一天，推荐仍能产出非空排名**——否则功能上线头几天看起来是坏的。融合权重随日志积累逐步向自建日志倾斜。
- **进程路径 → 桌面图标映射**：用 01 已具备的快捷方式目标解析能力反查。映射不上的进程**仍记录、但不进入排名**，以免噪声污染推荐。

打分是纯函数，衰减计算不读系统时钟（时间由调用方传入），因此可精确断言。

**Blocked by:** 01, 06

**Status:** ready-for-agent

- [ ] 打分是纯函数，当前时间由参数传入而非内部读取
- [ ] 单测断言：距某次启动恰好 14 天时，该次启动的贡献分数为初始值的一半
- [ ] 单测断言：多次启动按各自时间独立衰减后求和
- [ ] 系统现成启动记录被读取并折算为先验分数，ROT13 值名与二进制值被正确解析
- [ ] 单测断言：自建日志为空时，排名仍非空（来自先验）
- [ ] 单测断言：自建日志充足时，先验权重被压过
- [ ] 进程路径能经快捷方式目标反查到桌面图标项
- [ ] 映射不上的进程不出现在排名结果中，但仍保留在日志里
- [ ] 本机 `Prefetch` 未被用作数据源
- [ ] 该分数只用于应用区推荐，不参与文档区排序（文档区一律用修改时间）
