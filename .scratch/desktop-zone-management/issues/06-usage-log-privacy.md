# 06: 使用日志采集与隐私边界

**What to build:** 让数据服务开始积累一手的"我在用什么应用"记录，为后续推荐提供数据。在既有的 1Hz 采样循环上增加两路采集：前台窗口轮询，以及进程集合差分（用于识别"进程从无到有"这一真启动事件）。

**本票的核心是一条隐私边界**：日志**只落盘进程可执行路径与时间戳，严禁记录窗口标题**。用户的日常工作是法律案件调研，窗口标题里经常直接带着案号、当事人名称、项目名。这条边界必须有测试守着，防止日后被"顺手加上"。见 ADR-0002。

日志按 90 天滚动清理，存放在本地应用数据目录下服务的专属子目录，不落在代码目录内。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 采集前台窗口对应的进程可执行路径
- [ ] 通过进程集合差分识别真启动事件（进程从无到有计一次）
- [ ] 日志每条记录仅含进程可执行路径与时间戳
- [ ] **隐私回归断言：日志文件中不得出现窗口标题字段**，该测试常驻
- [ ] 采集路径上不获取窗口标题文本（不是"获取了但不写"）
- [ ] 90 天滚动清理生效，超期记录被删除
- [ ] 日志存放在本地应用数据目录，不在代码目录内
- [ ] 日志写入失败不影响数据服务既有的 `/performance` 与 `/deck` 契约
- [ ] 采集开销不使既有 1Hz 采样循环明显退化
- [ ] 实机验证：正常用机一段时间后日志文件有内容，且字段集合符合上述约束
