# 06: 使用日志采集与隐私边界

**What to build:** 让数据服务开始积累一手的"我在用什么应用"记录，为后续推荐提供数据。在既有的 1Hz 采样循环上增加两路采集：前台窗口轮询，以及进程集合差分（用于识别"进程从无到有"这一真启动事件）。

**本票的核心是一条隐私边界**：日志**只落盘进程可执行路径与时间戳，严禁记录窗口标题**。用户的日常工作是法律案件调研，窗口标题里经常直接带着案号、当事人名称、项目名。这条边界必须有测试守着，防止日后被"顺手加上"。见 ADR-0002。

日志按 90 天滚动清理，存放在本地应用数据目录下服务的专属子目录，不落在代码目录内。

**Blocked by:** 01

**Status:** ready-for-agent

- [x] 采集前台窗口对应的进程可执行路径
- [x] 通过进程集合差分识别真启动事件（进程从无到有计一次）
- [x] 日志每条记录仅含进程可执行路径与时间戳
- [x] **隐私回归断言：日志文件中不得出现窗口标题字段**，该测试常驻
- [x] 采集路径上不获取窗口标题文本（不是"获取了但不写"）
- [x] 90 天滚动清理生效，超期记录被删除
- [x] 日志存放在本地应用数据目录，不在代码目录内
- [x] 日志写入失败不影响数据服务既有的 `/performance` 与 `/deck` 契约
- [x] 采集开销不使既有 1Hz 采样循环明显退化
- [x] 实机验证：正常用机一段时间后日志文件有内容，且字段集合符合上述约束

## Comments

- 2026-09-23: 由 to-tickets 创建。本机 `C:\Windows\Prefetch` 是空目录（预取被禁用），不得作为数据源；系统现成的应用启动记录仅有约 4 条，只能作冷启动先验（07 处理）。
- 2026-09-23: 实施完成。产物：`usage_log.py`（`detect_starts` / `detect_focus` 纯函数、按天 JSONL 的 `append`/`prune`、`foreground_exe` 只取进程路径、`Collector`、独立 CLI）、`server.py` 新增 `_usage_collector` 守护线程（2s 一轮，**不占用 1Hz 采样循环**）。`tests/test_usage_log.py` 含常驻隐私断言（源码不得出现 GetWindowText / 标题字段；记录键集合恰为 {ts, exe}）。全套 91 测试绿。
- 2026-09-23: **记录形状的设计取舍**：票面要求"每条记录仅含进程可执行路径与时间戳"，而 07 的"真启动次数"又必须能把 start 与 focus 区分开。解法是**两类事件各写各的按天文件**（`start-YYYYMMDD.jsonl` / `focus-YYYYMMDD.jsonl`），每条记录严格只有 ts 与 exe，不引入第三个字段。
- 2026-09-23: 实机 30s 采集验证：`%LOCALAPPDATA%\qoder-deck\usage\` 下出现 start/focus 两个文件，focus 记到前台应用、start 记到差分新进程；记录字段集合恰为 {ts, exe}。重启服务后 `/deck` 200，4 秒内 `history.cpu` 增长 5 点，1Hz 采样无退化。
- 2026-09-23: **给 07 的前置提醒**：实机 start 事件里大量是短命工具进程（head/grep/rg/pip 等）。07 计分前必须先按"能经 .lnk 目标映射到桌面图标"过滤，否则噪声会主导排名；映射不上的仍记录但不参与排名（spec 已定）。
