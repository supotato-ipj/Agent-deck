# 09: 事件驱动增量编排与漂移纠正

**What to build:** 让分区自己维持，而不必每次手动下命令。监控用户桌面与公共桌面两个目录，**仅在新增或删除时**触发编排；增量编排自动落位，不需要人工确认。

漂移纠正策略是本票的核心：**只管新出现的项**。用户手动摆过的应用区图标不移动——服务不和用户抢鼠标。**文档区豁免此保护**：它是服务托管区，新增一项会移动同组后续项（级联编排），这是预期行为而非 bug。

明确**不做常驻轮询纠偏**。

**Blocked by:** 05, 08

**Status:** ready-for-agent

- [ ] 目录事件监控同时覆盖用户桌面与公共桌面
- [ ] 仅新增/删除触发编排；无关的文件内容修改不触发
- [ ] 增量编排自动落位，无需人工确认
- [ ] 实机验证：桌面新建一个文档 → 数秒内自动出现在文档区所属组的正确位置
- [ ] 实机验证：删除该文档 → 文档区自动收紧、不留空洞
- [ ] 实机验证：手动拖动一个应用区图标到别处 → 服务不把它拖回
- [ ] 实机验证：手动拖动一个文档区图标 → 下一次文档区编排时它被归位（豁免保护）
- [ ] 图标视图句柄不可用（explorer 重启中等）时静默跳过本次编排并记录，不抛错
- [ ] 跳过编排不影响数据服务既有的 `/performance` 与 `/deck` 契约
- [ ] 事件风暴（一次性拷入大量文件）被合并为一次编排，不逐项触发
- [ ] 每次自动落位前仍写运行前快照，还原命令始终可用
- [ ] 不移动、重命名或删除任何磁盘文件
