# Spec: DESKTOP ZONES — 桌面分区管理（图标编排）

Status: ready-for-agent

## Problem Statement

桌面上同时堆着常用应用快捷方式和随手下载/生成的文档，混成一列。找某个应用要在十几个图标里扫，找某个文档更难；新落到桌面的文件会随手一放，越积越乱。用户希望桌面自己"分区"：常用应用固定在上部、按使用频次自动把最该顺手的补进来，文档归集到下部并按类型成列——同时**不接受**任何会移动、重命名或藏起磁盘文件的做法（会打断硬编码路径、网盘同步与肌肉记忆），也不接受一个会和自己抢鼠标、把手动摆好的图标又拖回去的服务。

## Solution

在既有数据服务内增加一个**桌面图标编排**能力：读取真实桌面图标清单，按归类规则与几何常量算出一份 `name → (x,y)` 的编排计划，再通过 explorer 图标视图的 Win32 消息把真实图标落位。桌面因此呈现两个分区——上部**应用区**（12 个栏位，手钉优先、推荐按使用频次填补剩余空位）与下部**文档区**（按扩展名动态成组、每组一列、组内按修改时间新在上）。壁纸侧不画任何分区边框，只在两区之间的空行加一行极小灰字标签说明方位。

磁盘文件一个都不动，只动图标坐标。首次全量编排走 dry-run，看过计划再显式 apply；之后由目录事件驱动做单项增量，自动执行。任何写入前先做布局快照，可一键还原到出厂态。

## User Stories

1. 作为桌面用户，我想把常用应用列进手钉清单，以便它们稳定占据应用区最靠前的栏位。
2. 作为桌面用户，我想手钉项永远排在推荐项之前，以便我的显式意图不被算法覆盖。
3. 作为桌面用户，我想系统按使用频次把常用应用自动填进手钉之外的空栏位，以便不用手动维护也能顺手。
4. 作为桌面用户，我想推荐项**只填空位、绝不顶替手钉**，以便我钉住的东西永远不会被挤掉。
5. 作为桌面用户，我想在 12 个栏位被手钉钉满时推荐自动不出现，以便应用区不会溢出到别处。
6. 作为桌面用户，我想推荐排名按"真启动次数 × 时间衰减（半衰期 14 天）"计算，以便推荐反映的是最近的habit而非历史遗留。
7. 作为桌面用户，我想在功能第一天就能看到有意义的推荐（来自系统现成的应用启动记录作冷启动先验），以便不必空等日志积累。
8. 作为桌面用户，我想随着自建使用日志积累，推荐逐渐由一手数据主导，以便推荐越来越贴合我当前的用法。
9. 作为桌面用户，我想桌面上的文件（非快捷方式）被归集到下部文档区，以便上部只剩应用入口。
10. 作为桌面用户，我想文件夹也归入文档区，以便"快捷方式以外都归集"这条规则没有例外。
11. 作为桌面用户，我想文档区按扩展名分组成列（文件夹 → Office → PDF → 图片 → 压缩包 → 其他），以便同类文档相邻。
12. 作为桌面用户，我想当前没有该类型文档时那个组不占列，以便不出现空列浪费横向空间。
13. 作为桌面用户，我想组序固定而非按数量动态变化，以便每个类型的位置可预测、能形成肌肉记忆。
14. 作为桌面用户，我想每个文档组内按修改时间新在上，以便我刚下载/刚生成的那个文件在第一格。
15. 作为桌面用户，我想单个文档组超过 8 行时折到右侧相邻列，以便文档区不会长到屏幕底部之外。
16. 作为桌面用户，我想新文件落到桌面时被自动归位到所属文档组，以便不必手动整理。
17. 作为桌面用户，我想删除文件后文档区自动收紧，以便不留空洞。
18. 作为桌面用户，我想文档区内的级联移动被允许（它是服务托管区），以便分组始终连续可读。
19. 作为桌面用户，我想**我自己手动摆过的应用区图标不被服务移动**，以便服务不和我抢鼠标。
20. 作为桌面用户，我想回收站被移到屏幕左下角，以便它远离常用区、减少误点，同时把 `(13,2)` 让给应用区首格。
21. 作为桌面用户，我想在两分区之间的空行看到一行极小灰字标签（形如 `▲ APP 12 栏位 ／ ▼ DOC 按类型分列`），以便不靠猜就知道上下各是什么区。
22. 作为桌面用户，我想分区标签落在没有任何图标格的空行里，以便它不被不透明的图标和文件名压住。
23. 作为桌面用户，我想壁纸上不出现任何分区边框或底色，以便 QODER DECK 已定稿的极简形态不受影响。
24. 作为桌面用户，我想任何图标都不落入右栏避让线以右，以便 DECK 的会话列表与硬件读数不被遮挡。
25. 作为桌面用户，我想首次运行只打印编排计划（每项 `name → 目标 (x,y)`）而不真动，需我显式确认才落位，以便一次移动十几个图标的动作是可预期的。
26. 作为桌面用户，我想之后的单项增量自动执行、无需我下命令，以便"自动归集"真的自动。
27. 作为桌面用户，我想每次编排前自动留下一份布局快照，以便排错了能退回上一步。
28. 作为桌面用户，我想有一份在任何写入之前完成的出厂态快照，以便无论怎么折腾都能回到最初的样子。
29. 作为桌面用户，我想用一条还原命令把桌面恢复到出厂态或上一次运行前态，以便这个功能敢被打开。
30. 作为桌面用户，我想磁盘上的文件一个都不被移动、重命名或删除，以便硬编码路径、网盘同步与我的肌肉记忆全部不受影响。
31. 作为桌面用户，我想推荐**不会为了上榜而在桌面新建快捷方式**，候选只限桌面上已有的图标，以便服务不往我桌面写东西。
32. 作为桌面用户，我想中文文件名在全链路被正确处理，以便归类和落位不因编码出错。
33. 作为桌面用户，我想公共桌面上的共享快捷方式也参与归类，以便应用区完整（并接受其位置改动在本机全用户生效）。
34. 作为桌面用户，我想 `desktop.ini` 这类隐藏系统项永不被触碰。
35. 作为隐私敏感的用户，我想使用日志**只记录进程可执行路径与时间戳、绝不记录窗口标题**，以便案号、当事人名、项目名不会明文落盘。
36. 作为隐私敏感的用户，我想使用日志按 90 天滚动清理，以便它不会无限积累。
37. 作为桌面用户，我想映射不到桌面图标的进程仍被记录但不参与推荐，以便日志完整而排名不被噪声污染。
38. 作为桌面用户，我想编排中途失败时桌面不留在半截状态，以便不会出现"排了一半"的桌面。
39. 作为桌面用户，我想手钉清单和几何常量是可手改的配置文件并随代码存放，以便调整不必翻 AppData。
40. 作为桌面用户，我想使用日志与布局快照存放在本地应用数据目录，以便代码目录不被持续增长的个人数据污染。
41. 作为壁纸维护者，我想整个能力都在既有数据服务进程内、不新增常驻进程、不放宽看门狗条件，以便运维面不扩大。
42. 作为壁纸维护者，我想这个功能不引入任何 HTTP 写端点，以便不在本地开出无鉴权的写操作通道。

## Implementation Decisions

### 载体与部署

- 能力全部落在既有数据服务进程内，随壁纸共存亡；**不新增常驻进程**，**不放宽看门狗的拉起条件**（仍要求 WE 运行且端口空闲）。WE 未运行期间分区不工作，属可接受的已知限制。
- **不引入任何 HTTP 写端点**。壁纸在桌面上收不到点击（见 ADR-0001），编排由服务内部与命令行触发，因此数据服务保持 GET-only，`Access-Control-Allow-Origin: *` 的现状不构成新风险。
- 壁纸侧唯一改动：在 QODER DECK 页面加一行极小灰字分区标签。不加分区边框、不加底色、不加任何交互元素、不改右栏与既有信息模块。

### 桌面项采集与落位（I/O 适配层）

- 通过 explorer 的桌面图标视图控件读取项目清单：显示名、当前坐标、项类型；通过解析快捷方式的目标路径得到"进程可执行路径 → 桌面图标"的映射依据。
- 落位通过同一控件的设位置消息完成。跨进程读写需先在 explorer 进程内分配内存缓冲。
- **ctypes 调用必须为 64 位句柄显式声明 restype/argtypes**，否则访问违例（已实测踩过）。
- 全链路使用 Unicode（`...W`）API。**不得经由 shell/PowerShell 传递文件名**——控制台会把中文名输出成乱码。
- 采集范围包含用户桌面与公共桌面两处；`desktop.ini` 等隐藏系统项在采集阶段即被排除。

### 编排核心（纯函数，主接缝）

- 一个纯函数接收：桌面项清单、手钉清单、频次分数、几何常量；输出完整编排计划 `name → (x,y)`。不触碰 Win32、文件系统、注册表。
- 该计划对象同时就是 dry-run 的产物；apply 只是把它交给落位适配层。
- 计划内的分类结果（应用区/文档区/不动/回收站）一并携带，便于打印与断言。

### 归类规则

- `.lnk` / `.url` / UWP 应用项 → **应用区**。
- 普通文件与**文件夹** → **文档区**。
- 回收站 → 固定落左下角，不参与任何一区。
- `desktop.ini` 及其它隐藏系统项 → 永不移动。
- 文档组归属按扩展名映射到固定组序：文件夹 → Office → PDF → 图片 → 压缩包 → 其他。未出现的组不占列。未识别扩展名归"其他"。

### 几何常量

- 屏幕 `2560×1440`，显示缩放 100%（AppliedDPI=96），CSS px = 物理 px；任务栏占底部 48px，可用高度到 `y=1392`。
- 图标格垂直步长 98px、图标 48px。**水平列步长需在实施时实测确定**（当前仅知系统间距设置为 -1125 twips），实测后作为几何常量固化。
- **应用区**：6 列 × 2 行 = 12 栏位，行优先（第一行 = 最靠前的 6 个栏位），起点 `(13, 198)`。原 `(13, 100)` 于 2026-09-24 被实机截图推翻：#deck 有 2.2rem 上边距，顶栏底线实际在 y≈109，y=100 的晶格行会压线。原设计起点 `(13, 2)` 于 2026-09-23 实机截图被推翻：DECK 顶栏（4.6rem ≈ 74px）横跨整屏，首行图标会压住品牌字；100 是让开顶栏的最顶晶格行。
- **分区标签**：位于应用区与文档区之间的空行内，约 `(13, 420)`；该行不得有任何图标格。
- **文档区**：起点 `y≈492`；每组一列、组间空一列；组内列优先向下、按修改时间新在上；**单列上限 8 行**（末行 `y≈1178`），第 9 项起折到本组右侧相邻列。
- **回收站**：`(13, 1276)`。原设计 `(13, 1294)` 不在 98 晶格上，实机 apply 时被 explorer 吸附到 1276（由 apply 后读回校验抓到）；1276 是格底不超可用高度的最底晶格行。
- **硬约束**：所有落位坐标必须满足 `x < 1984`（右栏避让线 = 屏宽 − DECK 右栏 576px），且任何项的格底不得超出 `y=1392`。回收站除外（它固定在最底行）。

### 频次打分（纯函数，次接缝）

- 分数 = 真启动次数（进程从无到有计一次）× 指数时间衰减，半衰期 14 天。
- 两个数据源融合：系统现成的应用启动记录（UserAssist，ROT13 编码值名 + 72 字节二进制值）作**冷启动先验**；自建使用日志随积累逐步接管权重。融合权重与先验的折算方式在实施时定，但必须保证"日志为空的第一天仍能产出非空推荐"。
- 本机 `Prefetch` 目录为空（预取被禁用），**不得作为数据源**。
- 进程路径经快捷方式目标反查桌面图标；映射不上者记录但不进入排名。
- 该分数**只用于应用区推荐**。文档区排序一律用文件修改时间（见 ADR-0002 的后果）。

### 使用日志

- 采集：前台窗口轮询 + 进程启动事件。原设计写"对既有 1Hz 采样循环做进程集合差分"，2026-09-23 实施时改为**独立 2s 守护线程**（保证"采集开销不使 1Hz 采样退化"这条验收不再只是平凡满足），差分按 **pid** 而非可执行路径集合——否则同路径的第二实例与退出后重启都数不到，违背"进程从无到有计一次"。
- 落盘字段**仅限**进程可执行路径 + 时间戳。**严禁记录窗口标题**（ADR-0002）。
- 90 天滚动留存，超期清理。
- 存放于本地应用数据目录下的服务专属子目录。

### 触发与漂移纠正

- **事件驱动**：监控用户桌面与公共桌面目录，仅在新增/删除时触发编排。
- 漂移纠正 = **只管新出现的项**；用户手动摆过的应用区图标不移动。
- **文档区豁免此保护**：它是服务托管区，允许级联编排（新增一项会移动同组后续项，这是预期行为）。
- **不做常驻轮询纠偏**——那会和用户抢鼠标。

### 快照与回滚

- 每次编排前写一份布局快照（全部图标的 `name → (x,y)`）。
- **出厂态快照必须在任何一次写入之前完成**；若已存在则不覆盖。
- 提供还原命令，可选还原到出厂态或最近一次运行前态。
- 快照存放于本地应用数据目录下的服务专属子目录。

### 首次全量 vs 日常增量

- **首次全量编排默认 dry-run**：打印完整计划（含每项的分类与目标坐标），需显式 apply 参数才落位。
- 之后的事件驱动增量自动 apply（单项或单组级联），无需人工确认。

### 配置与数据存放分层

- **随代码存放**（用户会手改的）：手钉清单（应用显示名的有序数组）、几何常量。
- **本地应用数据目录**（机器自己写的）：使用日志、布局快照。
- 手钉清单为纯数据文件，改动后下次编排生效；不提供任何 GUI 或 HTTP 编辑途径。

### 失败处理

- 编排为"先算完整计划、再一次性落位"，不存在算一半就写的路径。
- 落位过程中任一项失败即中止后续写入并报告，桌面可能处于部分落位状态——此时还原命令可用（快照已在写入前完成）。
- 图标视图句柄找不到（explorer 重启中、或未来 Windows 变更了控件结构）时，静默跳过本次编排并记录，不抛错、不影响数据服务既有的 `/performance` 与 `/deck` 契约。

## Testing Decisions

- **主接缝 = 编排核心纯函数**。用合成的桌面项清单 + 手钉清单 + 分数 + 几何常量喂入，断言输出的计划。覆盖：归类正确性（.lnk/文件夹/desktop.ini/回收站）、手钉优先占前格、推荐只填空位且不顶替手钉、栏位钉满时推荐为空、文档组动态成列与固定组序、空组不占列、组内按修改时间新在上、单组满 8 行折列、回收站落左下角、所有坐标满足 `x<1984` 与 `y` 底界、中文显示名不被破坏。
- **次接缝 = 频次打分纯函数**。用合成的启动事件序列 + 固定"当前时间"喂入，断言：半衰期 14 天处的分数恰为初始一半、UserAssist 先验在日志为空时仍产出非空排名、映射不上的进程不出现在结果里。
- **不做单元测试的部分**：Win32 采集与落位、目录事件监控、快照落盘、使用日志采集。explorer 无法有意义地 mock；这些由实机冒烟验证。
- **实机冒烟**：沿用仓库既有的桌面截图脚本手法（最小化 → 截图 → 还原）。断言方式：(a) dry-run 打印的计划与读回的真实坐标一致；(b) apply 后重新读回坐标与计划一致；(c) 还原命令后坐标与出厂态快照一致；(d) 截图人工核对分区观感与标签可读性。
- **好的测试只断言外部行为**：计划的坐标与分类、日志文件的字段集合、快照文件的可还原性、截图观感。**不断言**内部函数划分、缓存策略、Win32 调用序列。
- **框架**：Python 标准库 `unittest`，不引入 pytest——服务除 psutil 外全是标准库，保持零新增依赖。
- **隐私回归断言**：使用日志文件内容中不得出现窗口标题字段——这条要有测试守着，防止日后被"顺手加上"。
- 仓库当前无任何测试基础设施，本 feature 需一并建立测试目录与运行方式。

## Out of Scope

- **移动、重命名、删除任何磁盘文件**；把文档归档进子文件夹。（需求边界，非技术取舍）
- **在桌面新建快捷方式**以让未上榜应用参与推荐；候选池只限桌面已有图标。
- **壁纸内的任何可点击 UI**、拖拽、输入框、iframe。平台限制见 ADR-0001。
- **任何 HTTP 写端点**（POST/PUT/DELETE）与随之而来的鉴权/CORS 收口工作。
- **常驻轮询强制归位**（会和用户抢鼠标）。
- **独立 GUI 进程 / 托盘程序 / 置顶窗口**来管理手钉清单。
- **"位置即意图"**（用户把图标拖进应用区即自动记为手钉）——已识别为体验最好的后续增强，本次不做。
- **文档级推荐**（哪个文档最常用）——被 ADR-0002 排除。
- **多显示器差异化布局**；本机仅一个显示器。
- **修改 Windows 自身的"自动排列图标"/"对齐到网格"设置**——当前实测两者均为关，服务只读检测，不擅自更改。
