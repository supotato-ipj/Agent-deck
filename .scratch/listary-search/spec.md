# Spec: DECK 壁纸内嵌 Listary 搜索面板

Status: ready-for-agent

## Problem Statement

桌面是用户的作战面板：QODER DECK 右窄栏实时呈现会话与硬件状态，桌面图标按分区/栏位编排。但文件搜索的入口却游离在壁纸之外——每次找一个文件，都要先用双击 Ctrl 或热键唤起 Listary 的悬浮小窗，再打字、再选结果。壁纸承载了「看状态」，却承载不了最常用的「搜一下」。用户要的是：搜索框就长在壁纸上，点它就能搜，不必再单独打开 Listary。

## Solution

QODER DECK 右窄栏顶部新增一个 SEARCH 面板（面板头与 SESSIONS 同款样式）。待机时它与壁纸视觉融为一体，看起来就是壁纸画出来的一个搜索框；点击即可直接打字（中文输入法原生可用），结果列表实时展开在输入框下方；↑/↓ 选择，Enter 打开文件，Ctrl+Enter 在资源管理器中定位所在文件夹，单击结果等同 Enter，ESC 或失焦即退回待机态。Listary 7 退居后台只当搜索引擎与索引（经其本地 HTTP API 查询），其原有热键、悬浮窗与 launcher 能力（应用启动、网络关键词跳转）原样保留、随用随取。引擎不可用时面板显示 ENGINE OFFLINE。

## User Stories

1. 作为桌面用户，我想让搜索框常驻 DECK 右窄栏顶部、与 SESSIONS 和硬件块同款风格，这样作战面板集齐「状态 + 搜索」两个入口。
2. 作为桌面用户，我想让搜索框待机时看起来就是壁纸的一部分（同字体、同色系、同分隔线），这样不产生「多开了一个软件」的杂质感。
3. 作为桌面用户，我想点击搜索框即可开始打字，这样省去先唤起 Listary 小窗的那一步。
4. 作为桌面用户，我想用中文输入法正常输入查询词，这样搜中文文件名不卡壳。
5. 作为桌面用户，我想边打字边看到实时刷新的结果，这样不需要按任何「提交」键。
6. 作为桌面用户，我想用 ↑/↓ 在结果间移动选中项，这样全键盘即可完成选择。
7. 作为桌面用户，我想按 Enter 直接打开选中的文件，这样一步到位。
8. 作为桌面用户，我想按 Ctrl+Enter 在资源管理器中打开所在文件夹并定位该文件，这样处理文档时能顺手归档或找同类。
9. 作为桌面用户，我想鼠标单击某条结果等同 Enter，这样不必把手挪回键盘。
10. 作为桌面用户，我想按 ESC 收起结果并退回待机态，这样桌面立刻恢复干净。
11. 作为桌面用户，我想点击桌面别处（失焦）时面板自动退回待机态，这样不用刻意去关。
12. 作为桌面用户，我想继续打字时选中项与结果列表随之更新，这样改词的成本为零。
13. 作为桌面用户，我想看到结果总数与当前列表规模，这样能分辨「没搜到」和「只显示了一部分」。
14. 作为桌面用户，我想空结果时看到明确的无结果提示而不是一片空白，这样不误判为故障。
15. 作为桌面用户，我想结果行显示文件名与路径（合理截断），这样同名文件能互相区分。
16. 作为桌面用户，我想结果默认约 8 行、面板不超出右窄栏宽度，这样不遮挡壁纸的其他信息模块。
17. 作为桌面用户，我想 Listary 引擎未开或未就绪时面板显示 ENGINE OFFLINE 而不是卡死，这样我知道该去开 Listary。
18. 作为桌面用户，我想引擎限流时面板静默退避、稍后自动重试，这样快速打字不会把面板打进错误态。
19. 作为桌面用户，我想查询词只发给本机回环地址上的 Listary API、绝不上网，这样隐私边界与数据服务的既有边界一致。
20. 作为桌面用户，我想我的查询词不进入本项目自建的使用日志，这样与「日志不含敏感内容」的既有约定一致。
21. 作为桌面用户，我想保留 Listary 原有全部热键与其自己的窗口（应用启动、网络关键词跳转），这样面板之外的能力一个不少。
22. 作为桌面用户，我想搜索框不占任何桌面分区/栏位、不参与编排，这样桌面图标的编排零扰动。
23. 作为桌面用户，我想重启电脑后搜索面板随既有自启链路自动就位，这样不需要手工拉起。
24. 作为桌面用户，我想数据服务重启后搜索面板自动回到待机态原位，这样状态可以自愈。
25. 作为数据服务维护者，我想搜索链路的纯逻辑（防抖、限流退避、结果模型、按键到动作的映射）可以离线测试，这样不依赖真机 Listary 就能做回归。
26. 作为数据服务维护者，我想验收电池能一键在真机端到端跑完主要路径并存证截图，这样每次改动后的复验成本极低。

## Implementation Decisions

- **目标壁纸是 QODER DECK**（当前主壁纸），本 spec 草稿早先的「TERMINAL 02」表述作废。DECK 右窄栏顶部新增 SEARCH 面板头与待机框视觉；固定落位、物理像素、不占栏位、不进编排（与分区标签同类）。若用户改用非 100% 缩放，对齐偏差为已接受的已知限制。
- **壁纸网页层只加静态视觉，完全不参与搜索链路**：数据服务维持 GET-only 与宽松 CORS 的既有形态，不新增写端点。
- **搜索面板是数据服务自有的常驻无边框窗口**（见 ADR-0003）：待机态以 DECK 同款视觉（等宽字体、既有前景色与分隔线色）伪装成壁纸静态视觉；点击激活为活动态；ESC/失焦退待机；窗口线程寄生于数据服务、与其共存亡，不新增进程。输入控件用系统原生控件以保证中文输入法可用。
- **搜索引擎是 Listary 7 本地 HTTP API**（用户已在本机启用；规格仅存于其应用内「选项 → HTTP API」对话框，调查中已抄录存档于本 feature 目录）。契约要点：
  - `POST http://127.0.0.1:38431/api/v1/search`，`Content-Type: application/json`；
  - 请求体：`query`（必填）、`limit`（默认 10、上限 100）、`offset`、`search_in`（目录数组）、`types`（取值 file/folder）、`extensions`；
  - 响应：`ok` 与 `data.results[]`（含 `path/name/type/size_bytes/modified_at/score`）、`data.total` 等；错误码含 `SEARCH_UNAVAILABLE`、`TOO_MANY_REQUESTS`、`REQUEST_VALIDATION_FAILED` 等；
  - API 仅监听 127.0.0.1、只读、**无 CORS、无 keep-alive**——因此调用方必须是数据服务（非浏览器上下文），且每次请求新建连接；因无 CORS 支持，壁纸网页层永不直连该 API（架构上已排除）。
- **节流策略**：输入防抖约 200ms；默认取约 8 条结果；遇 `TOO_MANY_REQUESTS` 静默退避重试。
- **操作集**：↑/↓ 移动选中；Enter 打开文件；Ctrl+Enter 资源管理器定位；单击等同 Enter；继续打字即更新；ESC/失焦退待机。打开与定位动作由数据服务执行（沿用其已有的无窗口子进程先例，避免控制台闪现）。
- **引擎离线态**：API 连接失败或 `SEARCH_UNAVAILABLE` 时，面板显示 ENGINE OFFLINE（呼应壁纸的 OFFLINE 徽章语言），不崩溃、不卡死，恢复后自动可用。
- **隐私边界**：查询词不写入自建使用日志（对齐 ADR-0002 的精神）；查询落入 Listary 自身 SearchHistory 属其原生行为，不做额外处理。
- **能力边界（防返工）**：Listary 7 API Phase 1 只读、仅文件/文件夹搜索。应用启动、网络关键词跳转不在面板能力内，继续走 Listary 原窗口与其热键——与「保留现有热键」的决定互补。
- **部署**：运行中的自启链路指向主检出，改动须到达主检出（或调整自启目标）；DECK 壁纸改动后 Wallpaper Engine 无热重载，需用其控制命令重载壁纸。

## Testing Decisions

- 好的测试只断言外部可见行为（窗口状态、结果渲染、打开/定位动作、结果模型的正确性），不断言内部实现细节。
- **主缝（真机验收电池，沿用既有验收先例）**：一键端到端——面板窗存在且几何落在右窄栏顶部 → 模拟点击激活 → 键入探针词 → 真实 API 返回 → 结果渲染 → Enter 打开验收专用的临时探针文件（造唯一名、搜它、验证打开、清理）→ Ctrl+Enter 验证资源管理器定位 → ESC/失焦退待机 → 复用桌面截图脚本存证到工单评论。
- **辅缝（纯逻辑离线测试，新增且尽量小）**：把「查询 → 防抖 → API 调用 → 结果模型 → 按键 → 动作」抽成不依赖 GUI 的可导入逻辑，用假 API 响应离线测；只覆盖真机上不可安全复现的分支：引擎离线、限流退避、空结果、offset 翻页、防抖窗口。
- 壁纸侧视觉对齐不设自动化缝，沿用截图人工核验的既有惯例。
- 先例：桌面分区的验收电池、自启重启验收记录、桌面/壁纸截图脚本。

## Out of Scope

- 不做应用启动与网络关键词跳转（API Phase 1 限定文件/文件夹搜索；这些能力继续走 Listary 原窗口）。
- 不新增唤起搜索面板的全局热键（点击已可达；后续要加成本很低）。
- 不改动 Listary 的任何设置、热键或窗口行为。
- 不把搜索历史、查询统计接进 DECK 或使用日志。
- 不做结果右键菜单、多选、拖拽等扩展操作（操作集以上述为准）。
- 不做 TERMINAL 02 版本的面板适配（若未来切回该壁纸再议）。

## Further Notes

- **为什么输入不进壁纸层**：Wallpaper Engine 官方唯一的网页键盘通道要求「URL 加载 + 隐藏桌面图标」，会摧毁建立在可见图标之上的桌面分区体系（ADR-0001 背景）；故输入面只能是服务窗口。
- **为什么是 V7**：实测 V6 的 `-search` 命令行只开空窗不预填、`listary://` 协议无查询参数、无任何 API——V6 上「把查询词带进 Listary」不存在可行路径。V7 本地 HTTP API 是官方为第三方工具预留的正道。探针证据脚本已存于本 feature 目录。
- **风险**：Listary 7 为 beta（HTTP API 有过崩溃修复记录），端口与契约以应用内对话框为准；正式版若变动，由验收电池兜底发现。
