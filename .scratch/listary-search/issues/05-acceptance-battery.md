**What to build:** 仿照桌面分区验收电池先例的一键验收脚本，作为本功能后续回归的主缝：面板窗存在且几何落位 → 模拟点击激活 → 键入探针词 → 真实引擎返回结果 → 结果渲染断言 → Enter 打开验收专用的临时探针文件（造唯一名、搜它、验证已打开）→ Ctrl+Enter 验证资源管理器定位 → ESC/失焦退回待机态 → 全程截图存证并追加摘要到本票评论。临时探针文件与验收中打开的资源管理器窗口在结束后自动清理/关闭；脚本可重复执行（幂等），任一步失败即非零退出并报告失败步骤。

**2026-09-25 22:2x 更正与根因（前述两块结论作废）**

1. **「MinimizeAll 重置面板几何」系误诊，作废**：那是一次 DPI 虚拟化量测
   误读——显示器切到 200% 缩放后，非 DPI 感知进程读 GetWindowRect 得到的
   是逻辑坐标（物理 1982,134,536 恰显示为 991,67,268）。面板几何从未被
   破坏。逐窗最小化设计保留（精确可逆），理由改为不动用户全部窗口。
2. **「跑绿阻塞于 200% 显示」也作废**：200% 下产品行为正常。电池当晚在
   200% 显示上跑出的真实失败，根因是产品缺陷（下条），与缩放无关。
3. **电池抓到的真缺陷（产品级，任何缩放下都在）**：
   `search_panel._clear_results` 只销毁 results_host 的子控件，而 Tk 的
   `winfo_reqheight` 在子控件销毁后不回缩（保留最大已布局值），
   `_apply_height` 于是在 ESC/失焦后把展开高度原样重设——**面板一旦出过
   结果，窗口高度永远不收回**。黑底叠黑壁纸视觉不可见，故一直无人察觉；
   窗口物理上持续遮住壁纸右侧对应区域。修法：`_clear_results` 改为销毁
   重建 results_host（新空 Frame 的 reqheight 为 1），高度回基线。
   隔离验证：Tk 最小复现确认「销毁子控件后 reqheight 不回缩、重建才回缩」；
   244 离线测试中 GUI 用例随即抓出修法自身的 host 捕获次序 bug（已修）。
   另：200% 下 ESC 经 SendKeys 正常到达（此前怀疑 IME 吞 ESC，误）。
