# Spec: QODER DECK — 自建 WE 桌面系统壁纸

Status: ready-for-agent

## Problem Statement

用户想要一套完全自制的"桌面系统"：以 Wallpaper Engine 壁纸形态常驻桌面，实时呈现多个 Qoder 会话的任务进展、当前任务在做什么、以及系统数据（含历史趋势）。继续改造 TERMINAL 02 已接近其布局框架极限，且创意工坊更新覆盖风险始终存在；用户希望布局完全自主、信息密度更高、有"系统感"。

## Solution

在 Wallpaper Engine 的 `projects/myprojects/` 下新建自有 web 壁纸项目（QODER DECK）：终端等宽字风格的全屏 HUD，分区呈现多会话列表、聚焦会话详情（任务进度 + 最近消息预览）、硬件仪表与 CPU/网速历史曲线。数据由既有本地数据服务扩展的新契约端点供给。新壁纸与 TERMINAL 02 并存试跑，用户满意后再切换为主力。

## User Stories

1. 作为桌面用户，我想在 WE 里看到名为 QODER DECK 的自有壁纸可选用，以便与 TERMINAL 02 并存试跑、随时切回。
2. 作为桌面用户，我想一眼看到所有活跃 Qoder 会话的并列列表（项目名 + 状态 + 任务进度），以便掌握并行工作的全貌。
3. 作为桌面用户，我想点击某个会话行将其设为聚焦会话，以便查看详情而不受其他会话干扰。
4. 作为桌面用户，我想看到聚焦会话当前任务的最近一条消息预览（assistant 文本或正在调用的工具名），以便知道 agent 此刻具体在做什么。
5. 作为桌面用户，我想 hover 会话行时展开其消息预览，以便不切换聚焦也能快速扫读。
6. 作为桌面用户，我想看到 CPU 与网络上下行的近 5 分钟历史曲线，以便识别负载趋势而非瞬时值。
7. 作为桌面用户，我想看到 GPU/VRAM/内存的即时仪表，以便掌握游戏与编译之外的资源余量。
8. 作为桌面用户，我想让整屏延续终端等宽字 HUD 风格，以便与既有审美一致。
9. 作为桌面用户，我想在没有任何活跃会话时看到明确的待机态，以便区分"没会话"与"服务挂了"。
10. 作为桌面用户，我想在数据服务未启动时壁纸其余部分（时钟、装饰）仍正常渲染，以便桌面不残废。
11. 作为桌面用户，我想让 QODER DECK 继承静态 HUD 透视观感（可开关），以便与 TERMINAL 02 的 helmet 感一致。
12. 作为桌面用户，我想让数据服务开机后随 Wallpaper Engine 自动拉起，以便无需手动启动。
13. 作为壁纸维护者，我想让新壁纸目录完全自有（不在创意工坊目录内），以便永不担心更新覆盖。
14. 作为壁纸维护者，我想让服务端单端口同时服务 TERMINAL 02 与 QODER DECK，以便少一个进程少一份运维。
15. 作为桌面用户，我想让多会话列表在会话结束（超过活跃窗）后自动消失，以便列表始终反映"现在"。

## Implementation Decisions

- **项目位置**：Wallpaper Engine 自有项目目录下的 `qoder-deck` 子目录（web 类型壁纸：project.json + index.html + 资源），不放入创意工坊目录；加载方式为 WE UI 选择或 openWallpaper 命令；不自动改 WE 当前壁纸选择（并存试跑）。
- **数据契约**：既有服务新增 `GET /deck` 端点，返回：`sessions`（活跃池内按最近活跃排序的会话数组，每项含 id、项目名、running、tasks_done、tasks_total、current_task、preview、preview_role、age秒）；`history`（CPU/下载/上传/GPU 四个环形缓冲数组，1Hz 采样、约 300 点）；`ts` 时间戳。原 `/performance` 端点保持不变供 TERMINAL 02 使用。
- **消息预览提取**：会话记录文件尾部倒扫，取最近一条 assistant/user 记录；优先其内容块中最后一个非空 text 块（截断约 100 字符）；无 text 块而为 tool_use 时预览为 `tool:<工具名>`；preview_role 标记 assistant/user。
- **历史缓冲**：服务内单一采样线程每秒追加 CPU、网速差值、GPU 利用率（GPU 走既有缓存查询）到环形缓冲；不持久化。
- **前端布局**：全屏网格——顶栏（标题 + 时钟 + 活跃会话计数）、左栏（多会话列表，点击聚焦、hover 展开预览）、主区（聚焦会话：状态灯、任务进度条列表、消息预览流）、底栏（硬件仪表 + 三条 canvas 历史曲线）。终端等宽字风格，字体资源从 TERMINAL 02 复制。
- **交互**：仅轻交互——会话行 hover 展开、点击切换聚焦；不做滚轮列表、拖拽、输入。
- **HUD 透视**：继承静态座舱环抱/俯倾（同 TERMINAL 02 常量量级），以壁纸属性开关，默认开。
- **容错**：/deck 任一数据源失败降级为空结构；壁纸端 fetch 失败时保留上一帧并显示离线角标。
- **自启**：完成看门狗方案收尾——启动文件夹快捷方式指向 pythonw 看门狗脚本（WE 运行且端口空闲即拉起服务）；服务端保留端口占用自检防双实例。

## Testing Decisions

- **服务端接缝**：curl 断言 /deck 契约——sessions 含当前会话且 preview 非空、history 数组随时间增长且长度上限 300、损坏会话文件被跳过、无活跃会话时 sessions 为空数组。
- **前端接缝**：浏览器打开新壁纸 index.html，evaluate 断言——会话行渲染数量与 /deck 一致、点击行后聚焦详情切换、hover 类切换、fetch 失败时离线角标出现。
- **实机验收**：openWallpaper 加载新壁纸 + 桌面截图；与 TERMINAL 02 切换对比由用户执行。
- 好的测试只断言外部行为（JSON 字段、DOM 状态、截图观感），不断言内部实现。

## Out of Scope

- 任务看板三列视图、滚轮滚动、拖拽面板等重交互。
- 创意工坊发布、多显示器差异化布局。
- 音乐控制、日历/待办面板。
- 替换 TERMINAL 02 为主力（用户试跑满意后另行操作）。
- 历史缓冲持久化与跨重启恢复。

## Further Notes

- 词汇沿用 CONTEXT.md：信息模块、会话活跃、数据服务；新词"聚焦会话"指当前被选中查看详情的会话。
- 环境事实：WE 的 myprojects 目录已存在；web 壁纸运行于 WE 内置 CEF；桌面被遮挡时壁纸页定时器暂停（曲线会停摆，恢复后继续，属预期）。
- 看门狗自启为本 spec 的收尾票，此前因用户改道中断于"启动文件夹快捷方式未落盘"一步。
