# Spec: AGENT DECK 独立面板——脱离 Wallpaper Engine 的桌面替代应用

Status: ready-for-agent

## Problem Statement

桌面是用户的作战面板：AI 工具会话状态、硬件指标、常用入口都该常驻桌面。但今天这套能力长在 Wallpaper Engine 的 web 壁纸上，有三个根本痛点：

1. **命脉在别人手里**：看门狗只在 WE 运行时拉起数据服务；HUD 透视开关藏在 WE 壁纸属性里；部署脚本硬编码 Steam 路径——WE 一关，面板全灭。
2. **桌面是死的**：web 壁纸收不到任何点击，搜索要靠寄生窗口，桌面项的承载仍由 Windows 桌面负责，而系统重排、分辨率变化会反复打乱图标布局（漂移纠正/布局快照只是补丁）。
3. **长不出生态**：用户无法自定义桌面组件，更谈不上热插拔——壁纸 + Python 服务的形态到头了。

用户要的是一个**替代原桌面的独立应用**：壁纸（系统的或 WE 挂的）只当背景，应用浮于其上，自己承载快捷方式与文件，把 Windows 桌面的承载职责接过来；终局是可热插拔、用户自定义的桌面组件。

## Solution

一个独立常驻应用「AGENT DECK 独立面板」：Electron 窗口宿主 + cordis 插件内核 + Vite 前端，TypeScript 全栈。面板浮于任意壁纸之上，背景透明，默认鼠标穿透、光标进入交互热区时临时接收点击；隐藏原生桌面图标，自扫描桌面文件夹并自绘承载桌面项（应用区以底部 dock 呈现，文档区按扩展名聚合）；信息以 Personal OS 风格的卡片网格呈现（时钟/天气/日历、五工具会话列表、Qoder 状态块、硬件指标），搜索框内嵌面板（Listary 本地 API 驱动），设置浮层内嵌面板。内置信息块本身就是第一批可热插拔的桌面组件，插件机制经真实组件自举验证。Python 数据服务、看门狗、Tk 搜索窗、WE 部署脚本全部退役。

## User Stories

### 层叠与窗口

1. 作为桌面用户，我想让面板浮于我自选的桌面壁纸（系统设置或 Wallpaper Engine 挂载均可）之上，这样壁纸归壁纸、作战面板归作战面板，互不迁就。
2. 作为桌面用户，我想让面板背景全透明、各信息卡底色透明度可调，这样透过面板能看到壁纸，而文字始终保持实色清晰。
3. 作为桌面用户，我想让面板默认不拦截鼠标——点击与右键直接落到桌面，这样桌面的既有习惯一点不变。
4. 作为桌面用户，我想让光标移到信息卡、dock、搜索框等交互热区时面板临时接收点击，这样「看」与「点」互不干扰。
5. 作为桌面用户，我想让面板永远压在普通应用窗口之下，这样开再多的程序也不会被一块「桌面」挡住。
6. 作为桌面用户，我想在 Win+D 收起桌面后面板防抖自动恢复，这样误触显示桌面不用手动找回面板。
7. 作为桌面用户，我想让面板随开机自启、进程消失后自愈重启，这样它像壁纸一样「一直在」。
8. 作为桌面用户，我想在面板异常退出时原生桌面图标被自动还原，这样永远不会面对一个空桌面。
9. 作为桌面用户，我想让屏幕几何（面板坐标、分区原点、dock 尺寸、分区标签位）进 config 且以当前值为默认，这样换机或改分辨率只调配置。

### 桌面承载

10. 作为桌面用户，我想让用户桌面与公共桌面的全部文件和快捷方式被扫描并由面板自绘呈现，这样桌面项一个不漏。
11. 作为桌面用户，我想让每个桌面项显示从 lnk/文件提取的真实图标，这样观感与原桌面无差。
12. 作为桌面用户，我想双击桌面项即启动它指向的文件或应用，这样肌肉记忆原样保留。
13. 作为桌面用户，我想单击桌面项呈选中态，这样启动前能确认目标。
14. 作为桌面用户，我想在分区内和跨分区拖拽桌面项摆位，这样布局由我做主。
15. 作为桌面用户，我想让新出现在桌面的桌面项被自动归类入区，这样新装的软件自己归位。
16. 作为桌面用户，我想让被删除的桌面项从面板同步消失，这样面板与磁盘永远一致。
17. 作为桌面用户，我想让原生桌面图标的显隐由面板管理（启动时确保隐藏），这样不会出现「两套桌面」。
18. 作为桌面用户，我想让手钉的应用入口稳定占据 dock 前段、不被推荐顶替，这样常用位永远顺手。
19. 作为桌面用户，我想让 dock 剩余栏位按使用频次（时间衰减加权）自动填补，这样越常用的越靠前。
20. 作为桌面用户，我想在自建使用日志尚空时借系统启动记录折算初始频次（冷启动先验），这样新装面板的 dock 不至于乱序。
21. 作为桌面用户，我想一键恢复出厂布局，这样摆乱了一键回魂。

### Personal OS 卡片

22. 作为桌面用户，我想以卡片网格 + 底部 dock 的形态组织面板，这样信息分区清晰，不再是壁纸右栏的一条窄带。
23. 作为桌面用户，我想有时钟/日期/天气/日历卡，这样抬头即见。
24. 作为桌面用户，我想有会话列表卡：五工具（Qoder、kimi work、kimi code、zcode、hermes）活跃会话按最近活跃混排、带两字母工具标签，这样全局状态一屏尽收。
25. 作为桌面用户，我想有 Qoder 状态卡：最近活跃会话的项目、任务进度与当前任务，这样盯进度不用切窗口。
26. 作为桌面用户，我想有硬件指标卡：CPU/内存/GPU/网络及历史曲线，这样机器状态一目了然。
27. 作为桌面用户，我想保留分区标签（极小文字标注方位、不画边界），这样分区语义延续而视觉干净。

### 搜索

28. 作为桌面用户，我想让搜索框常驻面板右窄栏待机位、与面板视觉一体，这样「搜一下」永远在老地方。
29. 作为桌面用户，我想点击搜索框直接打字（中文输入法可用），这样免去先唤起 Listary 小窗那一步。
30. 作为桌面用户，我想边打字边出实时结果、↑/↓ 选择、Enter 打开、Ctrl+Enter 在资源管理器定位，这样检索一步到位。
31. 作为桌面用户，我想 ESC 或失焦退回待机态，这样桌面立刻干净。
32. 作为桌面用户，我想 Listary 未就绪时显示 ENGINE OFFLINE 而非卡死，这样能分清故障与未启动。
33. 作为桌面用户，我想查询词只发往本机 Listary API 且不进自建使用日志，这样隐私边界与既有约定一致。
34. 作为桌面用户，我想 Listary 原有热键、悬浮窗与 launcher 能力原样保留，这样面板之外一个不少。

### 交互

35. 作为桌面用户，我想点击会话卡上的会话块即聚焦对应工具窗口（未运行则启动它），这样从状态直达现场。
36. 作为桌面用户，我想面板内置设置浮层（透明度滑杆、恢复出厂布局等），这样配置不用手改文件。

### 插件体系

37. 作为插件作者，我想按一份声明式契约（manifest + 生命周期钩子）编写桌面组件，这样上手成本可控。
38. 作为插件作者，我想让插件携带前端组件资产并在渲染层动态加载，这样组件 UI 自由。
39. 作为插件作者，我想让插件在运行时被加载/卸载/重载而不重启面板（热插拔），这样迭代即时可见。
40. 作为桌面用户，我想让内置信息块（时钟、天气、会话列表、Qoder 状态块、硬件）本身就是第一批桌面组件，这样插件机制经真实组件自举验证，而非玩具样例。
41. 作为桌面用户，我想未来加装第三方桌面组件只需放入插件目录即被识别，这样生态有生长空间。

### 维护者

42. 作为面板维护者，我想让会话扫描、频次、归类/编排、Listary 客户端、搜索状态机等纯逻辑可离线测试，这样不依赖真机与真实工具做回归。
43. 作为面板维护者，我想让内核对渲染层的桥接契约可在 Node 中带桩驱动断言，这样渲染层之外的行为全部可测。
44. 作为面板维护者，我想有一键真机验收电池：透明/穿透/钉扎 Win32 探针、热区点击、桌面项与扫描一致性、双击启动探针 lnk、图标隐藏还原、Win+D 恢复、真重启自启，全程存证截图，这样复验成本极低。
45. 作为面板维护者，我想迁移后的会话判定语义与现契约逐字段一致（90 秒 RUNNING、10 分钟活跃池、subagent 排除等），这样迁移不悄悄改行为。
46. 作为面板维护者，我想应用单实例运行、重复拉起自动退出，这样不会出现双面板。

## Implementation Decisions

- **底座（ADR-0004）**：Electron 作窗口宿主（透明无边框窗口、托盘、鼠标穿透 + 事件转发），cordis 3.x 作主进程插件内核（插件生命周期、依赖注入、热插拔），Vite 构建前端；TypeScript 全栈。cordis 锁 3.x 稳定线（4.0 尚在 beta、官方声明 API 未稳定），只圈定使用插件生命周期与依赖注入子集。
- **层叠模型**：背景层（用户自选壁纸，系统或 WE 挂载均可）< 独立面板（普通原生窗口）< 普通应用窗口。面板默认鼠标穿透，光标进入交互热区时临时解除；底部钉扎（HWND_BOTTOM）Electron 无原生档位，经 FFI/SetWindowPos 实现。Explorer 与任务栏不动，只接管桌面图标的承载职责。
- **交互热区**：热区由渲染层声明（信息卡、dock、搜索框、设置入口），主进程做光标命中跟踪并切换穿透状态；热区之外的一切点击直达桌面。
- **透明背景**：依赖 WebView2/Chromium 透明合成，实施前先做 spike 探针；失败即降级为窗口级整体 alpha（文字随之变虚）——ADR-0004 已接受的降级路径，不阻塞其他工作。
- **桌面承载引擎**：扫描用户桌面与公共桌面（合并去重）得桌面项池 → 归类（应用入口入应用区，其余入文档区）→ 编排（首次全量 + 单项增量）→ 栏位分配（手钉在前，推荐位按使用频次填补）。图标自 lnk/文件提取并缓存；双击启动、单击选中、区内/跨区拖拽摆位；监听桌面文件夹增删同步；隐藏原生桌面图标（启动时确保、退出与崩溃时还原）；提供恢复出厂布局动作。
- **语义平移**：应用区/文档区/栏位/手钉/推荐位/使用频次/使用日志/冷启动先验/归类/编排按词汇表原义平移到自绘世界；漂移纠正与布局快照退役（自绘布局不受系统打扰），仅保留恢复出厂布局。使用日志继续只含进程路径与时间戳、不含窗口标题（ADR-0002 有效）；应用区以底部 dock 形态呈现。
- **会话模型**：统一会话模型（ADR-0003-multi-tool 有效）随扫描器移植，判定语义逐字段保持：90 秒时间窗判 RUNNING、10 分钟活跃池、SQLite 一律只读 URI 打开、单扫描器失败静默跳过、zcode subagent 会话排除、kimi work 降级无标题。五工具扫描从文件系统/SQLite 直读，不走任何 API/IPC。
- **内核契约（唯一新缝）**：内核对渲染层只暴露一个桥接 API，收口全部能力——面板快照（会话/硬件/桌面项/历史曲线）拉取与变更订阅、搜索查询与动作、桌面项启动与摆位、配置读写。服务之间用 cordis 生命周期与事件协作，不另开通信通道。
- **搜索**：Listary 7 本地 HTTP API（仅监听 127.0.0.1、无 CORS、无 keep-alive）由内核调用，渲染层永不直连；待机/活动/引擎离线三态平移；输入防抖约 200ms、限流静默退避；Enter 打开、Ctrl+Enter 定位由内核执行；查询词不写入使用日志。搜索框为面板内 HTML 浮层，Tk 窗退役。
- **配置**：config.json 收口屏幕几何（面板坐标、分区原点、dock 尺寸、分区标签位）、透明度、自启项等，以当前生产值为默认；代码中不再出现 Steam/WE 绝对路径。
- **插件体系（骨架）**：桌面组件 = cordis 插件——manifest 声明能力与前端入口，前端资产经应用自定义协议提供给渲染层动态加载；插件目录即安装位（放入即被识别）。时钟、天气、会话列表、Qoder 状态块、硬件指标五个内置信息块改为第一批桌面组件，验证机制自举。
- **自启与守护**：Startup 快捷方式改指新应用；单实例守卫；Win+D 最小化的防抖自动恢复；原看门狗的 WE 门控逻辑退役（服务不再依赖 WE 存在）。
- **退役清单**：Python 数据服务与其自启链、server_watchdog、Tk 搜索面板窗口、zones Win32 挪真图标链路、deploy/apply/restore 三个 WE 部署脚本；deck 与 patched 壁纸资产连同 backup 冻结归档不再维护。迁移期（Q20A 拍板）不再向 Python 侧添加任何新功能。
- **字体**：Latin 等宽与 CJK 字体从可商用免费候选中选定（对比页见本 feature 目录 font-compare，含 Share Tech Mono / JetBrains Mono / IBM Plex Mono 与 MiSans / HarmonyOS Sans / 阿里巴巴普惠体 / 阿里妈妈数黑体 / Noto Sans SC），字体文件本地化进资产目录、随应用分发；VT323（OFL）保留。

## Testing Decisions

- 好的测试只断言外部可见行为（快照内容、搜索结果与动作、桌面项落位、窗口状态），不断言内部实现细节。
- **辅缝——纯逻辑离线测试（vitest，沿用先例）**：五工具扫描器（假文件树/假 SQLite fixture）、使用频次与冷启动先验、归类/编排/栏位分配、Listary 客户端（假 HTTP）、搜索状态机（三态迁移、防抖、退避）、config 模型。Python 侧 19 个 unittest 文件整体移植为这套测试，移植期间充当回归网。
- **内核契约缝（新，唯一新缝）**：在 Node 中直接驱动 cordis 内核，文件系统/监听/Listary 用桩，断言桥接 API 的请求/响应与变更推送契约；插件热插拔（加载/卸载/重载、前端资产交付）也在本缝测。
- **主缝——真机验收电池（沿用先例）**：一键端到端：窗口透明与穿透的 Win32 探针（穿透态点击直达桌面、热区态被面板接收）→ 底部钉扎 z 序探针 → 桌面项与磁盘扫描一致 → 双击启动验收专用探针 lnk（造唯一名、验证启动、清理）→ 拖拽摆位落盘 → 原生图标隐藏与崩溃还原 → Win+D 防抖恢复 → 真重启自启复验；桌面/壁纸截图脚本存证到工单评论。
- WebView2 透明合成先做 spike 探针定降级路径，再进入主缝。
- 界面视觉对齐不设自动化缝，沿用截图人工核验的既有惯例。
- 先例：accept_zones / accept_search 验收电池、capture_desktop / capture_wallpaper 截图脚本、listary-search 票据 04/05 的真重启复验记录。

## Out of Scope

- 不做打包安装器与跨机分发（仍以本机仓库运行；打包是将来独立的正交目标）。
- 不做 WE 让位机制（面板常驻壁纸之上，无需让位；自动检测更不需要）。
- 不做桌面项右键菜单与删除/重命名等管理操作（一律回资源管理器办）。
- 不做文本选择、拖拽信息卡重排、多主题等全交互（交互 MVP 以热区三入口 + 桌面项基本操作为限）。
- 不做 TERMINAL 02 改版的独立化与 WE 音频可视化（随 patched 冻结退役）。
- 不做 HUD 透视（已退役；透视观感不进入新 UI）。
- 不做第三方插件的分发渠道、市场与签名机制（本期只有插件目录 + 内置组件自举）。
- 不做自动检测 WE 壁纸变化等智能联动。
- 不做多显示器编排（config 单屏几何延续现状，多屏另立票据）。
- 不接入 Listary 应用启动与网络关键词跳转（沿用 listary-search 的能力边界）。

## Further Notes

- **决策溯源**：本 spec 由一轮完整的 grilling 拷问产出（20 个决策点全部经用户拍板），架构决策记录于 ADR-0004（取代 ADR-0001 与 ADR-0003-search-panel；ADR-0002 隐私边界与 ADR-0003-multi-tool 会话模型继续有效），领域词汇以 CONTEXT.md 终稿为准（新增：独立面板、背景层、鼠标穿透、交互热区、桌面项、桌面组件；退役：信息模块、HUD 模式、座舱环抱、仪表俯倾、漂移纠正、布局快照）。
- **参考视觉**：用户提供的 Personal OS 参考图（顶栏导航 + 居中搜索、时钟/天气/日历大卡、统计与日程卡、底部 dock）为 UI 北极星；截图存于会话产物，细节以实现期对照为准。
- **字体对比页**：候选字体样张与截图生成于本 feature 目录 font-compare 子目录，选型结论随实施票据落定。
- **实施工单**：由用户主导拆分（`issues/<NN>-<slug>.md`，从 01 起编号，见 docs/agents/issue-tracker.md）。
